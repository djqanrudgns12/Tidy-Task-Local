# Tidy Task 6.0.0 정식 릴리스 계획 (앱 안 업데이트)

작성일: 2026-11-19 (한국 시간). 기준 문서: [업데이트 배포 가이드](업데이트-배포-가이드.md), [AGENTS.md](../AGENTS.md).
이 문서는 6.0.0을 **앱 안 [지금 업데이트]로 받게** 정식 배포하기 위한 준비 상태와 남은 순서를 적습니다.

## 0. 한 줄 요약

- **서명 키("tidy task key")는 꼭 써야 합니다.** 단, 새로 만들지 않고 **기존 키 그대로**입니다. `npm run release`가 알아서 읽습니다.
- 버전 표기는 6.0.0으로 모두 맞췄고, 새 소식 창은 6.0.0 공지 하나로 바꿨습니다(지난 공지 · 롤링 썬더 홍보 내림).
- **아직 배포하지 않습니다.** 글꼴 고도화(안티그래비티 작업 2건)와 다른 세션의 미커밋 변경이 끝나 커밋된 뒤 빌드합니다.

## 1. 서명 키 — 써야 하나요?

네. 앱 안 업데이트는 **우리 서명 키로 서명한 설치 파일만** 설치합니다. 이미 설치된 5.x 앱 안에는 짝이 되는 공개 키가 들어 있으므로,
6.0.0도 **같은 개인 키**로 서명해야 기존 사용자 앱이 받아들입니다.

| 항목 | 상태 (2026-11-19 확인) |
|---|---|
| 개인 키 `C:\Users\User\.tauri\tidy-task-updater.key` | 있음 (내용은 열지 않음) |
| 공개 키 `.key.pub` ↔ 앱의 `tauri.conf.json` `plugins.updater.pubkey` | **일치** |
| `src-tauri/.env`의 `NEIS_API_KEY` · `POSTHOG_PROJECT_TOKEN` · `POSTHOG_HOST` · `POSTHOG_DEV_ENABLED` | 네 항목 모두 있음 (값은 열지 않음) |

- `npm run release`가 빌드 전에 이 키로 작은 파일에 서명해 보고 앱의 공개 키로 확인합니다. 다른 키면 빌드 전에 멈춥니다.
- ⚠️ **새 키를 만들지 마세요**(`tauri signer generate` 금지). 새 키로 서명하면 기존 앱이 모두 설치를 거부합니다.
- ⚠️ 키 파일을 USB · 개인 클라우드에 **따로 백업**해 두세요. 잃으면 모든 사용자가 직접 내려받아 다시 설치해야 합니다.
- `.env`와 개인 키는 Git · 릴리스 첨부에 절대 넣지 않습니다.

### 누가 앱 안에서 받을 수 있나

| 지금 쓰는 버전 | 6.0.0 받는 방법 |
|---|---|
| 5.5.3 이상 (5.6.x 포함) | 앱 위 알림 띠 → [지금 업데이트] (PC 보호 경고 없음) |
| 5.5.2 이하 | 안내 창의 링크로 한 번 직접 내려받아 설치 |

- 버전 비교(`updateChecker.js` `compareVersions`)는 주 버전이 바뀌어도 숫자로 비교하므로 6.0.0 > 5.6.5를 정상 인식합니다.
- 사용자 데이터(`%APPDATA%\com.tidy.task`)는 덮어쓰기 설치에서 지워지지 않고, 설치 직전 사본(`*.before-update.json`)도 남습니다.

## 4. 배포 순서 (처음 하는 분 기준)

1. 위 게이트를 모두 체크하고 Git에 커밋 · 푸시합니다. `.env` · 개인 키는 올리지 않습니다.
2. 프로젝트 폴더 터미널에서 `npm run release`
   - 버전 일치 → PostHog 운영 설정 → 통계 회귀 검사(`analytics::tests` 포함) → 서명 키 확인 → 빌드 → 실행 파일 속 설정/이벤트 · 서명 · 해시 확인
   - `--skip-build`는 쓰지 않습니다(변경 반영 수단이 아님).
3. `output/release/v6.0.0/`의 **두 파일** 확인: `Tidy.Task_6.0.0_x64-setup.exe`, `latest.json`
4. 가능하면 다른 PC(또는 테스트 환경)에 설치해 버전 6.0.0 · 새 소식 창 · 기존 데이터 보존을 확인합니다.
5. [GitHub Releases](https://github.com/djqanrudgns12/Tidy-Task-Local/releases) → **Draft a new release**
   - 태그 **`v6.0.0`** (새 태그 만들기), 제목 **`Tidy Task 6.0.0`**, 설명은 아래 5절을 그대로 붙여 넣기
   - 두 파일을 **모두 첨부한 다음** Save draft → 다시 확인 → **Publish release** → `Latest` 표시 확인
   - 빈 릴리스를 먼저 게시하지 않습니다(immutable 릴리스는 게시 후 파일 추가 불가).
6. `npm run release:verify` — 사용자 앱과 같은 순서로 태그 · latest.json · 설치 파일 서명을 확인합니다. ✅면 끝.
7. 5.6.5 앱에서 설정 → 앱 업데이트 → **업데이트 확인** → [지금 업데이트] → 재실행 · 데이터 보존 · 새 소식 창 확인
8. PostHog(615314, `environment=production`)에서 앱 버전 6.0.0 수신과 모둠원 뽑기(`picker_group`) · D-Day(`dday`) 분류를 확인합니다.
   HTTP 성공만으로 집계 확인 완료라고 쓰지 않습니다.

## 5. GitHub 릴리스 설명 (앱 안내 창 "이번에 좋아진 점"에 그대로 보임)

앱은 앞의 **8줄**만, 한 줄 120자까지 보여 줍니다. 그래서 정확히 8줄로 맞췄습니다.

```text
- D-Day: 할 일과 이어지는 D-Day 배너 · 바탕화면 위젯 · D-Day 컨트롤이 생겼어요
- 할 일: 끌어서 순서 바꾸기, 지우개로 지우기, 6초 안에 되돌리기
- 모둠원 뽑기: 모둠 열차 · 빙하 갈라지기 · 엘리베이터 세 무대로 모둠을 정해요
- 글꼴 72종과 새 글꼴 고르기 창(묶음별 탭 · 굵기 바로 고르기)
- 우클릭 메뉴 새 단장: 자주 쓰는 일을 큰 단추로 모았어요
- 타이머: 창 크기에 맞춘 글자 크기 자동, 위젯 모드
- 설정 창 정리, 메모 칸 높이 안정, 긴 글 줄바꿈 개선, 작은 오류 수정
- 지금까지 쓰신 할 일 · 메모 · 툴킷 자료는 그대로 유지돼요
```

글꼴 4번째 줄은 커밋된 카탈로그(`fontCatalog.js`: 72종 · 6묶음, `.woff2` 62개 = 기존 38 + 새 24)와 대조했습니다(2026-11-19).
