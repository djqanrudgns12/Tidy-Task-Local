# 5.6.3 사용 통계 복구와 배포 안내

작성일: 2026-09-28 (한국 시간). 이 문서는 이번 변경과 배포 절차를 기록합니다.

## 바뀐 점

- 토큰이 빠진 채 배포된 5.6.0/5.6.2의 연결 문제를 고치고 빌드 PC의 공개 PostHog 프로젝트 토큰을 복구했습니다.
  누가 언제 어떤 이유로 설정을 빠뜨렸는지는 기록으로 확정할 수 없습니다. `.env`가 Git 밖의 로컬 설정이고,
  이전 빌드는 토큰이 없어도 성공했던 것이 누락을 배포 전에 잡지 못한 구조적 원인입니다.
- 투표·주사위·타이머·시계·집중벨·뽑기·토너먼트·알림장·명단·점수판·온도계·자리 배치를 구분합니다.
  타이머는 디지털·아날로그·모래시계·스톱워치를 각각 구분합니다.
- 앱 전체 활동과 도구별 활동을 별도 기록합니다. 같은 분에 여러 도구를 써도 빠지지 않으며,
  동일 도구의 선생님 창·표시 창은 합쳐 셉니다. 분별 기록은 재시작 후에도 중복되지 않습니다.
- 주사위 굴리기, 타이머 시작·재개·일시정지·완료, 투표 생성·개표 시작·결과 저장을 실제 성공 시점에 기록합니다.
  자동 완료 자체가 활성 설치 수를 늘리지 않습니다. 투표 내용·학생 이름·주사위 결과는 전송하지 않습니다.
- 5.6.3으로 설치 버전, 두 lock 파일, 첫 실행, 설정, 도움말, 새 소식과 검수 스크립트를 맞췄습니다.
- `AGENTS.md`, `claude.md`, 통계 사전, 배포 가이드에 필수 규칙을 기록했습니다.
  새 도구를 분류에서 빠뜨리거나 토큰 없이 빌드하면 자동 검사에서 실패합니다.

## 자동 업데이트와 기존 사용자의 참여

토큰은 설치 후 따로 내려받는 설정이 아니라 실행 파일에 포함됩니다. 자동 업데이트는 서명을 확인한 새 설치 파일로
실행 파일을 교체하며 토큰이나 수집 코드를 따로 삭제하지 않습니다. 이용자에게 `.env`를 나눠 줄 필요가 없습니다.
앱 데이터 보존 훅도 확인했습니다. 정상 토큰을 포함한 5.6.3으로 업데이트하면 새 수집 코드가 같이 적용됩니다.

기존 `consent:false` 값은 현재 코드에서 사용하지 않습니다. 정상 설정된 배포본에서는 별도 동의 조작 없이 자동 참여하며,
이전 거부 파일을 읽어 자동 수집하는 회귀 테스트도 통과합니다. **이미 누락된 과거 사용량은 복구되지 않습니다.**
네트워크 차단·장기 오프라인·앱 데이터 삭제 등까지 완전하게 관측할 수 있는 통계는 아닙니다.

이전 `window_used` 차트는 기능 대시보드에 남겼습니다. 과거 `other`는 세부 도구로 되돌릴 수 없습니다.

## 배포할 때 할 일 — 처음 하는 분 기준

1. 수정 내용을 Git에 저장하고 원격 저장소에 올립니다. `.env`와 서명 개인 키는 올리지 않습니다.
   코드가 바뀐 뒤라면 프로젝트 폴더의 터미널에서 `npm run release`를 다시 실행해 새 설치 파일을 만듭니다.
2. `output/release/v5.6.3` 폴더를 엽니다. 올릴 파일은 **`Tidy.Task_5.6.3_x64-setup.exe`와 `latest.json` 두 개**입니다.
   `latest.json`은 기존 앱이 설치 파일 주소와 서명을 확인할 때 꼭 필요합니다.
3. 가능하면 다른 Windows PC나 별도 테스트 환경에 설치 파일을 설치하고, 버전이 5.6.3인지 확인합니다.
   주사위를 한 번 굴리고 짧은 타이머를 시작·완료하고 테스트 투표를 만들고 끝냅니다.
   앱을 1~2분 정도 켜 둔 뒤 PostHog 기간을 '오늘'로 맞추고 새로고침합니다. 반영 지연이 있으면 잠시 뒤 다시 확인합니다.
4. [GitHub Releases](https://github.com/djqanrudgns12/Tidy-Task-Local/releases)에서 **Draft a new release**를 누릅니다.
   태그를 **`v5.6.3`**, 제목을 **`Tidy Task 5.6.3`**으로 정하고 아래 설명을 붙여 넣습니다.
5. 위의 **두 파일을 모두 첨부한 다음** Publish release를 누릅니다. 빈 릴리스를 먼저 게시하지 마세요.
6. 프로젝트 터미널에서 `npm run release:verify`를 실행합니다. 게시된 버전·설치 파일 주소·업데이트 서명을 확인하는 명령입니다.
7. 기존 5.6.2 앱에서 업데이트를 확인하여 5.6.3 설치·재실행·기존 데이터 보존을 확인합니다.
   PostHog '사용 중인 앱 버전'에 5.6.3이 생기고 도구별 차트가 채워지는지 확인하면 마무리입니다.

확인 후 차트가 비어 있으면: 버전 5.6.3 여부 → 올바른 프로젝트 615314·기간 '오늘'·production 필터 → 실제 도구 조작 → 네트워크 순으로 봅니다.
로컬 전송 대기열은 `%APPDATA%/com.tidy.task/tidy-task-analytics.json`에 있습니다. 원인 확인 전에 지우지 마세요.
