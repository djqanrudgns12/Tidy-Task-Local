# 학급 명단·모둠 공통 기반 PRD

작성: 2026-09-20 · 대상: Tidy Task Local 5.5.0 · 구현 기록: 2026-09-21 [QA](QA-classroom-roster.md)

## 1. 목적과 결정의 성격

교사가 여러 학급의 학생과 모둠을 한 번 등록하고, 앞으로 뽑기·개인/모둠 점수판·자리배치에서 같은 정보를 사용한다. 이번 결과물은 명단 관리 기능과 공통 데이터 계약이다. 후속 도구 자체는 만들지 않는다.

사용자 확정: 독립 팝업, 학급 목록과 학생 표, 로컬 영속 저장, 번호·이름·선택 성별, 수동 모둠 소속, 직접 입력과 파일 가져오기, 원본 사본 비보관, 평소 자동 저장/가져오기 확정 저장. 번호·결번 보존, 이름만 입력하면 번호 자동 부여. 원본 컴퓨터 파일은 삭제하지 않는다.

위임받아 채택한 설계: 단일 명단 창, 공통 기본 학급과 도구별 고정 학급, SQLite 저장, 변경 비교를 통한 재가져오기, 학생당 한 모둠, 삭제 실행 취소, 아래 입력 한도와 UX. 이 문서는 구현 승인을 뜻하지 않는다. 향후 리팩터링이 전혀 없을 것을 보장하지 않고, 저장·파서·도구의 경계를 지금 정해 재작업 가능성을 줄인다.

선행 문서: [인계서](HANDOFF-classroom-toolkit-next-development.md). 현재 코드와 최신 사용자 결정을 우선한다. 인계서의 단일 학급 초안은 다학급 요구로 대체한다. 기존 타이머·음원·테마·미커밋 작업을 보존한다.

## 2. 범위

| 구분 | 이번 출시 |
| --- | --- |
| 필수 | 다학급 CRUD, 학생 CRUD/검색/정렬/다중 선택, 수동 모둠 CRUD/배정, 로컬 자동 저장, 가져오기/재가져오기, 툴킷 진입, 창 간 변경 반영, 최소 백업/복원 |
| 파일 | XLSX, 텍스트 PDF, HWPX, CSV 및 표/이름 붙여넣기 |
| 후속 | 스캔 PDF OCR, 구형 HWP/XLS, 임의 이미지, 자동 모둠 편성, 모둠 안 좌석, 여러 모둠 편성 세트, 점수/뽑기/자리배치 UI |
| 제외 | 접속 코드, 프로필 사진, 연락처·생년월일 저장, 서버 업로드/클라우드/외부 AI 전송, 미구현 도구 버튼 |

스캔 PDF는 감지 후 지원 범위를 설명하고 XLSX/HWPX/직접 입력으로 안내한다. 모든 임의 양식의 완전 자동 인식을 약속하지 않는다. 번호·이름 후보가 명확하지 않으면 미리보기 열 연결로 보완하고, 복구 불가능하면 저장하지 않는다.

## 3. 화면과 창

요구 ID R01. 툴킷 끝에 직접 실행 메뉴 `학급 명단`을 추가한다. 연속 클릭은 이미 열린 창을 앞으로 가져온다. 기본 크기 1040×720 논리 픽셀, 최소 640×480을 목표로 하되 모니터 작업 영역 안에 맞춘다. 크기 조절 가능, 작업표시줄 표시, 항상 위 기본 OFF 및 창별 토글. 본창과 별개로 사용한다.

```text
학급 명단                                  저장됨      고정 / 창 닫기
┌ 학급 목록 ────────┬────────────────────────────────────────────┐
│ 학급 추가        │ 5학년 2반       학생 21명       기본 학급으로 │
│ 5학년 1반        │ 학생 명단 | 모둠 구성                       │
│ 5학년 2반  기본  │ 검색       학생 추가   파일 가져오기    ⋯   │
│                  │ 선택  번호       이름             성별      │
│                  │ □      1         예시학생         미선택    │
│                  │ ...                                        │
└──────────────────┴────────────────────────────────────────────┘
```

- 880px 이상: 약 208px 학급 사이드바 + 가변 본문. 미만: 학급 선택기로 전환하고 본문 확보. 창 전체와 표의 이중 가로 스크롤 금지.
- 상단 제목/학급/탭/표 머리글 고정, 표 본문 스크롤. 모둠 탭은 좁은 폭에서 미배정 영역을 접을 수 있게 한다.
- 현행 밝은 테마와 폰트 사용. 옅은 활성 배경, 얇은 구분선, 행 높이 42~46px 목표. 모든 셀을 카드로 꾸미지 않는다. 핵심 입력은 14px 이상, 보조는 12px 이상.
- 학급 선택과 `기본 학급으로`는 분리한다. 다른 학급을 잠깐 확인했다고 도구의 기본 학급이 바뀌지 않는다. 첫 학급만 자동 기본 지정.
- 학생 이름 입력은 늘 보이게 하고, 선택된 행에만 다중 조작 바를 표시한다. 성별은 남/여/미선택의 간결한 제어, 색만으로 구분하지 않는다.
- 숫자·이름·성별 외 열은 선택 체크박스와 행 메뉴뿐. 저장 상태는 `저장 중… / 저장됨 / 저장하지 못했어요 · 다시 시도`.

## 4. 데이터 규칙

요구 ID R02. 학생 ID는 이름/번호/순서와 독립적인 불변 ID. 학급·모둠도 각각 불변 ID를 갖는다. 화면 순서는 참조 키가 아니다.

| 항목 | 규칙 |
| --- | --- |
| 학급 이름 | 필수, 앞뒤 공백 제거, 1~60자. 같은 표시 이름 허용하되 추가 시 중복 안내. ID로 구분 |
| 학생 번호 | 학급 내 고유 정수 1~9999. 전각 숫자/앞뒤 공백 정리. 번호 교환은 일괄 수정으로 원자적 처리 |
| 자동 번호 | 해당 학급 최대 번호 + 1, 첫 학생은 1. 기존 결번은 채우지 않음. 상한이면 직접 입력 안내 |
| 학생 이름 | 필수 1~80자, Unicode NFC 및 앞뒤 공백 정리. 내부 공백·외국어·하이픈 보존. 제어 문자 불허. 동명이인 허용 |
| 성별 | male / female / unspecified. 남·남성 / 여·여성을 대응. 값 부재는 unspecified, 알 수 없는 값은 확인 대상으로 표시 |
| 모둠 | 이름 1~40자, 학급 내 정규화된 이름 중복 불허, 빈 모둠 허용. 색상은 보조 표시 |
| 소속 | 같은 학급의 모둠 하나 또는 미배정. 성별 미선택은 모든 기능 사용 가능 |
| 기본 한도 | 학급 100개, 학급당 학생 500명, 모둠 100개. 파일 처리 한도는 R05. 초과는 분명한 안내 후 변경 없음 |

## 5. CRUD와 주요 흐름

### R03. 학급 CRUD

| 동작 | 사용자 흐름 | 저장·실패 규칙 |
| --- | --- | --- |
| 생성 | 학급 추가 → 이름 한 칸 입력 → 생성 → 첫 이름 칸 초점 | 생성 성공 후 목록 반영. 연타 중복 생성 방지. 빈 학급 유지 가능 |
| 조회 | 목록 클릭 → 학생/모둠 조회 | 탭/검색/스크롤은 창 세션 상태. 기본 학급 표시는 영속 설정 |
| 수정 | 제목 메뉴 → 이름 수정 | ID·학생·소속 유지. 실패 시 수정값 남김 |
| 삭제 | 학급 메뉴 → 학급명·학생/모둠 수 확인 → 삭제 | 학급과 소속 데이터 한 트랜잭션 삭제. 기본 학급이면 null, 자동으로 다른 반 지정하지 않음 |

학급 삭제는 명시 확인하며 세션 내 실행 취소를 제공한다. 사용 중인 도구는 `학급이 삭제되었어요` 상태로 멈추고 다른 학급을 자동 선택하지 않는다. 후속 도구의 영속 데이터가 생기면 동일 트랜잭션에서 정리하고 확인 화면에 영향 수를 포함해야 한다.

### R04. 학생 직접 입력·조회·수정·삭제

- 생성: `학생 추가` 또는 맨 아래 입력 행 → 번호 자동 제안 → 이름 입력 → Enter. 이름 입력 없이 빈 행을 저장하지 않는다. 새 행은 이름을 확정한 시점에 생성한다. 성별 선택은 나중에 가능하다.
- Enter는 같은 열의 다음 행, Tab/Shift+Tab은 다음/이전 입력, Escape는 해당 셀의 미확정 변경 취소. 한글 조합 중 Enter는 이동·저장·생성하지 않는다. 이름만 연속 입력할 때 성별 선택을 강요하지 않는다.
- 조회: 기본 번호 오름차순. 이름/번호 검색, 성별·미배정 필터, 이름 정렬. 검색 결과 개수와 전체 수 구분. 정렬/필터는 실제 번호나 ID를 바꾸지 않는다.
- 수정: 셀에서 바로 수정. 유효한 변경은 입력 종료 500ms 후 또는 blur/Enter에 저장. 편집 중 행은 재정렬하지 않고 셀 확정 후 순서 반영. 입력 중 빈 이름·중복 번호는 오류를 표시하며 이전 저장값 유지.
- 새 학생 생성 대기 중 해당 행 후속 변경은 동일 생성 작업 뒤에 순서대로 전달한다. 생성 전 draft ID와 영속 ID 대응을 유지하여 유령 학생/중복 생성을 방지한다.
- 다중 선택: 현재 필터 결과 전체 선택이며 숨겨진 학생은 포함하지 않음. 학급 전환 시 선택 초기화. 삭제 버튼에 정확한 대상 수 표시.
- 삭제: 한 명은 즉시 삭제 + 실행 취소, 여러 명은 인원 확인 후 일괄 삭제. 학생 삭제는 소속만 함께 제거하며 모둠 자체는 남는다. 이름을 지우는 동작을 삭제로 해석하지 않는다.
- 번호 교환: 다중 행 붙여넣기/일괄 편집 미리보기에서 최종 번호 유일성을 검사하고 하나의 변경으로 처리. 중간 저장 때문에 번호 충돌이 나지 않게 한다.

### R05. 파일/붙여넣기 최초 등록

1. `파일 가져오기` 또는 창 안 파일 드롭. 한 번에 파일 하나. 파일 대화상자 취소 시 화면 변화 없음.
2. 로컬 분석 → 필요 시 학급/시트/표 선택 → 번호·이름·성별 미리보기. 파일명은 세션 중만 표시.
3. 높은 확실성은 자동 열 연결. 모호하면 번호·이름·성별 열을 지정한다. 번호 열을 명시적으로 `없음`으로 선택하면 자동 번호 부여. 번호 열이 있는데 일부 값이 깨진 경우 자동 재번호 금지.
4. 정상 행/빈 행 제외/확인 필요 건수를 구분한다. 숫자만 있고 이름 없는 행은 등록하지 않는다. 이름이 있으나 번호 오류인 행은 조용히 누락하지 않고 등록 차단 또는 사용자가 명시 제외한다.
5. 미리보기에서 수정 → `21명 등록` → 전부 성공 또는 전부 실패. 실패하면 미리보기 유지. 취소하면 임시 학생 후보도 폐기.

붙여넣기는 이름 여러 줄 및 TSV 표를 지원한다. 기본 Ctrl+V의 단일 텍스트는 셀 편집이며, 여러 행/열만 가져오기 미리보기로 전환한다. 쉼표가 있는 이름을 무조건 CSV로 나누지 않는다. CSV 파일은 인용부호/줄바꿈과 UTF-8 BOM·CP949/EUC-KR 대응을 검증한다. 인코딩 판별이 불확실하면 미리보기에서 선택한다.

파서 계약: 파일별 읽기 → 제한된 임시 표 → 머리글/행/학급 경계 탐지 → 세 필드 후보 → 공통 검증. 첫 행·고정 열 번호에 의존하지 않는다. 학년·반은 표 구분에만 임시 사용하며 학생 부가 필드로 저장하지 않는다. 반복 머리글/쪽 번호/재적 집계를 제거하고, 여러 반은 반드시 구분하여 선택한다. 자동으로 반을 합치지 않는다.

분석 한도 초기값: 원본 20MiB, PDF 50쪽, XLSX 20시트·읽기 100,000셀, 압축 해제 누적 100MiB·ZIP 항목 2,000개, HWPX 중첩 깊이 64. 제한 도달 시 부분 성공으로 표시하지 않는다. 분석 취소 가능, 30초 초과 시 종료 안내. 실제 샘플/저사양 기기 검증으로 수치는 조정 가능하나 검증 없이 무제한으로 풀지 않는다.

### R06. 기존 학급에 재가져오기

- 기본 모드는 `변경 비교`. 같은 번호+정규화된 이름이 모두 맞고 유일한 경우에만 기존 학생에 자동 연결한다. 성별이 파일에 없으면 기존 성별을 유지한다.
- 번호만 같거나 이름만 같으면 `기존 학생 수정 / 새 학생`을 사용자가 선택한다. 동명이인·개명·번호 변경을 추측으로 합치지 않는다. 기존 학생 연결 시 ID와 모둠 유지.
- 파일에 없는 기존 학생은 유지한다. 화면에서 별도로 선택한 삭제만 적용한다. `명단 전체 교체` 자동 경로는 제공하지 않는다.
- 새 학생은 새 ID로 생성하고 미배정. 이미 같은 파일을 다시 가져오면 변경 0건으로 종료 가능. 확정 전에 추가·수정·삭제·그대로 유지 수를 표시한다.
- 비교 중 원본 학급 revision이 바뀌면 적용을 멈추고 다시 비교한다. 사용자 수정 초안을 보존하되 새 비교 결과의 충돌 항목은 재확인한다.

### R07. 모둠 CRUD/소속

- 생성: `모둠 추가`는 `1모둠` 등 충돌 없는 다음 기본 이름을 제안. `여러 모둠 만들기`에서 수를 입력해 빈 모둠을 한 번에 생성 가능.
- 조회: 미배정 학생 영역 + 모둠별 카드, 학생 번호/이름·인원 표시. 성별은 배정의 필수 조건이 아니다.
- 배정: 미배정 또는 기존 모둠에서 여러 학생 선택 → 대상 모둠 선택 → 한 번에 이동. 버튼 방식이 기본이며 드래그는 같은 명령을 호출하는 보조 방식.
- 수정: 모둠명·표시 순서 변경, 학생 이동/미배정으로 보내기. 한 학생이 두 모둠에 나타나는 중간 상태를 저장하지 않는다.
- 삭제: 구성원 수 안내 후 삭제, 학생은 미배정으로 이동. 학생 삭제와 모둠 삭제를 구분한다. 빈 모둠 삭제는 바로 실행 취소 제공.
- 되돌리기: 최근 배정/이름 변경/삭제를 되돌릴 수 있다. 끌어놓기 실패 시 원래 위치 유지. 다른 반으로 학생 드래그 이동은 이번 범위 밖.

## 6. 저장·실행 취소·수명

R08. 창에서는 초안과 저장된 값을 구분한다. 저장 성공을 받은 변경만 `저장됨`으로 표시한다. DB 실패는 초안을 남기고 재시도한다. 후속 수정은 순서를 지키며, 같은 명령 재전송으로 중복 반영하지 않는다.

R09. 세션 내 최근 20개 확정 작업에 실행 취소 제공. 연속 타이핑은 셀 확정 단위로 묶는다. 가져오기/일괄 배정도 한 작업. Ctrl+Z는 입력 필드 안에서는 텍스트 편집에만 사용하며 도메인 실행 취소는 별도 버튼으로 명확히 한다. 되돌리기는 저장소의 역명령이며 다른 변경을 덮어쓰지 않는다. 영향 받은 학급 버전이 달라지면 취소 거절 및 이유 표시. 창 종료 시 취소 이력 폐기. 영구 휴지통/변경 이력은 두지 않는다.

R10. 창 닫기·학급 전환·앱 정상 종료 전 debounce를 비우고 저장 결과를 기다린다. 실패/잘못된 입력은 `돌아가기 / 미저장 변경 버리기`로 명확히 처리한다. 파일 미리보기 중 닫기는 미등록 정보 폐기 확인. OS 강제 종료·전원 차단 전 아직 저장하지 않은 초안의 복구는 보장하지 않는다. 기존 코드의 destroy 직행을 명단 창에 사용하지 않는다.

R11. 전용 로컬 SQLite DB에서 원자적 CRUD를 수행한다. 타이머 JSON 설정·메모·급식 데이터를 이관하지 않는다. schema version과 순차 migration을 둔다. 손상/상위 버전은 자동 빈 DB로 덮어쓰지 않고 쓰기를 차단한다. 유효한 백업 복원/재시도 경로를 제공한다.

R12. `학급 데이터 내보내기/복원`은 전체 학급·학생·모둠·기본 학급의 버전 있는 JSON이다. 원본 가져오기 자료와 로그는 포함하지 않는다. 사용자가 고른 위치에만 저장. 복원은 기존 데이터를 대체한다는 안내와 개수 미리보기 후 한 트랜잭션으로 실행한다. ID 유지, 실패 시 기존 DB 유지. 복원 성공 시 열린 도구 캐시·실행 취소 이력을 무효화한다. 자동 영구 백업은 생성하지 않는다.

## 7. 공통 도구 연동

R13. 전역 기본 학급은 새 도구의 초기값이다. 열린 도구는 `boundClassId`를 유지한다. 명단 창의 탐색은 기본 학급 변경과 독립적이다. 기본 학급 null이면 새 도구에서 학급 선택을 요구한다.

- 같은 학급의 수정은 revision 알림 후 최신 조회로 반영. 이벤트에 이름·전체 명단을 싣지 않는다.
- 구독 시작 후 최초 조회, 포커스 복귀 시 재조회, 이전 revision 응답 무시. 이벤트 누락으로 영구적으로 오래된 명단을 보지 않게 한다.
- 뽑기 진행 중에는 선택 당시의 ID와 표시 데이터 스냅샷을 유지하고, 다음 실행에 최신 데이터를 사용한다. 삭제된 학생을 새 후보로 다시 넣지 않는다.
- 후속 점수는 studentId/groupId 기준. 개명·번호 변경은 점수 귀속 불변. 모둠원 이동으로 모둠 점수를 옮기거나 개인 점수를 합산하지 않는다.
- 향후 삭제 연동은 해당 저장소 트랜잭션에 참여해야 한다. 삭제 이벤트만 믿고 별도 파일을 나중에 지우는 구조 금지. 이번에는 빈 점수 테이블을 미리 만들지 않는다.

## 8. 개인정보·원본 수명·배포

R14. 원본 바이트/압축 내용/전체 텍스트는 분석 중 메모리에만 존재한다. 추출 완료·실패·취소 시 참조 해제, 파일 핸들 닫기, PDF task/worker 종료, object URL 해제. 언어 런타임/OS 수준의 물리적 메모리 완전 소거를 보장한다고 표현하지 않는다.

미리보기에는 번호·이름·성별, 오류 코드·위치, 임시 표 선택 라벨만 남긴다. 연락처/생년월일을 미리보기나 진단에 출력하지 않는다. 암호 파일의 비밀번호도 저장하지 않는다. 원본 경로·파일명·학생 정보는 telemetry/console/crash breadcrumb에서 제외한다. CSV 수식/문서 스크립트/외부 링크를 실행하거나 외부 리소스를 받지 않는다.

`public/sample/student`의 제공 파일은 분석용이다. 구현 단계에서 배포 경로 밖의 로컬 전용 폴더로 안전히 옮기고 Git 제외한다. 공개 테스트는 가명 합성 자료로 만든다. 사용자 원본은 삭제하지 않는다. 저장된 명단을 삭제해도 사용자가 내보낸 백업이나 원본까지 지우지 않는다. 암호화 저장은 이번 기능에 포함되지 않는다.

## 9. 접근성과 성능

R15. 실제 table + input/button을 기본으로 사용한다. 완전한 ARIA grid 패턴을 구현하지 않은 채 role=grid만 붙이지 않는다. 입력별 학생·열 label, 눈에 보이는 focus, 오류 연결, 저장 상태의 조용한 live region, 대화상자 초점 복귀를 제공한다. 색상·드래그 없이 모든 조작 가능. 검색 결과 변경 때 편집 초점을 빼앗지 않는다. 입력 동작 중 자동 정렬 금지.

R16. parser는 가져오기 시 지연 로드. 저장·분석은 UI 스레드에서 무거운 동기 작업 금지. 대상 학급만 조회하고 학급 목록에는 인원 집계만 전달. 첫 출시에서 복잡한 가상 테이블/범용 폼 프레임워크를 도입하지 않는다.

성능 합격 목표(측정값 아님): 학생 40명 표 입력 반응 p95 100ms 이내, 저장 왕복 p95 300ms 이내(유휴 로컬 환경), 제공 샘플 분석 각 3초 이내, 같은 학급 창 반영 1초 이내. 분석 20회 반복 후 보유 worker/파일 핸들이 누적되지 않아야 한다. 기기·빌드·측정 조건을 QA에 기록하고 미달 원인을 확인한다.

## 11. 설계 근거

2026-09-20 공식 자료 확인. 아래는 제품 구현 완료 증거가 아니라 선택한 기법의 근거다.

- [SQLite 원자적 commit](https://www.sqlite.org/atomiccommit.html), [외래키](https://www.sqlite.org/foreignkeys.html): 일괄 변경과 관계 무결성을 DB 트랜잭션/제약으로 처리.
- [Tauri commands](https://v2.tauri.app/develop/calling-rust/), [Rust에서 frontend 호출](https://v2.tauri.app/develop/calling-frontend/): 명령과 변경 알림을 분리.
- [WAI-ARIA grid](https://www.w3.org/WAI/ARIA/apg/patterns/grid/): 복합 그리드의 키보드 책임을 고려해 초기에는 의미 있는 HTML 표와 입력 사용.
- [PDF.js](https://mozilla.github.io/pdf.js/getting_started/), [Web Workers](https://developer.mozilla.org/en-US/docs/Web/API/Web_Workers_API/Using_web_workers): PDF 해석과 무거운 처리의 UI 분리.
- [calamine](https://docs.rs/calamine/latest/calamine/): XLSX 읽기 후보. 정확한 버전과 Rust 최소 버전은 구현 착수 시 검증.

세부 작업·API·실패 처리·검증 순서는 [구현 계획](PLAN-classroom-roster.md)에 따른다.
