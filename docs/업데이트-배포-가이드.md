# 업데이트 배포 가이드

Tidy Task는 **GitHub Releases**를 "공식 배포처"로 삼아, 새 버전이 올라오면
앱이 스스로 알아채고 사용자에게 안내합니다. 별도의 서버나 비용은 필요 없습니다.

---

## 1. 이 시스템은 어떻게 동작하나요?

```
[개발자] GitHub에 새 릴리스 발행
              ↓
[앱] 매니저 창이 6시간마다 GitHub에 "최신 버전이 뭐예요?" 문의
              ↓
[앱] 내 버전(5.0.0) < 최신 버전(5.1.0) 이면
              ↓
[사용자] 창 위에 얇은 띠: "🎉 새 버전 v5.1.0 이 나왔어요"
              ↓ (누르면)
[사용자] 3단계 설치 안내 → [새 버전 내려받기] → 브라우저에서 파일 다운로드
```

**핵심 설계**

| 항목 | 내용 | 이유 |
|---|---|---|
| 확인 주체 | **매니저 창 1개만** | 창을 10개 켜도 GitHub 호출은 1회. 알림도 1번만 뜹니다 |
| 확인 주기 | 부팅 8초 뒤 1회 + 이후 6시간마다 | GitHub 무료 한도(시간당 60회)를 여유 있게 지킵니다 |
| 설치 방식 | 앱은 **링크만 열어 줍니다** | 앱이 파일을 만지지 않으므로 사용자 메모·할 일이 위험해질 일이 없습니다 |
| 사용자 선택 | "나중에"(하루) / "이 버전 건너뛰기" | 선택은 디스크에 저장되어 앱을 꺼도 유지됩니다 |
| 실패 시 | 자동 확인 실패는 **조용히 무시** | 인터넷이 잠깐 끊겼다고 사용자를 놀라게 하지 않습니다 |

## 2. 새 버전을 배포하는 방법 (개발자가 할 일)

### ① 버전 번호 올리기 — `package.json` 한 곳만

```jsonc
// package.json
"version": "5.1.0"   // ← 여기만 고치면 됩니다
```

> **왜 한 곳만인가:** `src-tauri/tauri.conf.json`이 `"version": "../package.json"`으로
> package.json을 바라보도록 연결해 두었습니다. 버전을 여러 곳에 적으면 하나를 빠뜨렸을 때
> "업데이트했는데도 알림이 계속 뜨는" 문제가 생깁니다.
>
> `src-tauri/Cargo.toml`의 `version`은 **앱 버전과 무관한 Rust 패키지 번호**라 그대로 두어도
> 동작에는 아무 문제가 없습니다. (검증 완료: package.json만 5.0.1로 올리자 Cargo.toml이
> 5.0.0인 상태에서도 설치 파일이 `Tidy Task_5.0.1_x64-setup.exe`로 생성되었습니다)
> 헷갈리지 않도록 같이 맞춰 두고 싶으시면 함께 올리셔도 됩니다.

### ② 설치 파일 만들기

```bash
npm run tauri build
```

결과물이 아래 경로에 생깁니다.

```
src-tauri/target/release/bundle/nsis/Tidy Task_5.1.0_x64-setup.exe
```

### ③ GitHub에 릴리스 발행하기

1. https://github.com/djqanrudgns12/Tidy-Task-Local/releases 로 이동
2. **Draft a new release** 클릭
3. **Choose a tag** → `v5.1.0` 입력 → *Create new tag* 선택
   - ⚠️ 태그는 반드시 `v5.1.0` 또는 `5.1.0` 형식이어야 앱이 알아봅니다
   - ⚠️ 태그 번호는 `package.json`의 버전과 **똑같이** 맞춰 주세요
4. **Release title**: `Tidy Task 5.1.0` 처럼 입력
5. **Describe this release**: 달라진 점을 한 줄에 하나씩 적습니다
   ```
   - 테마를 15종으로 늘렸습니다
   - 메모가 가끔 저장되지 않던 문제를 고쳤습니다
   ```
   → 이 내용이 앱 안내 창의 "이번에 좋아진 점"에 그대로 표시됩니다
6. ②에서 만든 **`.exe` 파일을 첨부**합니다 (Attach binaries 영역에 끌어다 놓기)
   - ⚠️ 이 파일을 빠뜨리면 앱은 릴리스 페이지 링크만 안내합니다
7. **Publish release** 클릭

끝입니다. 사용자 앱은 최대 6시간 안에(또는 앱을 다시 켜면 8초 뒤에) 알림을 띄웁니다.

## 3. 사용자(선생님)가 겪게 되는 화면

1. **얇은 알림 띠** — 작업을 가리지 않고 창 위쪽에 조용히 나타납니다
   - `×`를 눌러도 "영구 무시"가 아니라 **하루 미루기**입니다. 실수로 닫아도 내일 다시 알려 줍니다
2. **안내 창** (띠를 누르면 열림)
   - 🔒 "지금까지 쓰신 할 일과 메모는 그대로 남습니다" — 가장 먼저 보이는 안심 문구
   - 이번에 좋아진 점 (릴리스 노트)
   - **설치 방법 3단계** — 누를 순서 그대로
   - 💡 "Windows의 PC 보호" 파란 경고창 대처법 (→ [추가 정보] → [실행])
   - [새 버전 내려받기] / [나중에] / [이 버전 건너뛰기]
3. **설정 → 앱 업데이트** — 언제든 직접 확인할 수 있는 고정 경로

## 4. 알아두실 점

- **저장소가 Public이어야 합니다.** Private으로 바꾸면 앱이 릴리스를 읽지 못합니다.
- **릴리스가 하나도 없으면** 앱은 조용히 넘어갑니다. 설정에서 직접 확인하면
  "아직 공개된 새 버전이 없습니다"라고 안내합니다. (오류가 아닙니다)
- **버전을 되돌리면(예: 5.1.0 → 5.0.9)** 앱은 업데이트로 인식하지 않습니다.
  버전 번호는 항상 올라가야 합니다.
- **코드 서명 인증서가 없어** 설치 시 "Windows의 PC 보호" 경고가 뜹니다.
  안내 창에서 대처법을 미리 알려 주므로 사용자가 당황하지 않습니다.
- 사용자 데이터(`tidy-task-config.json`)는 `%APPDATA%` 아래에 저장되므로
  설치 파일을 덮어써도 **삭제되지 않습니다.**
