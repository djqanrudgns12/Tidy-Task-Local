# 할 일 줄 조작 검수 — 2026-11-19

설계: [PRD-todo-row-gestures.md](PRD-todo-row-gestures.md)

할 일 줄 오른쪽의 손잡이·휴지통(투명한 채 약 42px 차지)을 없앴습니다. 순서는 **완료 버튼·날짜 알약을 위아래로 끌어** 바꾸고, 삭제는 마우스를 올리면 톡 나오는 **말랑 X**로 합니다. 지운 직후에는 **휴지통 친구가 있는 되돌리기 알림**이 입력줄 위에 뜹니다. 마감된 일 목록도 같은 X와 알림을 씁니다.

## PRD에서 더 다듬은 것

- **연타 보호 중 같은 자리 누름은 줄 어디서든 통째로 버림**(캡처 단계 pointerdown·mousedown·click·dblclick). X를 더블클릭하면 둘째 클릭이 올라온 다음 줄 글에 떨어져 편집이 시작되고 단어가 선택되던 문제를 검수 중 발견해 막았습니다.
- **보호가 끝날 때 포인터 밑 줄을 다시 읽음.** 줄이 밀려 올라오면 `pointerover`가 오지 않아, 다음 줄의 X가 보이는데 마우스를 움직이기 전까지 눌리지 않았습니다.
- **X 무장은 마우스에만.** 터치·펜은 올림과 누름이 한순간이라 0.15초 규칙이면 X를 영영 못 누릅니다.
- **마감된 일 줄 높이를 예전과 정확히 같게**(`min-height: calc(0.5rem + 13px)` = 예전 휴지통 단추). 측정값 26.31px로 동일 → 5.5줄 목록 높이·창 배치가 바뀌지 않습니다.
- **[되돌리기] 단추가 화면 글자 크기를 따라 커짐**(10pt 24px → 15pt 29.7px).
- 휴지통 친구에 얇은 테두리를 넣어 20px 그림이 방석 색에 묻히지 않게, 방석은 테마 강조색을 옅게 섞었습니다.
- 제목 따옴표는 제목과 함께 말줄임되어, 잘렸을 때 "…’" 사이가 벌어지지 않습니다.

## 검수 방법

실제 `MemoBody`·`TodoList`·`ArchivedList`를 쓰는 개발 미리보기(`?memo-layout-preview&sort-qa&sort-motion=full`)에서 브라우저 실제 포인터·키보드 입력으로 확인했습니다. 저장은 검수 카운터로 대체해 사용자 저장소에는 쓰지 않았습니다.
검수 브라우저 창이 가려진 상태라 프레임(rAF·WAAPI)이 멈춰 있었습니다. 그래서 착지 애니메이션은 `getAnimations().finish()`로 끝까지 진행시킨 뒤 결과를 보고, 화면 캡처는 상태(DOM) 확인과 함께 판단했습니다. "끌다 Esc → 버튼 위에서 뗌"은 마우스를 누른 채 키를 누를 수 없어 같은 순서의 포인터·키 이벤트를 보내 확인했습니다.
