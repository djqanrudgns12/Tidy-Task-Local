# Tidy 툴킷 자리 배치 세부 개발계획

작성: 2026-09-25 · 기준: [PRD v0.2](PRD-classroom-seating.md) · 상태: 개발 준비 문서

## 1. 구현 순서와 완료 정의

PRD의 S01~S08을 모두 출시 범위로 유지한다. 사용자와 확정한 방향은 학급별 자동 전환, 선생님 전용 조건 창, 필수 조건 자동 완화 금지, 최근 확정 기록 3개 참고다. 그림 세부 방향은 제작자에게 위임되었다.

작업 순서는 **데이터 계약 → 교실 조작 → 선생님 조건 → 배치 엔진 → 기록 → 에셋 통합·공개·출력 → 실제 교실 검수**다. 에셋 스타일 검토는 데이터 설계와 독립적으로 진행할 수 있지만 이번 작업에서는 별도 에이전트 작업을 만들지 않는다.

현재 작업 트리에 명단·투표·점수판·툴킷·종료 처리 등의 수정이 있다. 구현 시작 때 `git status --short`와 해당 파일 diff를 다시 읽고 그 위에 필요한 부분만 수정한다. 이 계획은 기존 작업을 되돌리거나 전체 파일을 교체하라는 지시가 아니다.

| 객체 | 필수 값과 불변식 |

| Archive | ID, sessionId, classId, 자동 기록 시각·사용 날짜·제목, 당시 표시값·배치·관계·조건, 사용/사용 안 함 |
| PublicBoard | 공개 세션 ID·순서, 제목·날짜, 허용된 이름/번호·외형·교실·배정. 내부 학생 ID 없음 |

기록에서 학생 ID는 과거 연결을 위한 참조이고 학생 삭제와 함께 제거 가능해야 한다. 이름·번호 스냅샷은 일반 수정으로 바뀌지 않으나 개인정보 삭제 경로로는 지워진다. 공개 데이터에는 화면 내 임시 토큰을 사용한다.

### 저장 구조와 명령

기존 classroom SQLite schema 1에서 순차 migration한다. `seating_drafts`, `seating_archives`, `seating_operations` 등 학급 종속 테이블을 추가하고 class_id 삭제 연계를 둔다. 책상·교실 구조는 검증된 versioned payload로 저장할 수 있으나, 학생 개인정보가 들어 있는 모든 중첩 경로는 삭제 함수와 schema 검증기가 명시적으로 관리한다.

새 명령 예시: `saveDraft`, `saveCurrent`, `setArchiveUsage`, `deleteArchives`, `copyLayout`, `publishBoard`. 요청에는 operationId와 expectedDraftRevision을 넣고 명단 의존 명령에는 expectedClassRevision도 넣는다. `saveCurrent`는 같은 sessionId의 기록을 교체하며 Rust에서 명단 소속·중복 배정·필수 조건을 최종 재검증한다. UI 검증만 신뢰하지 않는다.

명단 전체 revision은 이벤트 순서 확인용, 학급 revision은 후보 신선도 확인용, 배치 revision은 편집 충돌 확인용이다. 공개와 교사 창의 쓰기 경쟁은 동일 저장소에서 직렬화하고 ‘마지막 저장 승리’를 적용하지 않는다. 같은 명령 재전송은 같은 결과를 반환한다.

### 기존 저장소 변경 시 필수 검토

현재 `classroom/mod.rs`의 `init`, `persist`, `transact`, `recover_file`과 `model.rs`의 Backup/Restore 계약을 읽고 함께 변경한다. 기존 명단 undo는 명단 snapshot을 보관하므로 그 상태만으로 배치 삭제를 되돌릴 수 없다. 학급/학생 삭제 작업에 관련 배치의 역변경 묶음을 붙이고 동일 revision 검증 안에서 복구한다. 백업 복원·DB 파일 복구가 새 테이블을 누락하지 않도록 정상 경로와 손상 복구 경로를 각각 검증한다.

## 4. P0 — 데이터와 창 연결

### P0-1. 툴킷 진입

`registry.js`, `preferences.js`, `ToolIcon.svelte`, `ToolkitApp.svelte`, `windows.js`, `src/main.js`, Rust `toolkit.rs`, `lib.rs`, capability 정의를 확인한다. 메인 role `seating`, 선생님 `seating-teacher`, 공개 `seating-display`를 등록한다. 선생님/공개 창은 독립 툴바 항목으로 노출하지 않고 메인에서 연다. 전용 아이콘은 기존 아이콘 체계와 맞는 SVG로 작성한다.

메인 초기 크기 1280×840, 최소 800×600 목표. 선생님 창은 480×760 기준으로 작업 영역에 맞추며, 최소 폭에서도 이름·조건·완료 버튼을 읽을 수 있게 한다. 기존 창을 다시 열면 재사용한다. 항상 위는 기본 끔. 미구현 역할 버튼은 배포 등록하지 않는다.

### P0-2. 학급 전환 상태 기계

상태: `loading → ready → saving → switching → ready`, 보조 상태 `save-error / no-class / deleted / readonly`.

1. 명단 이벤트 구독을 먼저 시작하고 최초 조회한다. focus 복귀 시도 최신 조회한다.
2. 추종 모드는 defaultClassId를 계산한다. 단순 명단 선택은 영향 없음.
3. 현재 조작 취소 → 유효한 초안 저장 → 쓰기 성공 확인 → generation 증가 → 새 학급 읽기.
4. A→B→C가 빠르게 들어오면 A를 안전하게 저장하고 최종 목표 C로 간다. 오래된 B 응답은 폐기한다.
5. 비동기 계산·이미지 준비·조건 저장·공개 응답은 classId와 generation을 검사한다.
6. 저장 실패면 기존 학급을 유지한다. 전환을 기다리는 학급명을 표시하고 재시도한다.
7. 선생님 창이 이전 반에 열려 있으면 편집 초안을 보존한 뒤 새 반으로 함께 전환한다. 오래된 창의 저장은 거부한다.
8. 공개 중 학급 전환은 기존 공개를 먼저 빈 안내 화면으로 바꾸고 새 반 확정 배치가 있으면 원자적으로 교체한다. 초안은 공개하지 않는다.

합격: PRD A01/A02, 응답 순서를 역전시킨 테스트, 이벤트 누락 후 focus 복구, class null·삭제·저장 실패. 기존 `createClassContext` 사용 도구는 동작 변화 없음.

### P0-3. 저장·종료·백업

초안 500ms debounce, drag 종료 즉시 저장 큐 진입, 큐 직렬화, 작업 중복 방지, 최대 세션 undo/redo 50개 목표. 드래그 중간 프레임은 이력으로 쌓지 않는다. 교실/조건 변경은 한 명령 단위로 묶는다.

현재 종료는 명단 창의 확인과 800ms 지연을 사용하는 경로가 있으므로 자리 배치가 이 시간 안에 저장된다고 가정하지 않는다. 앱 종료·업데이트 설치에서 명단과 자리 배치 저장 큐가 완료/실패 응답을 돌려주는 경로를 연결한다. 정상 종료 실패는 창에 돌아가 재시도할 수 있어야 한다.

합격: SQLite v1→v2 migration, v1/v2 백업 복원, 상위 버전 쓰기 차단, 학생/학급 삭제와 undo, 저장 실패 후 재시도, 같은 operation 재전송, 강제 종료 후 마지막 저장 복구. 기존 명단 백업 테스트도 통과.

## 5. P1 — 교실과 조작

### P1-1. 좌표와 숫자

교실 좌표는 표준 1인 책상 폭을 1로 한 논리 단위다. 화면 픽셀은 zoom·pan·보기 방향으로 변환한다. 저장에 화면 픽셀을 쓰지 않는다. 180도 보기 전환은 렌더 변환이며 원본 layout은 유지한다.

숫자 산출은 x/y 중심을 각각 정렬한 뒤 고정 기준점과 허용 오차로 묶는다. 인접한 값들을 연쇄 결합해 멀리 떨어진 책상이 하나로 묶이는 방식은 금지한다. 초기 오차는 책상 폭의 0.12를 제안하고 실제 조작에서 조정한다. 맞춤 진입/이탈 오차를 다르게 해 경계 떨림을 막는다. drag 중에는 committed 번호를 유지하고 preview 번호를 별도로 계산한다.

자유 모양은 안내선이 많아질 수 있으므로 축소 상태에서 겹치는 숫자는 줄여 표시하고 선택한 자리의 위쪽·왼쪽 안내선을 강조한다. 숫자는 학생/자리의 식별자가 아니며 원형 교실도 같은 좌표 규칙을 사용한다.

합격: 새 바깥 위치, 빈 안내선 제거, 거의 정렬된 위치, 원형·모둠형, 음수 위치 확장, 줌·회전 후 hit test, 왕복 변환 오차, 겹침 거절. 좌표 바뀜으로 기록이나 짝 관계가 바뀌지 않음.

### P1-2. 사용자 명령과 조작

명령: swapStudents, moveStudent, moveSeats, rotateSeats, addSeats, removeSeats, alignSeats, setAisle, linkPair, setSeatGroup, lockStudent, lockSeat, setParticipation.

클릭·키보드·pointer drag는 동일 명령을 호출한다. pointer capture 유실·창 focus 유실·Escape·학급 전환은 미확정 이동을 취소한다. 터치는 스크롤과 이동이 구별되도록 명시 조작 방식과 이동 손잡이를 이용한다. 화면 가장자리 자동 스크롤은 선택한 책상을 놓치지 않는 속도로 제한한다.

선택한 책상에만 도구를 보여 주고, 다중 선택 이동은 상대 간격 유지. 학생이 있는 책상 복제 시 학생은 복제하지 않는다. 책상 삭제 후 학생은 대기 영역으로 이동하고 undo로 원래 위치에 돌아간다. 책상 복제의 짝/모둠 관계는 선택 내부 연결만 새 ID로 복사한다.

합격: PRD A03/A04, 빈자리·사용 안 함·고정·전체 선택·부분 선택, 한 작업 되돌리기, 한 학생 중복 배정 불가.

## 6. P2 — 선생님 설정과 조건

선생님 창은 `배치 조건 / 지난 자리`를 큰 글자 탭으로 제공한다. 기본 화면에서는 ‘떨어져 앉기’ 대상 이름·조건 수·고정 이유를 보여 주지 않는다. 개인정보가 있는 조건 편집은 이 창으로 모은다. 조건 때문에 수동 조작을 거절할 때도 본 화면에는 일반 안내만 보낸다.

설정 흐름은 `학생 고르기 → 원하는 배치 고르기 → 조건 추가`로 통일한다. 추가한 배치 조건은 모두 필수이며, 함께 지킬 수 없으면 재배치 결과를 적용하지 않는다. 학생 검색·번호·다중 선택·현재 선택 요약을 제공한다. 거리 선택 시 교사 창 안의 교실 미리보기에서 범위를 표시한다. 큰 교실의 공개 화면에 분리 선을 그리지 않는다.

필수 검증: 같은 학생의 두 자리 고정, 함께/분리 중복, 허용 구역보다 많은 학생, 존재하지 않는 참조, 지정 짝의 중복, 비활성 자리 고정. 성별 미입력은 조건 부재로 분류하며 임의 남/여로 채우지 않는다. 서로 다른 성별의 짝 조건을 엄격하게 적용할 때 미입력 학생이 있으면 지정된 학생들에게만 적용하거나 교사가 조건 범위를 수정하게 한다.

공개용 IPC는 Rust에서 호출 window role을 검사한다. `seating-display`에는 readPublicBoard만 허용하고 roster·rules·archive 조회/쓰기 권한을 주지 않는다. 이벤트도 전체 앱 방송에 개인정보를 넣지 않는다. UI에서 숨겨도 payload에 남으면 실패로 본다.

합격: PRD A05/A08, 키보드 전용 규칙 입력, 단일/다중 모니터 이동, 교사 창 재사용, 공개용 payload 재귀 키 검사, DOM·접근성 트리·로그에 조건 없음.

## 7. P3 — 배치 엔진

### 계산 방식

외부 AI나 네트워크를 사용하지 않는 제약 기반 계산이다. Worker에서 실행하고 seed·engineVersion을 보관한다. 같은 입력·seed는 같은 결과를 반환하도록 한다. 무조건 균등한 무작위라고 설명하지 않는다. 필수 조건과 선호 때문에 후보 분포가 달라진다.

1. 가용 자리와 대상 학생 생성, 고정 학생 선배치, 각 학생의 허용 자리 집합 계산.
2. 인원·허용 자리·짝·분리의 명백한 충돌 사전 탐지. 이 단계에서 증명된 원인만 불가능이라 보고.
3. 한 학생 대상의 필수 조건을 먼저 매칭하고, 해당 자리를 예약한 뒤 앞자리부터 학생 수만큼 후보 자리를 좁힌다.
4. 선택 가능한 자리가 적은 학생부터 배치하는 backtracking과 seeded 후보 순서를 적용한다. 실행 예산과 취소 신호를 검사한다.
5. 실행 가능한 배치에 제한된 횟수의 교환을 적용해 선호 점수를 개선한다. 필수 조건을 깨는 이동은 폐기한다.
6. 가장 좋은 후보를 먼저 고르고, 같은 선호 충족 수준에서 앞선 후보와 학생 위치 차이가 가장 큰 결과를 차례로 골라 `배치 1 / 배치 2 / 배치 3`으로 제공한다.
7. Worker에서 결과를 보내도 main과 Rust 자동 기록 단계에서 다시 검증한다. 계산 결과는 저장 성공과 별개다.

선호 순서는 교사가 정한 우선순위 → 반복 짝 최소 → 반복 모둠 최소 → 위치 반복 최소 → 성별 선택 조건 등으로 명시한다. 숫자 가중치만으로 높은 우선순위 조건 여러 개를 몰래 상쇄하지 않는다. 동점의 선택에 seed를 사용한다. UI에는 점수 숫자 대신 실제 충족·미충족 사실을 보인다.

진행 상태는 계산 중/후보 있음/조건 충돌/시간 내 미발견/취소로 나눈다. 40명 기본은 체감상 즉시, 60명 복합은 0.9초 이내를 목표로 한다. 개선 교환이 전체 시간 예산을 소진하지 않도록 55ms와 제한 횟수 중 먼저 도달한 지점에서 멈춘다. Worker 중지와 취소는 응답 가능한 상태여야 한다.

### 의미 있는 엔진 검증

- 2~8명 작은 문제는 전수 열거 oracle과 비교해 가능/불가능 및 최상위 선호 결과 확인.
- 다양한 seed의 무작위 입력으로 한 학생 한 자리, 필수 조건 위반 0, 고정 유지, 제외 학생 미배정 검사.
- 성비 불균형, 전원 성별 미입력, 홀수, 장애물·통로, 회전 모둠, 짝 없는 자리, 모두 고정, 자리 부족을 fixture로 유지.
- timeout을 불가능으로 잘못 보고하지 않음. 취소·A반 계산 후 B반 전환에서 늦은 결과 폐기.
- JS/Rust 공통 조건 fixture로 확정 검증기의 판정 일치 확인. 테스트용 합성 학생만 사용.

## 8. P4 — 기록과 명단 변경

`saveCurrent`가 완성된 마지막 배치와 현재 사용 포인터 변경을 한 트랜잭션으로 처리한다. 같은 앱 작업의 sessionId가 있으면 해당 기록을 교체하고, 새 작업이면 새 기록을 만든다. operationId로 재전송 중복을 방지한다. 날짜는 표시용이며 기록 순서는 별도 시각값으로 안정화한다.

확정 시 짝 edge·모둠 구성·앞쪽 기준 위치 영역을 저장한다. 지난 짝 집계는 사용한 기록의 고유 학생 ID 쌍을 정렬해 비교한다. 기록 개수/기간 필터는 ‘사용 안 함’과 삭제 기록을 제외한다. UI에 어떤 기록을 참고했는지 교사 창에서 보여 준다.

비교 화면은 자리 이동과 관계 변화를 구분한다. 과거 모양 가져오기에는 학생·개인 규칙을 복사하지 않는다. 과거 배정 복원은 ID가 같은 현존 학생만 연결한다. 없어진 모둠·학생 참조는 명단 reconciliation으로 제거하고 명확한 변경 요약을 보인다.

합격: PRD A06/A07, 같은 작업의 후보 변경 20회/자동 기록 1회, 새 작업에서 새 기록 생성, 사용 취소 후 참고 제외, 개명·번호 재사용·학생 삭제 익명화, v2 backup roundtrip, 기록 삭제 후 통계 재계산.

## 9. P5 — 에셋·완성 화면·공개·인쇄

### 원화 제작

첫 산출물은 독립적인 학생·책상·소품 스타일 시트다. 첨부 화면을 이미지 생성 참고 입력으로 쓰지 않는다. 현대 한국 초등교실, 직접 위에서 본 일정한 시점, 자연스러운 머리색, 차분한 일상복, 작은 손과 책상 형태를 기준으로 제작한다.

순서: 스타일 시트 1장 → 실사용 크기 학생 6명 검수 → 기본형 12종과 소품 → 개별 투명 배경 파일 → 좌석 합성. 생성은 내장 imagegen을 사용한다. 프롬프트와 원본은 artwork에, 검수한 배포 파일만 src/assets에 둔다. 스타일 시트 자체를 잘라 그대로 완성된 게임 에셋이라고 취급하지 않는다.

manifest에는 ID·variant·원본 크기·기준점·시선 방향·라이선스/생성 출처·버전을 기록한다. 자동 선택은 안정적 학생 ID를 사용하되 실제 ID를 생성 프롬프트에 넣지 않는다. 이름·번호·고정 표시는 코드로 합성한다.

눈높이 검수: 실제 80~140px 좌석에서 사람과 책상이 명확한지, 위에서 본 자세가 맞는지, 손·의자·팔이 이상하게 겹치지 않는지, 30명이 모여도 이름이 먼저 읽히는지. 스타일 시트와 배포용 에셋 완료를 구분한다.

### 사용자 화면 검수

Tidy 테마·기본 글꼴·다크 모드에 연결하고 18/20/22px를 검수한다. 30명 교실·홀수 27명·60명·500명 목록 상태를 마련한다. 큰 글씨에서 조건 창과 버튼이 잘리지 않아야 한다. 좁은 화면은 목록/교실 전환과 화면 이동으로 해결하며 모든 이름을 축소하지 않는다.

### 공개와 출력

공개 화면은 확정 스냅샷을 불변 payload로 받아 전체 화면·즉시 공개·선택적 순차 공개를 제공한다. 학생별 이력·조건은 전달하지 않는다. 교사 창에서 진행 중인 후보는 노출하지 않는다. 공개 중 이름/명단 변경은 다음 확정 또는 명시 공개 갱신으로 반영하며 삭제 개인정보는 즉시 철회한다.

PNG 렌더와 인쇄 레이아웃은 DOM screenshot을 무작정 찍지 않고 public projection을 입력으로 한다. 내장 폰트와 이미지 로딩 완료 후 렌더링한다. 인쇄는 타깃 WebView2에서 먼저 기술 검증하고 필요 시 로컬 PDF 생성 경로를 선택한다. PDF 생성 라이브러리는 파일 크기·한국어 폰트·오프라인 동작 검증 후 결정하며 PRD에서 지원 완료로 표기하지 않는다.

합격: A08/A10/A14, 학생 쪽/교사 쪽 좌표와 이름 방향, 긴 이름, 흑백 출력, A4 한 장/분할, 이미지 실패 fallback, offline, 다크 모드, 프린터 대화상자 취소 후 상태 보존.

## 10. P6 — 종합 검증과 배포

| 층 | 확인 | 완료 기록 |
| --- | --- | --- |
| 순수 로직 | geometry·relations·solver·reconcile·projection 테스트 | 명령과 결과 수 |

| 브라우저 | 첫 배치·클릭/키보드/끌기·응답 순서·창 크기 | 가명 자료, 재현 절차·화면 |

권장 명령은 현재 package scripts에 맞춰 `npm.cmd test`, `npm.cmd run check`, `npm.cmd run build`, `cargo test --manifest-path src-tauri/Cargo.toml --lib classroom`을 사용한다. 구현 후 생긴 테스트 경로에 맞춰 focused run을 먼저 한다. 현재 전체 check가 통과하는지 이번 문서 작업에서 실행하지 않았으며 과거 오류 개수를 현재 기준으로 재사용하지 않는다.

품질 중단 기준: 반이 섞임, 필수 조건 위반 확정, 개인정보 공개 payload 포함, 명단 삭제 후 개인정보 잔존, 복원 누락, 정상 종료 미저장 유실. 이 항목이 남으면 미완료 기능을 툴킷에 노출하지 않는다. 사용성 목표는 실제 사용자 관찰 전에는 ‘확인됨’으로 쓰지 않는다.

## 11. 순서별 산출물과 의존성

| 단계 | 완료 산출물 | 선행 조건 |
