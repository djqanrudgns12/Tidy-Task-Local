# 간단 뽑기 PRD

작성일: 2026-09-21 · 대상: Tidy Task Local 학급 툴킷 후속 개발

문서 개정: v0.3 · 구현 승인 반영, 30명 동적 배치와 검증 결과 연결. 사용자 확정 사항은 2절이며 아래 구현 결정이 이전 제안과 충돌하면 우선한다.

**상태: 사용자의 ‘구현해’ 지시에 따라 구현 및 검증 진행.**

### v0.3 구현 결정

- 클래식 280ms, 인형 4.3초, 풍선 다트 3.1초. 연출 전에 결과를 확정하고 완료를 한 번만 기록한다.
- 창 안에서 모드와 성별 필터를 바꿔도 동일 학급의 제외 기록을 공유한다. 학급/직접 목록별 기록은 분리하며 창을 닫으면 초기화한다.
- 직접 입력 목록은 ‘목록 저장’을 누를 때만 기기에 보관한다. 추첨 결과와 일시 제외 기록은 저장하지 않는다. 풍선 모드 구현 명칭은 ‘풍선 다트’로 채택했다.
- **20·25·30명 모두 후보 수만큼 인형/풍선을 배치한다.** 남은 인원에 따라 열·행·크기·집게 크기를 함께 조절한다. 15명을 넘으면 풍선 이동 폭을 줄이고 무대 높이를 늘린다. 최소 창 640×520에서는 상단을 압축하고 추첨 버튼을 화면 하단에서 접근할 수 있게 한다.
- 무대는 최대 30개만 렌더링한다. 31~500개 직접 목록도 모든 항목이 동일한 추첨 후보이며 시각 오브젝트 수로 확률을 결정하지 않는다. 연출 중에는 시작 시점의 배치를 고정한다.
- 인형 독립 이미지 6종과 풍선 실루엣 6종, 혼합/개별 디자인 및 팔레트 3종을 제공한다. 소수 후보일 때는 실제 후보 수를 우선한다.
- 검증 증거와 실제 확인 범위는 [간단 뽑기 QA](QA-classroom-picker.md)에 기록한다. 아래의 초기 계획 전체가 자동으로 검증 완료되었다는 뜻은 아니다.

선행 문서: [후속 개발 인계서](HANDOFF-classroom-toolkit-next-development.md), [학급 명단 PRD](PRD-classroom-roster.md). 현재 코드와 최신 사용자 결정을 우선한다. 기존 타이머·알림장·학급 명단과 작업 폴더의 진행 중인 변경을 보존한다.

## 1. 목적

교사가 학급 명단 또는 직접 입력한 목록에서 대상을 빠르고 공정하게 뽑는다. 같은 추첨 기능을 클래식·인형 뽑기·풍선 연출로 제공한다. 클래식은 반복 사용의 속도, 인형과 풍선은 움직임의 완성도와 결과를 기다리는 재미를 중심에 둔다.

모드는 외형과 연출만 바꾼다. 추첨 확률·대상·중복 제외 정책은 공통으로 적용한다. 작은 설정을 바꿀 때마다 흐름을 끊거나 결과 확인 팝업을 닫게 하지 않는다.

### 1.1 사용 장면과 성공 조건

| 사용 장면 | 목표 흐름 | 성공 조건 |
| --- | --- | --- |
| 수업 중 발표자 연속 선정 | 학급 확인 → 클래식 → 반복 추첨 | 결과 확인을 위한 추가 클릭 없이 다음 학생 선정 |
| 활동 시작 전 기대감 형성 | 인형/풍선 선택 → 뽑기 | 한 번의 클릭으로 준비·이동·접촉·공개까지 자연스럽게 완료 |
| 발표할 모둠 결정 | 모둠 이름 붙여넣기 → 적용 → 뽑기 | 학생 명단·모둠원 등록 없이 모둠 이름으로 완료 |
| 수업 활동·순서 결정 | 직접 목록 입력 → 중복 제외 → 반복 추첨 | 마지막 항목까지 빠짐없이 뽑고 소진 상태를 명확히 표시 |

공통 조작을 먼저 익히면 다른 모드에서도 그대로 사용할 수 있어야 한다. 재미를 위한 디자인과 움직임은 무대 안에 집중하고, 설정·결과·버튼의 위치와 의미는 유지한다.

| R13 | 인형과 풍선은 다양한 디자인으로 구성 | 한 인형 반복·동일 풍선의 색상 변경만으로 완료 처리하지 않음. 형태·디테일·움직임 차이를 실제 화면에서 확인 |

## 3. 설계 제안과 미확정 정책

아래는 사용자 확정 사항과 구분되는 PRD 제안이다. 문서 검토 시 변경할 수 있다.

| 항목 | 제안 | 이유 |
| --- | --- | --- |
| 풍선 모드 이름 | **풍선 다트** | 동작을 바로 이해할 수 있음. ‘풍선 톡!’은 대안 |
| 창 | 간단 뽑기 창 하나를 재사용하고 내부에서 모드 변경 | 같은 창의 제외 기록을 유지하기 쉬움 |
| 시작 상태 | 클래식·전체 선출·현재 기본 학급 | 수업 중 빠른 진입 |
| 한 번에 뽑는 수 | 첫 버전은 1명 또는 1개 | 세 모드의 결과 연출과 취소 규칙을 일관되게 유지 |
| 중복 제외 | 최초 ON | 발표자 등을 골고루 뽑기 쉽게 함 |
| 직접 입력 목록 보관 | ‘목록 저장’으로 명시적으로 로컬 보관, 미저장 목록은 창 세션 동안만 유지 | 학생 이름과 일반 항목이 혼재하므로 자동 영구 보관을 피함 |
| 저장 목록 관리 | 모둠·일반 목록을 분리하고 목록 이름으로 다시 불러오기 | 학급 데이터와 혼동 방지 |
| 설정 보관 | 효과음·연출 줄이기 선호만 로컬 저장 | 추첨 실행 상태와 설정 분리 |
| 효과음 | 기본 ON, BGM 없음 | 짧은 조작·결과 피드백에 한정 |

**검토가 필요한 핵심은 직접 입력 목록의 보관 방식이다.** 사용자에게 확인된 것은 ‘등록해서 뽑기’이며, 앱 재실행 후 목록 보관까지 확정된 것은 아니다. 구현 시 이 제안을 채택할지 확인한다. 결과·제외 기록의 비영속 정책과 목록 자체의 보관 정책을 섞지 않는다.

### 3.1 결정 관리와 기본값

- 추가 제안: 디자인 선택은 ‘다양하게’가 기본이며, 같은 창에서 선택을 유지한다. 최초에는 각 모드의 기본 컬렉션을 혼합 표시한다. 디자인 선호 영속화는 이번 제안에 포함하지 않는다.
- 목록 보관 정책이 미확정이어도 추첨·연출·세션 목록의 세부 설계는 진행할 수 있다. 실제 구현은 사용자 지시 후 시작하며, 저장 기능은 정책 확정 전 DB 스키마부터 만들지 않는다.
- 창 재사용·모드 이름·수량·타이밍은 본 문서의 제안값을 기준으로 검토한다. 이미 확정된 자동 연출·직접 모둠 입력·창 세션 기록 범위는 다시 선택 사항으로 돌리지 않는다.
- 승인 후 제안값이 바뀌면 변경 이유와 영향 범위를 PRD·검증 목록에 함께 반영한다. 수치 조정으로 사용자 확정 요구를 축소하지 않는다.

## 4. 범위

포함: 세 모드, 다섯 대상 유형, 학급 선택, 직접 입력·여러 줄 붙여넣기, 후보 확인·일시 제외, 중복 제외, 섞기, 직전 뽑기 취소, 최근 결과, 다시 시작, 효과음, 연출 줄이기, 키보드, 창 크기 조절·항상 위·전체화면, 실패 및 후보 소진 처리.

직접 입력 목록의 저장·불러오기는 3절 정책 확정 후 포함 여부를 결정한다. 목록 편집은 공통으로 제공한다.

후속: 여러 명 동시 추첨, 모둠별 한 명, 자동 모둠 편성, 가중치·확률 편집, 추첨 결과 내보내기, 영구 이력, 교사/학생 별도 화면, 추가 뽑기 모드.

제외: 온라인 계정·클라우드 동기화·명단 외부 전송, 실제 경품 지급, 당첨자 사전 지정, 실패 확률이 있는 집게 게임, 점수판 자동 반영. 인형 개수나 풍선 위치가 추첨 확률에 영향을 주지 않는다.

### 4.1 작업 단위와 의존성

| 묶음 | 포함 작업 | 선행 조건 | 완료 산출물 |
| --- | --- | --- | --- |
| 공통 기반 | 후보·난수·상태 전이·제외·취소 | 기존 명단 계약 확인 | 순수 로직과 경계 테스트 |
| 대상 UI | 5개 유형·입력·미리보기·일시 제외 | 공통 후보 인터페이스 | 빈 상태부터 후보 소진까지 동작하는 화면 |
| 클래식 | 빠른 공개·반복 조작·최근 결과 | 공통 상태 | 반복 추첨 검증 |
| 인형·풍선 | 다양한 에셋·접점·타임라인·섞기 | 공통 상태, 에셋 좌표 계약 | 실제 재생 가능한 두 무대 |
| 통합 | 창·툴바·노출 설정·음향·접근성 | 각 모드 | 브라우저/네이티브 검증 보고 |

디자인 다양성은 첫 버전 필수 범위다. 토끼 한 종이나 풍선 한 모양만 구현한 상태를 세 모드 완료로 보고하지 않는다. 다양한 테마를 추가 구매·다운로드하게 만드는 상점 기능은 포함하지 않는다.

## 5. 진입과 화면 구조

툴킷의 ‘간단 뽑기’로 독립 창을 연다. 명단 버튼은 툴바 끝에 유지하고 도구 노출 설정에도 연결한다. 이미 열린 뽑기 창이 있으면 현재 모드·명단·결과를 유지한 채 앞으로 가져오는 것을 제안한다.

```text
간단 뽑기                         항상 위 / 전체화면 / 닫기
클래식       인형 뽑기       풍선 다트

전체 선출 ▾          5학년 2반 ▾           대상 24명 · 남은 21명
┌───────────────────────────────────────────────────────────┐
│                                                           │
│                  모드별 무대 / 큰 결과                     │
│                                                           │
└───────────────────────────────────────────────────────────┘
                   [ 뽑기 / 다음 뽑기 ]       섞기
뽑힌 대상 제외 [켜짐]                     대상 관리 / 설정
최근 결과       8번 예시학생 · 12번 예시학생     직전 뽑기 취소
```

- 상단 모드 선택 후 대상 선택기를 누르면 다섯 유형을 표시한다. 깊게 중첩된 메뉴는 쓰지 않는다.
- 학급 기반 유형에서만 학급 선택기를, 직접 입력 유형에서만 목록 이름·편집 버튼을 표시한다.
- 최초 학급 명단이 없으면 전체·성별 유형은 이유와 ‘학급 명단 등록’ 진입을 표시한다. 직접 입력 두 유형은 계속 이용할 수 있다.
- 무대·결과가 화면의 중심이다. 일시 제외·최근 결과 전체·추가 설정은 필요할 때 펼친다.
- 결과는 무대 안에서 공개하고 다음 추첨 전까지 유지한다. 별도 확인 모달은 띄우지 않는다.
- 창 기본 960×720, 최소 640×520 논리 픽셀 제안. 좁은 폭에서는 설정을 아래로 배치한다. 전체 가로 스크롤 금지.
- 전체화면 진입 전 창 위치·크기와 포커스를 보존하고 ESC로 복귀한다. 전체화면 해제는 추첨 취소가 아니다.

### 5.1 제어별 상세 동작

| 제어 | 동작 | 상태·포커스 처리 |
| --- | --- | --- |
| 모드 탭 | 공통 후보·기록을 유지하고 무대만 교체 | 연출/섞기 중 비활성. 마지막 결과는 새 모드의 결과 영역에 표시 |
| 대상 선택 | 5개 유형과 사용 가능 여부 표시 | 등록 불가 이유를 메뉴에서 읽을 수 있게 하고 빈 화면으로 보내지 않음 |
| 학급/목록 선택 | 해당 원본의 후보·기록으로 전환 | 학급↔직접 목록이 서로 덮어쓰지 않음. 전환 후 현재 대상 제목 갱신 |
| 대상 관리 | 검색·일시 제외·복귀 | 원본 삭제와 구분. 닫으면 열었던 버튼으로 포커스 복귀 |
| 설정 | 효과음·연출 줄이기·디자인 | 접어도 선택 유지. 디자인 설정은 연출 모드에만 노출 |
| 섞기 | 인형·풍선 배치를 0.6~0.9초간 재구성 | 클래식에서는 숨김. 진행 중 뽑기와 중복 실행 불가 |
| 최근 결과 | 기본 최신 5건, 펼쳐서 전체 열람 | 무대 높이는 유지하고 기록 영역만 스크롤 |
| 다시 시작 | 초기화 대상 이름·제외 유지 정책 확인 | 취소하면 상태 불변. 확인 후 뽑기 버튼으로 복귀 |

### 5.2 반응형 배치 계획

- 880px 이상: 무대 중심, 펼친 보조 패널은 최대 약 260px. 공간이 부족하면 무대 폭을 계속 줄이지 말고 패널을 아래로 이동한다.
- 640~879px: 무대 위에 두 줄 이내 대상 조작, 설정·기록은 무대 아래 하나씩 펼친다. 여러 보조 영역을 한꺼번에 열어 무대를 가리지 않는다.
- 520px 높이에서는 부가 설명과 기록을 먼저 접고 뽑기 버튼을 보이게 한다. 문서 전체 스크롤은 허용하되 무대 위에 고정 패널을 겹치지 않는다.
- 창 크기를 바꾸면 동일한 무대 좌표계를 비례 변환한다. 진행 중 리사이즈로 집게·인형 또는 다트·풍선이 따로 이동하지 않는다.
- 초기에는 무대를 로딩 상태로 두고 필요한 에셋 준비 후 추첨을 활성화한다. 이전 결과가 있다면 로딩·오류 패널과 별도로 계속 읽을 수 있게 한다.

## 6. 대상 구성

| 유형 | 데이터 | 표시와 빈 상태 |
| --- | --- | --- |
| 전체 선출 | 선택 학급의 모든 학생 | 성별 미등록 학생 포함. 번호·이름 표시 |
| 모둠 선출 | 직접 입력한 모둠 목록 | 예: 1모둠, 초록 모둠. 모둠원이나 인원수 불필요 |
| 남학생 | 선택 학급에서 성별이 남학생인 학생 | 해당 학생이 없으면 뽑기 비활성 |
| 여학생 | 선택 학급에서 성별이 여학생인 학생 | 해당 학생이 없으면 뽑기 비활성 |
| 직접 명단 등록 | 직접 입력한 사람·활동·일반 항목 | 학급·번호·성별 불필요 |

- 성별 미등록은 임의 추정하지 않는다. 성별 유형에서 ‘성별 미등록 N명은 포함되지 않아요’와 명단 수정 진입을 제공한다.
- 학급 학생은 이름이 아닌 불변 ID로 식별한다. 동명이인은 번호로 구분하고 개명 후에도 제외 기록을 유지한다.
- 직접 입력은 한 줄 한 항목, 공백 제거·빈 줄 무시, 등록 전 미리보기. 최대 500개·항목당 40자 제안. 한도 초과는 잘라 저장하지 않고 수정 안내한다.
- 같은 글자의 항목이 여럿이면 중복을 표시하고 의도한 별개 항목인지 확인한다. 임의 병합하지 않는다. 유지 시 각각 ID와 표시용 구분 번호를 부여하고 확률이 항목 수만큼 늘어남을 안내한다.
- 모둠 목록과 일반 목록은 별도 보관한다. 유형을 바꿔도 작성 중인 내용은 같은 창 안에서 유지한다.
- 학급 원본은 뽑기 화면에서 변경하지 않는다. 결석자는 ‘이번 뽑기에서 제외’로 처리한다.

### 6.1 직접 입력·수정 흐름

1. 처음 모둠/직접 입력을 선택하면 제목과 여러 줄 입력 영역을 표시한다. 모둠 예시는 placeholder로만 제공하고 실제 후보에 넣지 않는다.
2. 입력 → ‘목록 확인’ → 번호·항목·오류를 미리보기 → ‘이 목록으로 뽑기’ 순서로 적용한다. 미리보기 전에 실제 후보를 변경하지 않는다.
3. 공백 정리 외 쉼표·괄호·숫자를 임의 분리하거나 이름을 추정하지 않는다. 이름 안의 쉼표도 보존한다. 번호+이름 구조의 파일 가져오기는 기존 학급 명단에서 수행한다.
4. 중복 항목은 해당 행을 함께 강조하고 수정 또는 ‘별개 항목으로 유지’를 제공한다. 모든 문제가 해결되어야 적용할 수 있다.
5. 적용 후 개별 행 편집은 entryId를 유지한다. 전체 붙여넣기는 ‘새 목록으로 적용’임을 밝히고 기존 세션 목록과 분리한다.
6. 편집 중 닫기는 ‘변경 버리기/계속 편집’을 제공한다. 이미 적용한 미저장 목록은 같은 창에서 보존한다. 저장 기능을 채택할 경우에만 별도 ‘목록 저장’을 제공한다.

### 6.2 후보 계산과 카운트

후보 계산 순서는 원본 선택 → 유형 필터 → 일시 제외 → 중복 제외다. 화면에 ‘대상’은 유형 필터 후 수, ‘남은’은 최종 추첨 가능 수를 표시한다. ‘대상 관리’에는 전체 대상·일시 제외·이전 당첨·최종 후보 수를 구분한다. 같은 항목이 일시 제외와 이전 당첨에 모두 속할 수 있으므로 제외 수를 단순 합산하지 않는다.

검색은 표시 행만 필터링하며 추첨 후보를 바꾸지 않는다. ‘검색 결과 전체 제외’ 같은 대량 조작은 이번 버전에 넣지 않고, ‘일시 제외 모두 해제’만 명확한 범위로 제공한다.

## 7. 공통 추첨·중복 제외 규칙

### 7.1 공정성 및 확정 시점

1. 사용자가 뽑기를 누르면 현재 후보 목록과 표시 이름을 스냅샷으로 고정한다.
2. 균등 난수로 결과를 한 번 선택한다. 이후 애니메이션은 정해진 결과를 보여준다.
3. 결과·후보 버전·실행 ID를 세션 상태에 기록하고 추가 뽑기 입력을 잠근다.
4. 연출 종료 시 결과를 정확히 한 번 공개하고 완료 기록에 넣는다.

난수는 Web Crypto 기반 균등 정수 추출과 rejection sampling을 제안한다. 섞기는 Fisher–Yates를 사용한다. 난수 정렬 comparator나 단순 나머지 연산의 편향을 피한다. 시각적 인형·풍선 수는 전체 후보 수와 다를 수 있으며 ‘남은 N명/개’가 실제 후보 수를 나타낸다. 시각적 개수에 맞춰 후보를 잘라내지 않는다.

### 7.2 제외 기록의 범위

- 상태 키: 학급 학생은 `classId + studentId`, 직접 입력은 `listId + entryId`. 유형·모드는 키에 포함하지 않는다.
- 전체에서 뽑힌 학생은 같은 학급의 남학생·여학생 유형으로 전환해도 제외된다. 학급을 바꿨다가 돌아오면 이전 학급의 기록을 유지한다.
- 직접 입력의 ‘홍길동’과 학급의 같은 이름 학생은 별개 대상이다. 이름만으로 연결하지 않는다.
- 중복 제외 OFF 동안에는 이전 결과도 후보가 된다. 이때의 결과 역시 기록한다. 다시 ON으로 바꾸면 해당 세션에서 한 번이라도 뽑힌 대상을 제외한다.
- 모드·유형 전환과 섞기는 기록을 초기화하지 않는다. 닫기 또는 앱 종료 시 결과·제외·일시 제외 기록을 제거한다.
- ‘다시 시작’은 현재 학급 전체 또는 현재 직접 입력 목록의 결과·당첨 제외 기록을 초기화한다. 결석 등 일시 제외는 유지한다. 확인 화면에 범위를 명시한다.
- 모든 후보가 소진되면 ‘모두 뽑았어요’와 다시 시작을 표시한다. 자동으로 후보를 복구하지 않는다.

### 7.3 취소·제외·편집

- 직전 뽑기 취소는 현재 학급/목록의 마지막 완료 결과를 제거한다. 중복 허용 상태에서 같은 대상의 더 이전 결과가 남았다면 제외 상태도 유지한다.
- 결과를 계속 취소하면 한 건씩 이전으로 되돌릴 수 있다. 연출 중에는 취소·대상 변경·모드 전환·초기화·섞기를 잠근다.
- 대상 관리에서 번호·이름 검색, 개별 일시 제외/복귀, 현재 후보 수를 제공한다. 제외 사유나 결석 정보를 학급 원본에 저장하지 않는다.
- 직접 목록 개명·항목 이름 수정은 ID를 유지한다. 새 항목에는 새 ID를 발급한다. 목록 전체 교체는 새 목록으로 취급하고 기록 전환을 안내한다.
- 최근 결과는 현재 학급/목록 기준으로 표시한다. 기본은 최신 5건, 펼치면 세션 전체. 수백 회 반복 시에도 제어 버튼이나 무대가 밀려나지 않는다.

### 7.4 상태 전이와 실행 보호

| 상태 | 진입 조건 | 가능한 행동 | 종료 조건 |
| --- | --- | --- | --- |
| loading | 명단/에셋 준비 | 닫기·다른 사용 가능한 대상 선택 | 준비 완료 또는 오류 |
| ready | 후보가 있고 무대 준비 완료 | 뽑기·섞기·설정·편집 | 실행 시작 |
| shuffling | 섞기 클릭 | 음소거·창 조작 | 배치 안정 후 ready/result |
| drawing | 결과 1회 확정 | 음소거·연출 줄이기·창 조작 | 공개 완료 또는 연출 복구 |
| result | 결과 완료 | 다음 뽑기·취소·전환·초기화 | 다음 조작 |
| empty | 후보 0 | 대상 수정·제외 복귀·다시 시작 | 후보 복구 |
| error | 명단/필수 에셋 실패 | 재시도·다른 모드·닫기 | 의존성 회복 |

- 뽑기 처리의 첫 동기 구간에서 잠금을 건 뒤 스냅샷과 난수를 만든다. async 로딩·애니메이션 시작 전에 잠금이 걸려야 연타가 두 결과를 만들지 않는다.
- 실행 객체는 runId, sourceKey, 원본 revision, 후보 ID/이름 스냅샷, winner, mode, 시작 시각, 완료 여부를 가진다. 완료 함수는 같은 runId의 재호출을 무시한다.
- 시각 효과의 난수와 후보 선택 난수는 서로 분리한다. 색·인형 종류·타임라인 변형을 바꿔도 동일한 주입 난수에서 winner가 유지되도록 테스트한다.
- 추첨 완료 후 최종 후보가 0이면 결과는 그대로 남기고 조작부만 소진 상태가 된다. empty 상태가 결과를 지우지 않는다.
- 닫기는 언제나 허용한다. 실행 중 닫힌 세션을 다른 창으로 전달하거나 다음 열기에 복원하지 않는다.

### 7.5 세션 데이터와 취소 상세

`sourceKey`별로 완료 결과 배열·일시 제외 ID 집합·직접 입력 편집 상태를 둔다. 당첨 제외는 완료 결과의 ID별 출현 횟수에서 파생한다. 취소 시 횟수를 1 감소시켜 과거의 같은 대상 결과가 남는지 판단한다. 별도의 임의 boolean 집합과 결과 배열이 서로 어긋나지 않게 한다.

삭제된 학생의 이전 결과는 당시 이름으로 읽을 수 있지만 후보로 복구하지 않는다. 취소는 결과를 지울 뿐 삭제된 학생을 재생성하지 않는다. 다시 시작·취소는 명단 원본에 쓰기 명령을 보내지 않는다.

## 8. 모드별 연출 사양

시간은 검수용 목표이며 확정 수치는 아니다. 일반 설정에서 클래식 0.2~0.35초, 인형 3.8~4.6초, 풍선 2.6~3.4초를 목표로 한다. 실제 프로토타입에서 리듬을 확인한 뒤 조정한다.

### 8.1 클래식

- 대기: 큰 결과 영역과 뽑기 버튼. 불필요한 루프 애니메이션 없음.
- 진행: 짧은 카드 전환·위치 이동과 함께 결과 공개. 여러 가짜 이름을 오래 돌리거나 카운트다운하지 않는다.
- 결과: 번호는 보조, 이름은 중심. 다음 뽑기로 즉시 이어갈 수 있다. 버튼 위치와 포커스 유지.
- 길게 누르기·키 반복은 한 번의 추첨으로 처리한다. 별도 입력을 빠르게 반복하는 것은 허용한다.

### 8.2 인형 뽑기

- 외형: 밝은 세이지·아이보리의 간결한 기계 프레임. 유리 영역·레일·집게·바닥·배출구의 관계가 읽혀야 한다. 간판 문구와 장식 전구는 최소화한다.
- 대기: 인형은 바닥에 안정적으로 놓인다. 모든 인형을 계속 튀게 하지 않는다.
- 0~0.8초: 레일 위 집게가 좌우로 이동해 멈춤. 케이블과 집게가 함께 이동하며 끝에서 작게 흔들림.
- 0.8~1.6초: 케이블이 길어지고 열린 집게가 목표 인형까지 내려감.
- 1.6~2.1초: 집게가 닫히고 인형이 살짝 눌림. 인형이 갑자기 나타나거나 집게에서 떠 있지 않음.
- 2.1~3.2초: 같은 인형이 집게에 붙어 올라옴. 관성에 따른 작은 흔들림과 그림자 변화를 연결.
- 3.2~4.2초: 배출 위치로 이동해 인형을 내려놓고 이름표 공개. 공개 완료 후 다음 추첨 활성화.
- 섞기: 바닥 인형이 짧은 곡선 이동과 회전으로 재배치된 뒤 안정됨. 집게 추첨과 동시에 실행하지 않는다.
- 실패·놓침 연출 없음. 뽑기마다 하나의 결과를 보장하며 장식 인형별 종류·크기가 확률을 바꾸지 않음.

### 8.3 풍선 다트

- 외형: 여백 있는 밝은 무대와 차분한 3~4색 풍선. 실제 이름은 결과 전 숨긴다.
- 대기: 풍선마다 시작점·주기·진폭을 달리해 떠 있는 느낌을 만든다. 실과 몸체가 연결되고 급격한 방향 전환·큰 겹침을 피한다.
- 0~0.9초: 움직이는 풍선들 사이에서 장면이 정리되고 다트가 준비됨.
- 0.9~1.7초: 다트가 곡선을 따라 날아감. 발사 시점에 목표의 도착 위치를 계산하거나 목표 궤적을 제어해 실제 접점에서 충돌하게 함.
- 1.7~2.2초: 맞은 풍선이 짧게 변형된 뒤 터짐. 작은 조각은 신속히 사라지고 눈부신 섬광·화면 흔들기 없음.
- 2.2~3.1초: 해당 위치에서 이름 카드가 펼쳐져 중심에 안착. 배경 풍선은 잔잔해져 결과에 시선 집중.
- 섞기: 풍선 배치를 부드럽게 바꾸고 이름이나 당첨 제외 기록은 바꾸지 않는다.
- 다트가 빗나가는 연출, 수동 조준·추가 클릭, 특정 색의 당첨 가중치 없음.

### 8.4 동작 줄이기·중단

- OS의 reduced motion을 우선 반영한다. 설정에서 사용자가 추가로 연출을 줄일 수 있다.
- 줄인 모드에서는 이동·루프·다트 비행을 생략하고 0.15~0.3초의 차분한 결과 전환을 사용한다. 결과·확률·기록은 동일하다.
- 탭 숨김·창 최소화로 시간이 지나도 재추첨하지 않는다. 복귀 시 확정된 결과를 한 번만 완료한다. 소리가 뒤늦게 몰아서 재생되지 않게 한다.
- 창 닫기 시 애니메이션·타이머·이벤트·오디오를 정리한다. 세션은 버리고 다음 실행 시 복원하지 않는다.

### 8.5 다양한 디자인과 움직임 연결

| 모드 | 디자인별 차이 | 공통으로 고정할 것 |
| --- | --- | --- |
| 인형 | 귀·꼬리·몸통 실루엣, 크기 비율, 들렸을 때 회전 중심·흔들림 폭 | 동일한 추첨 확률, 집게에 붙는 접점, 전체 연출 시간 범위 |
| 풍선 | 둥근형·긴형·별·하트·꽃·곰 얼굴형, 무늬, 느린 부유 주기 | 한 번의 자동 발사, 실제 충돌, 동일 결과 공개 시간 범위 |

- 인형별 anchor를 정의한다: grip(집는 위치), center(회전 중심), foot(바닥 접점), label(결과 이름표 위치). 이미지를 똑같은 사각형으로 취급해 귀를 집거나 바닥에 파묻지 않는다.
- 기계의 레일·집게·인형·배출구는 하나의 정규화 좌표계에서 이동한다. 상승 구간은 grip을 집게 접점에 구속하고, 배출 순간에만 구속을 해제한다.
- 토끼는 긴 귀의 작은 후행 회전, 곰은 낮은 흔들림, 펭귄은 몸통의 짧은 좌우 기울기처럼 소재와 실루엣에 맞춘 차이를 준다. 귀/꼬리 분리 레이어가 없는 이미지에 가짜 관절 회전을 강제하지 않는다.
- 풍선은 유형별 path·충돌 내부 영역·매듭 위치를 둔다. 별·하트의 오목한 투명 영역이 아닌 실체 내부를 겨냥한다. 실은 매듭 위치에 고정하고 진폭에 맞춰 따라 움직인다.
- 다트 충돌 시점은 하나의 시간 기준으로 계산한다. 위치 추측 후 별도 CSS 루프에 맡겨 다트와 풍선이 어긋나지 않게 한다.
- 매번 같은 위치를 집거나 같은 풍선만 맞히지 않도록 시각 타깃 위치와 이동 경로를 바꾼다. 시각 다양성 보정은 winner 확정 후 수행하고 학생 당첨 결과에는 관여하지 않는다.

### 8.6 타임라인 구현·복구 계획

- 공통 타임라인은 준비·이동·접촉·공개·완료 신호를 내고, 각 무대는 그 신호를 시각화한다. 상태 잠금 해제를 CSS animationend 하나에만 의존하지 않는다.
- 정상 완료 신호와 상한 시간 점검을 함께 둔다. 프레임 중단·에셋 오류 등으로 연출이 끝나지 않으면 이미 선택한 결과를 단순 카드로 공개하고 잠금을 해제한다. 재추첨은 하지 않는다.
- 진행 중 ‘연출 줄이기’를 켜면 현재 결과의 간단 공개 단계로 이동해 정확히 한 번 완료한다. 다시 끄기는 다음 추첨부터 적용한다.
- 창이 숨겨지면 오디오와 장식 루프를 정지한다. 다시 보일 때 경과시간에 맞춰 결과로 진행하되 지난 음향 이벤트는 버린다.
- 모든 animation·requestAnimationFrame·타이머·ResizeObserver·오디오 노드는 모드 종료/창 닫기에서 해제한다. 이전 모드 callback은 현재 실행을 변경할 수 없게 실행 ID와 dispose 여부를 확인한다.

## 9. 시각 디자인과 이미지 자산

- 기준은 `appearance.js`의 밝은 툴킷 표면과 현행 타이머·알림장 팝업이다. 폰트는 앱 설정을 따른다.
- 옅은 활성 배경, 절제된 테두리, 넓은 무대와 간결한 조작. 모든 설정을 카드·그림자·배지로 감싸지 않는다.
- 설명은 빈 상태나 오류처럼 필요한 곳에만 둔다. ‘마법 같은 순간’, ‘행운의 주인공’ 등 상투적인 홍보 문구를 기본 UI에 넣지 않는다.
- 인형은 생성 래스터 이미지로 질감을 표현한다. 집게·케이블·풍선·이름표·버튼은 크기에 맞게 제어할 수 있는 코드 기반 요소로 구현한다. UI 전체를 생성 이미지 한 장으로 만들지 않는다.
- 이미지에는 이름·학생 번호·버튼 글자를 넣지 않는다. 가장자리·투명도·색·해상도·작은 크기에서의 실루엣을 검수한다.
- 런타임에는 선택된 최종 에셋만 넣는다. 원본·프롬프트·생성 방식은 artwork 아래 기록한다. 최종 파일 크기와 로딩 지연은 실제 출력 확인 후 예산을 정한다.

현재 생성한 [토끼 인형 시안](../artwork/toolkit/picker/rabbit-concept-v1.png)은 **디자인 검토용이며 채택 미확정**이다. 내장 ImageGen으로 생성했으며 런타임 코드에 연결하지 않았다. 생성 기록은 [자산 메모](../artwork/toolkit/picker/README.md)에 있다.

### 9.1 디자인 다양성의 기준

사용자 확정은 ‘다양한 디자인’이며 아래 수량·종류는 첫 버전 제작 목표다. 서로 다른 실루엣·소재 디테일을 기준으로 종류를 센다. 토끼 이미지를 색만 바꾼 6개는 6종으로 세지 않는다. 풍선도 단색 원형의 색상만 바꾸어 완료하지 않는다.

| 구성 | 첫 버전 제안 | 화면에서 확인할 차이 |
| --- | --- | --- |
| 인형 | 최소 6종: 토끼·곰·고양이·강아지·펭귄·병아리 | 귀·주둥이·날개·몸통 실루엣과 얼굴 디테일 |
| 풍선 | 최소 6종: 둥근형·긴형·별·하트·꽃·곰 얼굴형 | 외곽 형태·매듭 위치·폭과 높이 비율 |
| 풍선 무늬 | 무지·작은 점·가느다란 줄 3계열 | 채도 높은 복잡한 무늬 없이 가까이서 구분 |
| 무대 팔레트 | 세이지·버터·스카이 3계열 | 프레임·배경·보조색 조화. 텍스트 대비 유지 |

초기 제공을 수십 종으로 늘리기보다 6종씩의 완성도를 확보한다. 최종 목록은 비교 시안에서 교체 가능하지만 수량 감소·단일 디자인 회귀는 요구 축소로 기록한다. 풍선 무늬는 각 형태에 어울리는 조합만 선별하며 모든 조합을 기계적으로 곱하지 않는다.

### 9.2 화면 구성·배치·선택 경험

- 기본 ‘다양하게’는 후보가 4명 이상이면 4종 이상을 섞는다. 최대 30명까지 남은 후보마다 오브젝트를 하나씩 배치하고, 창 크기와 후보 수에 맞춰 크기·간격을 조절한다. 30개를 넘는 목록은 무대만 30개로 제한한다.
- 인형은 앞/뒤 두 층 이내로 배치하고 주요 실루엣이 서로 가려지지 않게 한다. 풍선은 약한 앞뒤 크기 차이를 주되 결과 카드·버튼과 겹치지 않는다.
- 설정의 ‘디자인’은 작은 실제 미리보기와 이름으로 제시한다. ‘다양하게’ 또는 개별 인형/풍선 형태, 무대 팔레트를 선택할 수 있게 한다. 처음 화면에 대형 디자인 상점을 펼치지 않는다.
- 개별 디자인 선택은 선택한 종류의 연출을 반복하는 사용자 선택이다. 기본값과 홍보 캡처는 다양한 구성을 사용한다.
- 디자인 변경은 다음 무대부터 적용하며 후보·기록·원본을 건드리지 않는다. 진행 중에는 디자인 변경을 비활성화하고 결과 완료 후 허용한다.
- 결과 공개가 끝난 뒤의 다음 무대 준비에서만 구성을 바꾼다. 공개된 인형·풍선과 이름표가 설정 변경 없이 갑자기 다른 종류로 바뀌지 않는다.
- 종류의 순환은 시각용 셔플백을 제안한다. 마지막 종류가 다음 첫 종류로 곧바로 반복되는 것을 가능하면 피하되 대상 추첨의 중복 제외와 완전히 분리한다.

### 9.3 자산 제작 절차

1. **공통 스타일 보드:** 기존 툴킷과 함께 6종 인형·6종 풍선의 실루엣/팔레트 계획을 나란히 비교한다. 기존 토끼는 질감 참고 후보일 뿐 모든 캐릭터의 원형이 아니다.
2. **인형 개별 생성:** 내장 ImageGen으로 인형별 독립 투명 배경 파일을 생성한다. 정면 또는 약한 3/4 각도, 광원 방향, 섬유 질감, 채도, 화면 내 점유율을 통일한다.
3. **형태별 검수:** 얼굴 비대칭·여분 팔다리·깨진 귀·과한 광택·텍스트 잔재·투명 가장자리 얼룩을 검수한다. 귀여움보다 형태 일관성과 가독성 저하 여부를 우선 판단한다.
4. **풍선 제작:** 형태별 코드 경로와 하이라이트·무늬 레이어를 준비한다. 필요 시 생성 시안으로 스타일을 탐색하되 최종 이동·충돌은 코드 경로와 연결한다. 6종 풍선을 모두 AI 이미지로 생성해야 한다는 의미는 아니다.
5. **배치·움직임 맞춤:** 각 인형 anchor와 각 풍선 hit 영역을 조정한다. 정지 이미지가 좋아도 집기/비행에서 부자연스러우면 다시 수정한다.
6. **배포 자산 정리:** 원본과 런타임 변환본을 분리하고 투명도 보존·크기 최적화·실제 로드 확인. 파일명·크기·종류·좌표·출처를 manifest로 관리한다.

생성 프롬프트는 공통 재질·광원·구도 조건 + 종별 형태 조건 + 금지 요소로 구성한다. 같은 무대에 사진 같은 인형과 평면 스티커 인형을 뒤섞지 않는다. 색상 변경만으로 종 수를 채우지 않는다. 사용자 명단을 프롬프트에 사용하지 않는다.

### 9.4 자산 계약과 통과 조건

제안 manifest 필드: `id`, `kind`, `src`, `width`, `height`, `anchors`, `bounds`, `motionProfile`, `palette`, `preloadGroup`. 풍선은 여기에 `shapePath`, `hitRegion`, `knotAnchor`를 둔다. 후보 ID나 이름은 manifest에 포함하지 않는다.

- 선택 모드의 필수 자산만 미리 읽고 decode 완료 후 ready로 전환한다. 다른 모드의 대용량 원본을 시작부터 모두 메모리에 올리지 않는다.
- 64/96/160px 크기 및 밝은 바탕에서 실루엣·투명 가장자리를 확인한다. 640px 창과 전체화면에서 동일 장면 비교.
- 인형 6종 각각 집기·들기·배출을 최소 3회 재생하고 풍선 6종 각각 비행·충돌·결과를 최소 3회 재생한다. 한 종류만 확인하고 공통 통과로 처리하지 않는다.
- 종류별 움직임의 진폭은 작게 유지한다. 큰 튀기·반짝이·상시 파티클로 차이를 대신하지 않는다.
- 필수 자산 로딩 실패 시 깨진 이미지로 추첨을 시작하지 않는다. 재시도와 클래식 전환을 제공한다. 진행 중 실패는 확정된 결과의 간단 공개로 복구한다.

## 10. 학급 변경·저장·실패 처리

- 열린 뽑기 창의 학급은 고정한다. 명단 창에서 기본 학급을 바꿔도 열린 도구가 자동으로 다른 학급으로 바뀌지 않는다.
- 대기 중 학급 변경 알림을 받으면 최신 후보를 갱신한다. 추가 학생은 참여 가능, 삭제 학생은 다음 추첨에서 제외한다.
- 연출 중 개명·삭제·성별 변경은 진행 중 결과를 바꾸지 않는다. 완료 결과는 추첨 시작 당시 이름으로 표시하고, 다음 추첨부터 최신 명단을 사용한다. 변경이 있었다는 짧은 안내를 표시한다.
- 학급 자체가 삭제되면 진행 중 결과까지 공개한 뒤 추가 추첨을 차단하고 학급 선택 또는 직접 입력으로 안내한다.
- 명단 읽기·갱신 실패 시 오래된 후보로 조용히 계속 뽑지 않는다. 새 추첨을 비활성화하고 재시도 제공. 이미 확정한 결과는 유지한다.
- 목록 영속화를 채택하면 타이머 preferences와 별도 버전 있는 저장소를 사용한다. 저장 실패는 명확히 표시하고 입력을 메모리에 유지한다. 손상·미지원 버전 파일을 빈 목록으로 덮어쓰지 않는다.
- 학생 이름·직접 목록·결과를 분석 이벤트, 일반 로그, 오류 수집, 이미지 생성 프롬프트에 보내지 않는다.

### 10.1 데이터 수명표

| 데이터 | 보관 위치 제안 | 초기화·변경 조건 |
| --- | --- | --- |
| 학급·학생 원본 | 기존 학급 DB | 뽑기는 읽기 전용 |
| 확정 진행 결과·완료 기록·일시 제외 | 창 메모리, sourceKey별 | 창 닫기/앱 종료. 완료 기록만 다시 시작으로 초기화 가능 |
| 직접 입력 적용 목록·편집 초안 | 창 메모리 | 창 닫기. 영속 저장 채택 시 저장본은 별도 |
| 직접 목록 저장본 | 정책 확정 후 별도 저장소 | 명시적 저장/삭제. 결과·제외 집합 포함 금지 |
| 효과음·연출 줄이기 | 버전 있는 뽑기 설정 | 사용자 설정 변경 |
| 디자인·무대 배치·시각 셔플백 | 창 메모리 | 새 창 또는 디자인 변경. 결과 확률과 무관 |

### 10.2 갱신·실패 순서

- 명단 구독 후 초기 읽기를 수행하고 revision으로 오래된 응답을 무시한다. 학급 선택을 바꿨다면 이전 요청의 늦은 응답도 버린다.
- 외부 갱신이 연출 중 도착하면 다음 후보용 최신 원본으로 보관한다. 진행 결과 스냅샷과 섞지 않고 완료 후 후보를 재계산한다.
- 갱신 실패는 조용히 삼키지 않도록 뽑기 소비 계층에서 상태를 노출한다. 기존 context의 오류 처리 방식을 실제 구현 전에 확인하고 필요한 범위만 확장한다.
- 저장을 채택하면 `목록 저장 중 / 저장됨 / 저장 실패·다시 시도`를 구분한다. 저장 완료 전 성공 표시 금지. 재시도는 같은 목록 ID를 사용해 복제 목록을 만들지 않는다.
- 저장 목록 삭제는 메모리의 현재 추첨 세션까지 자동 소거하지 않는다. ‘저장본 삭제, 현재 사용 중인 목록은 창을 닫을 때까지 유지’처럼 효과를 명시한다. 세부 UX는 저장 정책 채택 시 확정한다.

## 11. 접근성·음향·창 동작

- Tab으로 모든 제어에 접근하고 명확한 포커스 표시 제공. 기본 버튼의 Enter/Space 작동 보장.
- 전역 Space 추첨은 입력·텍스트 영역·선택기·대화상자·한글 조합 중에는 실행하지 않는다. 버튼 자체의 기본 클릭과 중복 실행하지 않는다.
- 결과는 한 번만 live region으로 안내한다. 움직이는 중간 상태를 연속 낭독하지 않는다. 색만으로 선택·제외를 구분하지 않는다.
- 효과음은 이동·충돌·결과에 맞춰 짧게 사용한다. 무음에서도 진행과 결과를 이해할 수 있어야 한다. 재생 실패가 추첨을 막지 않는다.
- 음원은 출처·라이선스·가공 내역을 기록한다. 기존 타이머 음원을 임의 교체하지 않는다.
- 창별 항상 위 기본 OFF 제안. 크기 조절·최소화·전체화면·ESC 복귀·닫기·본창 및 트레이 종료를 실제 Tauri에서 확인한다.
- 긴 이름과 목록을 무조건 잘라 표시하지 않는다. 결과는 두 줄까지 허용하고 단계적으로 크기를 조절한다. 최장 항목도 전체 내용을 읽을 수 있게 한다.

### 11.1 키보드·포커스 계획

- 모드 탭은 방향키·Home/End로 이동, 선택 버튼은 Enter/Space로 실행한다. 실제 탭 역할과 이동 패턴을 일치시킨다.
- 대화상자는 포커스를 내부에 유지하고 ESC로 닫은 후 호출 버튼으로 돌린다. ESC 우선순위는 가장 위 대화상자/패널 → 전체화면 복귀이며 진행 결과 취소는 하지 않는다.
- 진행 중 버튼은 비활성 이유를 근처 상태 문구로 제공한다. 완료 후 기존 뽑기 버튼 위치를 유지하되 이름 입력창 등 다른 작업으로 포커스를 강제로 빼앗지 않는다.
- 결과 낭독은 ‘8번 예시학생, 남은 20명’처럼 한 번만 전달한다. 과거 이력 펼침은 새 당첨으로 낭독하지 않는다.
- 글자 크기 200%와 OS 동작 줄이기에서 조작 가능 여부를 확인한다. 파스텔 바탕 위 작은 회색 글씨의 대비를 실제 측정한다.

### 11.2 음향 설계 계획

| 모드 | 음향 이벤트 | 제한 |
| --- | --- | --- |
| 클래식 | 짧은 결과 알림 1회 | 빠른 반복 시 이전 잔향을 정리, 소리 중첩 제한 |
| 인형 | 이동의 낮은 기계음·집기 접촉·배출 결과음 | 이동 루프는 해당 구간에서만 재생하고 모드 변경 시 중지 |
| 풍선 | 짧은 비행음·부드러운 파열음·결과음 | 날카로운 폭발음·놀라게 하는 음량 변화 금지 |
| 섞기 | 짧은 재배치 소리 선택 적용 | 결과음과 혼동하지 않음 |

음소거는 진행 중에도 즉시 적용하고, 다시 켜면 다음 이벤트부터 재생한다. 결과음 이벤트는 실행 ID·단계 ID로 중복 방지한다. 원본 음량을 그대로 섞지 않고 지각 음량과 피크를 정리하며 출처 및 가공 설정을 기록한다. 음향 선택을 기다리는 동안 기존 타이머 음원 작업을 바꾸지 않는다.

### 12.2 통합 회귀 계획

- 프런트/네이티브 양쪽 도구 ID 허용 목록과 schemaVersion 마이그레이션을 함께 설계한다. 구설정 사용자의 기존 숨김 도구·배치·음향값을 보존하면서 새 도구 기본 노출만 추가한다.
- 새 창 역할이 타이머로 잘못 분기되지 않도록 `main.js`부터 네이티브 생성까지 확인한다. 앱 종료 판단에 새 작업창을 포함한다.
- 툴바 크기 계산은 기존 방식에 새 도구를 포함시켜 재측정한다. 가로/세로와 플랫폼 버튼 포함 시 화면 경계 안 배치를 검증한다.
- 공통 CSS는 가능한 수정하지 않고 뽑기 전용 클래스로 제한한다. 공통 제어 수정이 필요하면 타이머·명단·알림장 화면을 함께 확인한다.

## 13. 검증 및 완료 기준

| 영역 | 반드시 확인할 사례 |
| --- | --- |
| 추첨 로직 | 0·1·500개 후보, 모두 일시 제외, 후보 소진, 동명이인, 편향 없는 정수 경계·rejection 경로, 섞기 후 누락·중복 없음 |
| 상태 | 연타·키 반복, 모드 전환 유지, 전체↔성별 공유 제외, 학급 전환 후 복귀, 중복 OFF→ON, 직전 취소와 동일 대상의 이전 결과, 초기화 범위 |
| 명단 | 로딩 실패·재시도, 추첨 중 추가/개명/삭제/성별 변경, 학급 삭제, 원본 불변 |
| 직접 목록 | 빈 줄·긴 항목·동일 이름·한글 입력·500개·초과 입력, 모둠/일반 목록 구분, 편집 시 ID 유지 |
| 연출 | 집게와 인형 접점·상승·배출 연결, 다트 실제 충돌, 결과와 시각 연출 일치, 섞기 중 연타, 리사이즈 중 위치, 배경 복귀 후 단일 완료 |
| 접근성 | 키보드 전체 흐름, 포커스 유지, 결과 1회 낭독, reduced motion, 무음, 긴 이름 |

| 회귀 | 타이머·명단·알림장 진입, 툴바 가로/세로·접힘·노출 변경, 구설정 마이그레이션 |
| 네이티브 | 창 재사용, 항상 위, 크기 조절, 전체화면 복귀, 닫기 후 세션 초기화, 본창/트레이 종료, 다중 모니터 |

- 난수 검증은 주입 가능한 난수 원천으로 경계와 균등 알고리즘을 확인한다. 불안정한 통계 테스트 하나로 공정성을 증명했다고 주장하지 않는다.
- 연출은 정지 캡처만으로 통과시키지 않는다. 단계별 캡처와 실제 재생 관찰을 함께 수행하고, 가능하면 짧은 동영상 증거를 남긴다.
- 일반 교실 규모 20~40명에서 반복 추첨하고 최대 500개에서도 후보를 생략하지 않는다. 30회 이상 반복 후 타이머·오디오·이벤트 누적과 UI 응답 저하를 확인한다.
- 애니메이션은 transform·opacity 중심으로 구현하고 지속적인 전체 화면 재배치를 피한다. FPS·프레임 지연은 검수 장비에서 측정해 기록한다. 60fps는 목표이며 실측 전 보장하지 않는다.
- 각 단계 결과는 단위 테스트·빌드·브라우저·네이티브 실기기 검증으로 구분해 보고한다. 미검증 항목은 완료로 표시하지 않는다.

### 13.2 품질 통과와 검수 산출물

- 로직: 결정적 fixture로 후보·결과·취소를 검증하고 성별/학급/목록 경계 누출 0건. 단순 화면 존재 검사만으로 통과하지 않는다.
- 디자인: 6종씩 contact sheet와 혼합 무대 캡처를 남긴다. 실루엣이 다른지, 같은 재질 계열인지, 결과 글씨가 가장 먼저 읽히는지 점검한다.
- 움직임: 각 종류 3회 이상, 대표 장면은 실제 동영상 또는 단계별 캡처+관찰 기록을 남긴다. 최소/기본 창 크기 모두 확인한다.
- 성능: 장비·브라우저/WebView·해상도·배율을 기록하고 30회 반복 전후 프레임 시간과 활성 타이머/오디오 자원을 비교한다. 기능상 멈춤·누적 루프가 있으면 통과 불가.
- 네이티브: 브라우저 검증과 별도 체크리스트 작성. mixed DPI/다중 모니터 장비가 없으면 미검증으로 명시한다.
- 산출물 제안: `docs/QA-classroom-picker.md`, `output/qa/picker/`의 로직·브라우저·네이티브 결과 및 이미지/움직임 증거. 이번 문서 작업에서는 생성하지 않는다.

## 14. 구현 순서 제안

1. PRD 검토, 직접 입력 목록 보관 정책·모드 이름 확인.
2. 공통 추첨 상태·대상 관리·클래식 흐름을 구현하고 핵심 상태 테스트.
3. 인형·풍선의 실제 움직임 프로토타입을 만들고 타이밍·접점·결과 공개를 검수.
4. 선택된 이미지·음원 적용, 창·툴킷 연결, 접근성·실패 처리 완성.
5. 브라우저 및 네이티브 검증, 문서·자산 출처·남은 제한 기록.

지금은 1단계의 문서 작성까지만 수행한다. 이미지 한 점은 앞서 생성한 시안이며 기능 구현 또는 최종 디자인 확정으로 보지 않는다.

## 15. 참고와 벤치마킹의 범위

- [Random.js 원본 저장소](https://github.com/ckknight/random-js): 균등 정수 분포·브라우저 난수·shuffle API를 검토하는 참고 자료. 라이브러리 도입이나 코드 복사를 확정한 것이 아니다.
- 제공 경로 `public/sample/select/personal/`: 대상 선택 등 기능 참고용. 시각 디자인·색·배치·캐릭터를 모방하지 않는다.
- 현재 툴킷 구현과 인계서: 창·밝은 외형·명단 데이터 계약의 기준.
- motion-design 스킬: 준비→동작→결과, 감속·관성·보조 움직임 설계에 참고. 실제 추첨 상태와 연출 타임라인은 분리한다.
- imagegen 스킬: 내장 생성 도구로 투명 배경 인형 시안 제작. 최종 에셋 채택 전 투명도와 축소 품질을 실제로 확인한다.

### 15.1 외부 로직 채택 절차

구현 단계에서 후보 라이브러리/원본의 버전·라이선스·난수 방식·테스트 범위를 확인한다. 설명이 비슷하다는 이유로 검증된 구현이라고 단정하지 않는다. 필요한 원칙만 자체 구현하면 경계 테스트를 함께 작성하고, 코드를 가져오면 라이선스·출처를 기록한다. 커뮤니티 게시물은 사례 탐색에만 쓰고 알고리즘 근거는 원본 문서·저장소로 확인한다.
