## 1. 먼저 확인된 사실 (진단의 근거)

진단 전에 라이브러리 원본 코드를 직접 열어 동작을 확인했습니다. 아래 사실이 여러 버그의 뿌리입니다.

### 1-1. 모든 창은 Rust 쪽 스토어 **메모리 1개**를 함께 씁니다
`tauri-plugin-store-2.4.2/src/store.rs`의 `build_inner()`는 같은 파일 경로면 이미 만들어 둔 스토어를 그대로 돌려줍니다.
→ 창마다 `new LazyStore(...)`를 만들어도 **실제 데이터는 하나**입니다. 다른 창이 `set()`한 값은 즉시 모든 창에 보입니다.

### 1-2. `reload()`는 "디스크 내용으로 메모리를 덮어쓰기"입니다
`store.rs`의 `load()`는 `self.cache.extend(디스크 내용)`입니다.
→ 다른 창이 `set()`만 하고 아직 파일에 쓰지 못한 값은 **옛 값으로 되돌아가고**, 메모리에서 지운 키는 **되살아납니다**.
→ 1-1 때문에 창 사이 최신화 목적의 `reload()`는 **애초에 필요가 없고 해롭기만** 합니다.
(`appState` 주석에도 같은 이유로 `reload()`를 뺐다고 적혀 있는데, 다른 곳에는 아직 남아 있습니다.)

### 1-3. 스토어는 디스크 읽기 실패를 **조용히 무시**합니다
`build_inner()`의 `let _ = store_inner.load();` — 읽기 오류(파일 잠김, JSON 손상)를 버리고 **빈 스토어**를 만듭니다.
→ `appState._ensureStoreLoaded()`는 `keys()` 성공 여부로 "읽기 성공"을 판단하는데, 이 호출은 빈 스토어에서도 성공합니다.
→ 즉 **"부팅 직후 읽기 실패 시 저장을 잠근다"는 보호 장치가 실제로는 작동할 수 없습니다.** (자세한 내용은 🔴 B6)

### 1-4. 스토어 파일 쓰기는 "원자적 쓰기"가 아닙니다
`save()`는 `fs::write` 한 번입니다(파일을 비운 뒤 새로 씀). 쓰는 도중 전원이 꺼지면 파일이 반쯤 잘릴 수 있고, 1-3 때문에 다음 실행에서 빈 데이터로 시작합니다.

## 2. 🔴 치명/높음 버그

각 항목은 **증상 → 원인(파일:줄) → 수정안 → 위험도 → 검증 방법** 순서입니다.

### B1. 🔔 리마인더 버튼 하나로 **모든 창의 테마·글꼴·본문이 바뀜**
- **증상**: 어느 창에서든 툴바의 종(🔔) 버튼을 누르면, 다른 모든 창(Tiny Note 포함)의 테마 색·다크 모드·글자 크기·"마감된 일/메모 표시"가 누른 창의 설정으로 바뀝니다. 기본 글꼴이 다르면 **다른 창 본문 HTML의 글꼴까지 다시 써서 저장**합니다.
- **원인**:
  - `src/components/MainToolbar.svelte:606-612` — `takeSnapshot()`에 `targetWindow`가 없는 채로 **전체 방송**(`emit`)
  - `src/App.svelte:964` — `if (s.targetWindow && …)` 조건이라 `targetWindow`가 없으면 **모든 창이 "나에게 온 설정"으로 처리**
  - `src/App.svelte:1009-1011` — 글꼴이 다르면 `applyFontToAllText()`로 본문을 다시 씀
- **수정안**: 버튼 payload에 `targetWindow: appState.windowLabel`을 추가 (한 줄). 다른 창은 기존의 "매니저 전용 리마인더 켜기/끄기" 분기만 탑니다.
- **위험도**: 매우 낮음 (설정 창의 "적용" 버튼이 이미 쓰는 경로와 똑같아집니다)
- **검증**: 창 2개에 서로 다른 테마 → 한쪽에서 🔔 클릭 → 다른 창 테마·본문 그대로인지, 리마인더 켜짐/꺼짐만 전역 반영되는지 확인

### B2. ⏰ "1시간 뒤 / 직접 시간 지정 / 오늘은 그만" 미루기가 **바로 풀림**
- **증상**: 리마인더 팝업에서 미루기를 눌러도, 곧바로 미루기 시간이 0으로 초기화됩니다. 다른 메모 창에서 글을 쓰거나 창을 옮기기만 해도 풀립니다.
- **원인** (두 갈래):
  1. `src/lib/appState.svelte.js:539-542` — 매니저가 `req-reminder-sync`를 받으면 `reminderSuppressUntil = 0`으로 **무조건 초기화**
  2. 이 이벤트는 **매니저가 아닌 창이 저장할 때마다** 보내집니다 (`appState.svelte.js:1430-1431`). 게다가 `src/App.svelte:873-875`의 닫기 처리기가 `settings`만 빼고 **리마인더·환영·우클릭메뉴 창에서도 저장을 실행**합니다. 그래서 미루기 버튼 → 리마인더 창이 닫히며 저장 → 이벤트 발송 → 미루기 초기화, 순서로 **즉시** 풀립니다.
- **수정안**:
  - 닫기 처리기에서 데이터 창(`main`/`note-*`/`tinynote-*`)만 저장하도록 제한 (`isDataWindow()` 함수가 이미 있음)
  - `_writeToDisk()` 입구에서도 데이터 창이 아니면 쓰지 않음 (이중 방어)
  - `req-reminder-sync` 처리기에서 `reminderSuppressUntil = 0` 줄 제거 → **사용자 결정 필요 (Q2)**
- **위험도**: 낮음
- **검증**: 팝업에서 "1시간 뒤" → 다른 창에서 입력·이동 → 팝업이 다시 뜨지 않는지, 앱 재시작 후에도 미루기 시각이 유지되는지

### B3. 🗑️ `reload()` 호출로 **다른 창이 막 저장한 내용이 되돌려질 수 있음**
- **증상**: 드물지만 아카이브 창을 열거나, Tiny Note를 보관하거나, 매니저 창이 닫히는 순간 다른 창의 마지막 입력이 디스크에서 사라질 수 있습니다. 특히 **창을 닫는 순간**에 겹치면 영구 유실입니다.
- **원인** (1-2 참고): `reload()` 호출 위치
  - `src/lib/appState.svelte.js:453` (매니저 승계)
  - `src/lib/archiveStore.svelte.js:34, 116, 147, 265` (초기화·수정·새로고침·꺼내기)
- **수정안**: 다섯 곳 모두 `reload()` 제거. 1-1에 따라 `get()`만으로 항상 최신값을 읽습니다.
- **위험도**: 매우 낮음 (외부 프로그램이 설정 파일을 직접 고치는 경우만 차이가 있고, 이 앱에는 그런 경로가 없습니다)
- **검증**: 아카이브 창을 연 채로 Tiny Note 여러 개에서 입력·보관 → 모든 내용 유지 확인

### B4. 👑 매니저 승계가 **실패하거나 매니저가 2개가 됨**
- **증상**:
  - `main`을 닫았을 때, 번호가 가장 작은 메모 창이 **닫혀 있으면**(데이터만 있고 화면에 없음) 아무도 매니저가 되지 않습니다 → **리마인더와 업데이트 확인이 조용히 멈춤**
  - Tiny Note만 남으면 역시 매니저가 없습니다
  - 승계한 창은 **1시간마다 도는 리마인더 점검 타이머가 없습니다** (1회만 실행)
  - 트레이에서 "열기"로 `main`을 다시 띄우면 `main`도 매니저가 되어 **매니저 2개** → 리마인더 중복, 업데이트 중복 확인
- **원인**:
  - `appState.svelte.js:454-468` — 후보를 "현재 열린 창"이 아니라 **저장 명부(`activeExtraWindows`, 닫힌 창 포함)**에서 고르고, `note-*`만 봄
  - `appState.svelte.js:469-475` vs `478-483` — 승계 경로에 `setInterval` 누락
  - `appState.svelte.js:445-447` — `main`이면 무조건 매니저
- **수정안**: 매니저 선출 로직을 한 함수로 모음
  - 후보 = **실제로 열려 있는** 데이터 창 (`main` → `note-1..10` → `tinynote-1..10` 순)
  - 승계·최초 기동이 **같은 시작 함수**(리스너 + 3초 뒤 점검 + 1시간 주기 + 업데이트 일정)를 호출
  - 새 `main`이 뜨면 `manager-reclaim` 이벤트로 기존 매니저가 권한과 타이머를 내려놓음
- **위험도**: 중간 (핵심 규칙 "매니저 권한 승계"를 건드리므로 시나리오 테스트 필수)
- **검증**: ① main 닫기 → 열린 note-3이 매니저가 되는지 ② note-1은 닫혀 있고 note-2만 열린 상태 ③ Tiny Note만 남은 상태 ④ 트레이 "열기"로 main 복귀 시 매니저 1개인지(콘솔 로그로 확인)

### B5. 📦 Tiny Note 보관 실패 시에도 **내용을 지우고 창을 닫음**
- **증상**: 저장소 오류로 보관이 실패해도 "안전하게 넣었어요" 표시 후 본문을 비우고 창을 닫습니다 → **데이터 유실**
- **원인**:
  - `src/lib/archiveStore.svelte.js:126-128` — `_safeModify()`가 오류를 삼키고 결과를 알려 주지 않음
  - `archiveStore.svelte.js:177` — `addNote()`가 **항상 `true`** 반환
  - 그래서 `src/components/StickerWindow.svelte:427`의 `if (!saved)` 방어가 **절대 실행되지 않음**
  - 추가로 Tiny Note 두 개를 거의 동시에 보관하면, 서로 옛 목록을 읽고 덮어써 **한쪽 보관본이 사라질 수 있음**(창마다 따로 도는 작업이라 줄 세우기가 안 됨)

  - `addNote()`는 저장 후 **다시 읽어서 새 메모가 실제로 있는지 확인**(최대 3회 재시도)한 뒤에만 `true`

- **검증**: 정상 보관 확인 + Tiny Note 2개에서 연속 보관 후 아카이브에 2개 모두 있는지

## 6. 🧱 클린 아키텍처 분리 계획 (기능 훼손 없는 이전)

### 원칙
1. **겉모습(공개 API)은 그대로**: 컴포넌트가 부르는 `appState.xxx()` 이름과 동작을 **하나도 바꾸지 않습니다.** `AppState`는 "안내 창구(facade)"로 남고, 속 로직만 모듈로 옮깁니다.
2. **순수 로직 먼저 분리 → 테스트 추가 → 연결** 순서로 옮겨, 옮기기 전후 결과가 같은지 테스트로 증명합니다.
3. 한 단계마다 `npm test` + `vite build` + 수동 시나리오 확인 후 다음 단계로 갑니다.

### 제안 구조
```

├─ appState.svelte.js          ← 안내 창구(facade). 상태($state)와 공개 메서드 이름 유지
```

## 8. 이미 잘 되어 있어 **건드리지 않을** 부분

- 창 내부 쓰기 큐(`enqueueWrite`)와 본문/설정 타이머 분리 — 창 **안**의 경합은 잘 막고 있음
- `flushPendingSaves()`를 이용한 닫기·포커스 이탈·`pagehide` 시 마지막 입력 보존
- `editable.js`의 한글 IME(조합형 입력) 보호, 붙여넣기 시 서식 제거, DOMPurify 정제
- `dragRegion.js`의 더블클릭 최대화 경합 제거
- 창 크기 화면 안 가두기(`clampSizeToScreen`, `clampTinyNoteSize`), 스플리터 점프 방지
- Tiny Note 전체화면/롤업 단일 상태 머신
- 업데이트 확인의 매니저 단일 호출·요청자 명단·릴레이 타임아웃 (단, B4의 승계 문제만 연동 수정)

## 11. 작업 순서 제안 (확정 전 초안)

각 단계는 **작은 커밋 1개** 단위로 진행하고, 단계마다 아래 "검증 게이트"를 통과해야 다음으로 넘어갑니다.

| 단계 | 내용 | 포함 항목 | 위험도 |
|---|---|---|---|
| 0 | 버전 5.0.2 | 9장 | 매우 낮음 |
| 1 | 한 줄~수십 줄짜리 확실한 버그 수정 | B1, B2, B3, M2, M3, M8 | 낮음 |
| 2 | 아카이브 안정화 | B5, M5, M6 | 낮음 |
| 3 | 매니저·창 관리 재정비 | B4, M4, M1, L1, L2 (+A2, 매니저 선출 모듈) | 중간 |
| 4 | 데이터 안전장치 (Q4 승인 시) | B6 | 중간 |
| 5 | 성능 개선 | P1~P8 | 낮음 |
| 6 | 구조 분리 (facade 유지) + 순수 모듈 단위 테스트 추가 | A1, A3~A6 | 중간 |
| 7 | 유령 코드·의존성·파일 정리 | G1~G17 | 낮음 |

### 검증 게이트 (매 단계 공통)
1. `npm test` — 기존 73개 + 새로 추가한 테스트 전부 통과
2. `npx vite build` — 성공, 새 경고 없음
3. `cargo check` (`src-tauri` 폴더) — Rust를 건드린 단계에서만
4. 수동 시나리오 (단계별 해당 항목):
   - 창 여러 개(main·note·Tiny Note) 열고 입력 → 앱 종료 → 재실행 시 전부 복원
   - 테마·글꼴 설정 적용 → 다른 창에 영향 없음
   - 리마인더 표시·미루기·"오늘은 그만"·항목 마감
   - main 닫기 → 승계 → 트레이 메뉴 동작
   - Tiny Note 롤업·전체화면·보관·꺼내기
   - 드래그 정렬, 되돌리기/다시 실행, TXT 내보내기/가져오기
   - 업데이트 확인(설정 창의 "확인" 버튼)

### 새로 추가할 단위 테스트 (순수 함수 대상)
- `hasWindowContent()` — 빈 HTML(`<div><br></div>`, `&nbsp;`) 판정
- `collectImminentTodos()` — D-3 경계, 날짜 오류 값, 창 간 같은 ID 처리
- `txtPorter` — 내보내기 → 가져오기 왕복 시 내용·마감일 보존
- 매니저 후보 선출 순서 — main 없음 / note 일부만 열림 / Tiny Note만 남음
- 저장 키 목록 — `init`/`_writeToDisk`/`takeSnapshot` 목록이 서로 어긋나지 않는지 (규칙 2 자동 점검)
