# 알림장 PRD — 작성·기록·화이트보드

작성일: 2026-09-21 · 대상: Tidy Task Local 학급 툴킷 · 상태: 구현 및 자동 검증 완료, 네이티브 수동 검증 대기. 실제 검증 범위는 [QA-classroom-noticeboard.md](QA-classroom-noticeboard.md) 참조.

상세 작업 트리: [PLAN-classroom-noticeboard.md](PLAN-classroom-noticeboard.md)

## 1. 목적과 문서의 권한

교사가 날짜별 알림장을 작성·저장하고, 학생들이 교실에서 쉽게 받아 적을 수 있는 화이트보드 화면으로 보여준다. 작성 내용의 유실 방지와 한글·서식·실행 취소의 일관성을 핵심 품질로 삼는다.

이 문서는 사용자 인터뷰의 확정 요구와 이를 실현할 설계 결정을 구분한다. 현재 요청은 PRD와 상세 계획 작성이다. 이 문서의 작업 지시는 후속 구현용이며, 문서 작성과 제품 구현 완료를 혼동하지 않는다.

- 최신 사용자 답변이 [HANDOFF](HANDOFF-classroom-toolkit-next-development.md)의 권장 개발 순서보다 우선한다.
- 첨부 화면은 기능 참고 자료다. 베이지 질감·갈색 장식·초록 칠판 디자인은 채택하지 않는다.
- 알림장의 ‘판서 모드’는 텍스트 기반 화이트보드 표시/편집이다. HANDOFF의 별도 자유 판서 도구와 다르다.
- 새로운 명단·플랫폼·타이머 작업이 현재 작업 폴더에 존재한다. 이를 되돌리거나 본 기능의 일부로 재작성하지 않는다.
- 안정성은 테스트와 실패 처리로 검증한다. 비정상 강제 종료 직전의 미보관 입력까지 무조건 복구한다고 약속하지 않는다.

### 2.1 구현자가 정하는 기본 정책

아래는 사용자에게 재질문할 필요 없는 설계 기본값이다. 시각 검수에서 수치를 조정하면 이 문서와 계획을 함께 갱신한다. 사용자 확정 사항으로 소급 표기하지 않는다.

- 현재 PC의 앱 자료 전체에서 날짜별 한 장. 명단의 학급 선택과 연동하거나 학급별 알림장으로 확장하지 않는다.
- 알림장 창은 하나를 재사용한다. 툴킷 재클릭은 현재 날짜/입력 상태를 유지한 채 기존 창을 앞으로 가져온다.
- 창을 새로 열거나 앱을 재시작하면 오늘 날짜·일반 모드로 시작한다. 과거 날짜의 초안은 목록에서 접근한다.
- 글꼴은 문서 전체에 적용한다. 크기·색·강조는 선택 구간 또는 이후 입력에 적용한다.
- 본문 기본 크기 22px, 조절 8~96px, 증감 1px. 일반 배율 100%, 화이트보드 배율 200%, 모드별 배율 50~300%/10% 단위로 시작한다.
- 글꼴은 새 문서 생성 시 Tidy 본문 설정을 우선하고, 불가하면 Tidy 기본 글꼴로 결정한다. 이후 본 앱 글꼴 변경이 기존 문서까지 바꾸지는 않는다.
- 같은 알림장 안에서 복사한 지원 서식은 보존한다. 외부 및 기존 Tidy 메모에서 붙여넣는 내용은 일반 텍스트로 처리한다.
- 편집 이력은 창 세션 동안 날짜별 유지한다. 저장/모드 전환으로 지우지 않으며 앱 재실행 후에는 복원하지 않는다.
- 날짜 키는 로컬 달력의 YYYY-MM-DD, 이번 주는 월~일, 이번 달은 달력 월, 시간 필터 기준은 PC의 오늘이다.
- 자동 초안 보관은 한글 조합 완료 후 500ms 대기, 연속 입력 중에도 조합 밖에서는 최대 2초 간격을 목표로 한다. 디스크 응답 전 성공 표시는 하지 않는다.

## 3. 범위

### 포함

날짜 탐색, 텍스트와 지정 서식, 초안/저장본, 기록 검색, 화이트보드, 전체화면, 단축키, 휴지통, 저장 실패/복구 안내, 독립 창과 앱 종료 연동.

### 제외

학급 시간표, 펜·지우개·자유 판서·화면 오버레이, 문단별 따라 적기, 듀얼 모니터의 교사/학생 별도 창, 이미지/표/첨부, 인쇄·이미지 내보내기, 템플릿·상용구, 자동 번호 목록, 다른 날짜로 복제, 클라우드·배포·학부모 전송, 사용자용 저장 버전 이력, 알림장 전용 새 글꼴 설치.

번호는 ‘1. 준비물’처럼 직접 입력할 수 있다. 제외 기능의 빈 버튼이나 준비 중 메뉴를 노출하지 않는다. 로컬 DB 복구용 내부 사본은 사용자용 저장 이력 기능과 구별한다.

## 4. 정보 구조와 화면

```text
학급 툴킷
└─ 알림장: 단일 독립 창
   ├─ 일반 모드
   │  ├─ 창 조작: 이동 / 항상 위 / 최소화 / 최대화 / 닫기
   │  ├─ 날짜: 이전 / 날짜 선택 / 다음 / 오늘
   │  ├─ 작성: 서식 도구 / 본문 / 보관 상태 / 저장 / 화이트보드
   │  └─ 기록: 검색 / 기간 필터 / 날짜 목록 / 휴지통 진입
   ├─ 화이트보드 모드
   │  ├─ 선택 날짜
   │  ├─ 학생용 본문: 넓은 흰 면, 직접 편집, 세로 스크롤
   │  └─ 최소 조작: 도구 열기 / 저장 / 일반 화면으로
   │     └─ 펼친 도구: 서식 / 보기 배율 / 보관 상태
   └─ 휴지통
      ├─ 삭제한 날짜 목록 / 읽기 전용 내용 확인
      └─ 복원 / 같은 날짜 충돌 해결 / 영구 삭제
```

### 4.1 일반 모드

- Tidy 타이머의 밝은 화면, 둥근 패널, 민트 조작부, 간결한 창 상단을 따른다. 기존 타이머의 장식 계기판을 본문에 복제하지 않는다.
- 넓은 창에서는 작성 영역과 오른쪽 기록 영역을 나란히 배치한다. 좁은 창에서는 기록을 여닫는 패널로 전환하고 작성 폭을 보장한다.
- 첫 진입에서 오늘의 저장본/초안을 조회하는 동안 입력을 잠시 막고 로딩 상태를 표시한다. 읽기 실패를 빈 문서로 위장하지 않는다.
- 날짜 변경·검색 결과 선택도 같은 ‘현재 초안 보관 → 대상 열기’ 절차를 사용한다.
- 입력 중 검색/기간 필터 변경은 본문과 선택 날짜를 바꾸지 않는다. 현재 날짜가 필터에서 제외되어도 편집은 계속한다.
- 저장 버튼은 본문이 비어 있으면 비활성화하고 이유를 표시한다. 이미 저장본과 같다면 ‘저장됨’ 표시.
- 초안 자동 보관 완료는 ‘초안 보관됨’, 저장본 확정 성공은 ‘저장됨’으로 구별한다.

### 4.2 학생용 화이트보드

- 흰색 바탕, 어두운 기본 본문, 날짜와 내용의 명확한 위계. 과한 카드 경계·그림자·질감·장식 없음.
- 날짜는 상단 중앙에 작게 고정하되 본문보다 시선을 빼앗지 않는다. 선택된 날짜를 표시하며 항상 오늘로 표기하지 않는다.
- 본문은 왼쪽 정렬하고 충분한 좌우 여백, 기본 줄 높이 1.65, 문단 간 약 0.55em 여백을 둔다. 마지막 줄 아래에도 읽기 위한 여백을 둔다.
- 본문 영역은 화면 크기에 맞춰 넓어진다. 짧은 문서를 수직 중앙으로 띄우거나 긴 내용을 한 화면에 강제로 축소하지 않는다.
- 글자 크기를 상대 배율로 계산해 문장별 강조를 유지한다. 편집 DOM에 CSS transform만 걸어 스크롤/커서 좌표를 어긋나게 만들지 않는다.
- 처음 진입하면 글의 시작부터 보여준다. 기존 커서 위치로 자동 스크롤하여 학생이 첫 부분을 놓치지 않게 한다. 사용자가 본문을 클릭하면 그 위치에서 편집한다.
- 도구 패널은 본문을 밀지 않는 가장자리 레이어로 열고, 하단 본문은 고정 조작부에 가리지 않도록 여백을 확보한다.
- 도구는 사용자 클릭으로 열고 닫는다. 입력 중 자동 사라짐이나 마우스 호버 의존 동작 없음.
- 저장 실패는 도구가 접혀 있어도 짧은 상태와 재시도 동작을 보여준다. 상세 파일 오류는 학생용 본문 위에 길게 출력하지 않는다.
- 아래 내용이 실제로 남아 있을 때만 ‘아래에 내용이 더 있어요’ 표시. 끝에 도달하면 사라진다.
- 일반 모드로 복귀하면 해당 모드의 스크롤/선택 맥락을 복원한다. 삭제된 문장 위치는 유효한 가까운 위치로 보정한다.

## 5. 편집 기능 계약

| 기능 | 동작 | 예외/이력 |
| --- | --- | --- |
| 글꼴 | Tidy 내장+등록 글꼴 목록, 문서 전체 적용 | 사용자 글꼴을 독립 창에도 로드; 실패하면 대체 표시만 사용하고 저장 ID 유지; 문서 글꼴 변경은 취소 가능 |
| 글자 크기 | 선택한 구간에 지정 값 적용; 커서만 있으면 다음 입력 크기 설정 | 혼합 선택은 ‘혼합’; 숫자 직접 입력 또는 +/- 사용; Ctrl+A 후 변경으로 전체 적용 |
| 크기 입력 | 정수 8~96px, Enter/blur로 확정, Escape 취소 | 빈 값·NaN·범위 밖 값은 본문 변경 없이 안내; +/- 경계는 비활성화 |
| 굵게/기울임/취소선/밑줄 | 선택 구간 또는 다음 입력에 토글 | 전부 적용된 선택이면 해제, 일부만 적용된 선택이면 전체 적용; 혼합 상태 구별 |
| 글자색 | 읽기 쉬운 진한 기본 팔레트에서 선택 구간/다음 입력에 적용 | 기본색 복원 제공, 배경색 기능 없음; 기존 색을 모드 전환으로 바꾸지 않음 |
| 줄바꿈 | Enter는 문단, Shift+Enter는 문단 내 줄바꿈 | 자동 번호/자동 링크 변환 없음; 빈 줄 유지 |
| 붙여넣기 | 외부 text/plain 삽입, CRLF를 LF로 정규화 | 앞뒤 공백·빈 줄 임의 trim 금지; 이미지/파일 드롭 무시 및 짧은 안내 |
| 내부 복사 | 지원하는 텍스트/서식만 보존 | 검증된 내부 payload일 때만 허용; 실패하면 plain text로 폴백 |
| 실행 취소/재실행 | 입력·삭제·잘라내기·붙여넣기·서식 변경 | 저장·배율·모드·검색·날짜 이동·휴지통 작업은 본문 이력에 넣지 않음 |

혼합 크기 선택에서 +/-는 각 구간 크기를 1px씩 변화시켜 상대 차이를 유지한다. 숫자를 직접 입력하면 선택 전체가 같은 크기가 된다. 커서만 있을 때의 서식 변경은 다음 입력과 묶어 취소하고, 텍스트를 입력하지 않은 서식 대기 상태만으로 영속 초안을 만들지 않는다.

### 5.1 선택 영역과 한글

서식 버튼·팝오버로 포커스가 옮겨져도 논리적 선택 영역을 유지한다. 마우스 사용을 위해 키보드 접근을 차단하지 않는다. 날짜 전환 이후 이전 날짜의 선택 북마크로 서식을 적용하지 않는다.

한글 조합 도중 DOM 전체를 다시 쓰지 않는다. 조합 중 Ctrl+Z/Y는 입력기에 맡기고 자체 이력을 중복 실행하지 않는다. 저장·날짜 이동·닫기 요청은 조합 완료를 기다린 뒤 확정된 문서에 적용한다. 타임아웃으로 미완성 음절을 성공 저장했다고 표시하지 않는다.

### 5.2 단축키

- Ctrl+Z: 실행 취소. Ctrl+Y: 다시 실행. 툴바 버튼과 같은 명령을 사용한다.
- macOS 지원 검수에서는 Cmd+Z 및 Cmd+Shift+Z도 같은 동작으로 연결한다. Windows Ctrl+Shift+Z도 다시 실행 별칭으로 허용한다.
- 본문 또는 본문 서식 도구에 포커스가 있을 때만 알림장 이력에 적용한다. 검색·날짜·크기 숫자 입력칸에서는 그 입력칸의 기본 취소 동작을 유지한다.
- 연속 일반 입력은 최대 500ms 간격의 한 묶음, 붙여넣기·서식 변경·문단 나누기는 독립 묶음으로 시작한다. 실제 한글 묶음 경계는 네이티브 IME 검사로 확정한다.
- 취소 후 새 편집을 하면 redo 갈래는 폐기한다. 자동 보관·저장은 redo를 폐기하지 않는다.
- 날짜별 이력은 창 세션 동안 유지하고 날짜 전환 시 서로 합쳐지지 않는다. 앱 재시작/창 완전 종료 후 이력은 초기화한다.
- ESC는 조합 중에는 입력기 우선, 팝오버/대화상자가 열려 있으면 가장 위 레이어부터 닫고, 그 외 화이트보드에서는 일반 모드로 복귀한다.

## 6. 초안과 저장본

### 6.1 상태 정의

‘문서 상태’와 ‘디스크 보관 상태’를 별도로 관리한다. 초안 보관 완료가 저장본 확정을 뜻하지 않는다.

| 문서 상태 | 설명 | 다시 열 때 |
| --- | --- | --- |
| 빈 날짜 | 저장본 없고 본문 입력 이력 없음 | 빈 본문, 목록에는 없음 |
| 초안만 있음 | 한 번도 저장하지 않은 내용 | 초안 + ‘초안’ 표시 |
| 저장본과 동일 | 현재 내용/서식이 저장본과 같음 | 저장본 + ‘저장됨’ 표시 |
| 저장본 수정 중 | 현재 내용/서식이 저장본과 다름 | 초안 + ‘저장하지 않은 수정사항’ 표시 |
| 빈 수정 초안 | 기존 내용을 모두 지운 상태 | 빈 본문 + 초안 상태, 저장본 되돌리기 제공 |
| 휴지통 | 삭제된 저장본/초안 묶음 | 일반 목록 제외, 읽기 전용 미리보기 |

보관 상태는 별도로 대기/보관 중/보관됨/실패를 가진다. ‘초안이 없음’과 ‘빈 문서인 초안이 있음’을 데이터에서 구별한다. 저장본 없는 문서를 작성했다가 전부 지운 경우에도 빈 초안을 보관한다. 처음부터 빈 날짜와 구별해 자동 기록 증식을 막는다.

### 6.2 저장·복구 흐름

1. 편집은 메모리 문서를 먼저 갱신하고 해당 날짜/문서 세대에 초안 보관을 예약한다.
2. DB가 실제 반영한 버전까지만 ‘보관됨’으로 표시한다. 보관 도중 더 입력하면 최신 내용은 계속 대기 상태다.
3. 저장 버튼은 클릭 시점의 확정된 문서 버전을 저장한다. 동시에 새 입력이 발생하면 그 부분은 다음 초안으로 남는다.
4. 저장 성공 시 클릭 당시 내용은 저장본이 되고, 더 최신 초안이 있다면 이를 지우지 않는다.
5. 저장본으로 되돌리기는 변경 내용을 버릴지 확인한 뒤 수행한다. 같은 창에서는 하나의 편집 작업으로 취소 가능하다.
6. 마지막 저장본이 없는 초안에는 ‘저장본으로 되돌리기’를 제공하지 않는다.
7. 오류 시 입력 내용과 이력은 메모리에 유지하고 재시도 제공. 재시도가 같은 작업을 두 번 적용하지 않게 한다.

정상적인 날짜 이동·창 닫기·앱 종료는 마지막 조합 완료 입력까지 보관 확인 후 진행한다. 디스크 오류 중에는 자동으로 창을 파괴하거나 일정 시간 뒤 강제 종료하지 않는다. 프로세스 강제 종료/전원 차단은 마지막 디스크 반영 이후 입력이 유실될 수 있으며, 다음 실행에서는 마지막 정상 보관본을 복구한다.

### 6.3 빈 내용

공백·줄바꿈·제로폭 공백만 있는 문서는 저장 버튼 비활성화. 한글 자모·숫자·기호·이모지는 유효 내용이다. 문서 표시의 줄바꿈/공백은 보존하고, 빈 내용 판정만 별도 정규화한다. 빈 초안을 자동으로 저장본으로 승격하거나 기존 저장본 삭제로 해석하지 않는다.

## 7. 날짜·목록·검색

- 날짜 선택은 실제 달력 날짜만 허용한다. UTC 변환으로 날짜가 하루 밀리지 않게 로컬 날짜 연산을 사용한다.
- 이전/다음/오늘·달력·검색 결과 클릭은 공통 전환 절차 사용. 빠른 연속 요청에서는 가장 마지막 목적지만 열고, 이전 조회 응답이 뒤늦게 화면을 덮지 않게 한다.
- 자정·절전 복귀 시 오늘 강조와 기간 필터 범위는 갱신하되 작성 중 날짜는 유지한다.
- 목록은 날짜 내림차순, 최초 50개와 더 보기. 초안만 있는 날짜도 포함한다. ‘초안’, ‘수정 중’, ‘저장됨’은 색 외 텍스트로 표시한다.
- 저장된 날짜의 카드 미리보기는 저장본을 기준으로 한다. 수정 중인 초안에만 검색어가 있으면 ‘초안에서 찾음’과 해당 미리보기를 표시한다. 카드 클릭 시에는 항상 초안을 우선 복원한다.
- 검색은 저장본과 초안의 일반 텍스트 및 표시 날짜를 대상으로 한다. HTML 원문/스타일 문자열은 검색하지 않는다.
- YYYY-MM-DD, YYYY.MM.DD, YYYY/MM/DD 및 ‘9월 21일’ 형식을 검색용 날짜 표현으로 지원한다. 본문 검색은 유니코드 정규화·영문 대소문자 무시, 정규식 문법은 해석하지 않는다.
- 기간 필터와 검색은 교집합. 건수도 같은 조건으로 계산한다. 검색 응답은 최신 요청에만 반영한다.
- 알림장 없음/검색 결과 없음/불러오기 실패를 다른 상태로 표시한다. 휴지통 자료는 일반 검색에서 제외한다.

## 8. 삭제·휴지통

- 날짜별 삭제 확인에는 날짜, 저장본/초안 동시 이동, 복원 가능 여부를 명시한다.
- 현재 편집 중인 날짜를 삭제할 때 최신 초안을 먼저 보관한다. 실패하면 삭제하지 않는다.
- 휴지통 이동 성공 후 해당 날짜는 빈 작성 화면이 된다. 입력 전까지 새 빈 레코드를 만들지 않는다.
- 삭제 전의 지연 보관 요청이 실행되어 휴지통 문서를 다시 활성화하지 못하게 한다.
- 휴지통은 삭제 시각 내림차순, 날짜와 본문 미리보기 제공. 같은 날짜를 여러 번 삭제한 항목은 별개의 삭제 ID로 구별한다.
- 같은 날짜가 비어 있으면 원래 날짜로 복원한다. 저장본/초안 상태도 그대로 복원한다.
- 같은 날짜에 새 문서가 있으면 양쪽 내용을 읽기 전용으로 비교한다. ‘현재 알림장 유지’는 취소, ‘휴지통 알림장으로 복원’은 현재 문서를 휴지통으로 옮기고 선택 문서를 활성화하는 원자적 교체다. 어느 내용도 조용히 버리지 않는다.
- 영구 삭제는 개별 항목에만 제공하고 되돌릴 수 없음을 확인한다. 자동 삭제·일괄 비우기는 이번 범위에 없다.
- 영구 삭제는 앱에서 복구 불가를 의미한다. OS/디스크 수준의 보안 완전 삭제 기능을 뜻하지 않는다.

## 9. 실패·접근성·성능 기준

| 상황 | 요구 동작 |
| --- | --- |
| 읽기 실패/손상/상위 스키마 | 새 빈 DB로 덮어쓰지 않고 오류·재시도/복구 안내 |
| 디스크 쓰기 실패/잠금 | 편집 내용 유지, 성공 표시 금지, 전환·종료 중단, 재시도 |
| 응답 유실/중복 클릭 | 작업 ID로 중복 방지, 실제 반영 여부 확인 후 UI 갱신 |
| 오래된 버전으로 수정 | 충돌 표시, 최신 자료 확인 전 자동 덮어쓰기 금지 |
| 전체화면 API 실패 | 일반 모드 유지, 재시도 가능; 절반 전환 상태 방지 |
| 모니터 제거/배율 변경 | 보이는 화면 안으로 원래 창 복귀, 본문/커서 유지 |
| 과도하게 큰 입력 | 붙여넣기 전에 제한 안내, 기존 내용 유지, 조용히 잘라내기 금지 |

입력 설계 상한은 문서당 일반 텍스트 100,000 Unicode scalar, 구조화 JSON UTF-8 2MiB, 문단 5,000개로 시작한다. 기존 자료 읽기와 신규 입력 제한을 분리하고, 지원 불가 자료를 자동 축약하지 않는다. 성능 검수 기준은 10,000자/200문단 편집과 3,650일 기록 검색이다.

키보드만으로 날짜·서식·저장·목록·휴지통·화이트보드를 조작할 수 있어야 한다. 아이콘에는 이름, 토글에는 상태, 대화상자에는 초점 복귀를 제공한다. 자동 보관 알림을 매 입력마다 스크린리더로 읽지 않는다. 기본 글자/팔레트는 흰 바탕 대비 4.5:1 이상을 목표로 검수한다.

기준 환경을 QA에 기록하고 10,000자 문서에서 입력 지연 p95 50ms 이하, 로컬 3,650일 검색 p95 200ms 이하를 목표로 한다. 수치는 측정 전 통과로 표기하지 않는다. 학생 뒷자리 실제 가독성은 데스크톱 캡처만으로 검증 완료 처리하지 않는다.

## 10. 출시 완료 기준

- R01~R18과 PLAN의 대응 검사 항목이 모두 연결되어 있음.
- 작성 → 자동 보관 → 저장 → 수정 → 날짜 이동 → 재열기 → 화이트보드 편집 → 복귀 → 삭제 → 복원 전체 흐름 통과.
- 실행 취소·한글·서식·저장 경합·종료·휴지통 충돌 검증 통과.
- 1366×768 및 1920×1080 학생용 화면, 작은 창·고배율·긴 본문 검수 완료.
- 기존 타이머/명단/툴바/메모/급식 기능에 대한 영향 범위 회귀 검사 완료.
- 브라우저 검사, 실제 Windows Tauri/IME/창 검사, 미실시 macOS·교실 디스플레이 검사를 명확히 분리 보고.
- 현재 문서는 위 검사가 끝났다는 의미가 아니다. 구현 상태는 별도 QA 문서에 증거와 함께 기록한다.
