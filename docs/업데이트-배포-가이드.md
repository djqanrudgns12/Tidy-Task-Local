# 업데이트 배포 가이드

Tidy Task는 **GitHub Releases**를 "공식 배포처"로 삼아, 새 버전이 올라오면
앱이 스스로 알아채고 사용자에게 안내합니다. 별도의 서버나 비용은 필요 없습니다.

---

## 1. 이 시스템은 어떻게 동작하나요?

```
[개발자] GitHub에 새 릴리스 발행
              ↓
[앱] 시작 2초 뒤, 이후 30분마다 GitHub에 "최신 버전이 뭐예요?" 문의
              ↓
[앱] 내 버전(5.1.0) < 최신 버전(5.1.2) 이면
              ↓
[사용자] 창 위에 얇은 띠: "🎉 새 버전 v5.1.2 이 나왔어요"
              ↓ (누르면)
[사용자] 3단계 설치 안내 → [새 버전 내려받기] → 브라우저에서 파일 다운로드
```

**핵심 설계**

| 항목 | 내용 | 이유 |
|---|---|---|
| 확인 주체 | **매니저 창 1개만** | 창을 10개 켜도 GitHub 호출은 1회. 알림도 1번만 뜹니다 |
| 확인 주기 | 부팅 2초 뒤 강제 확인 + 이후 30분마다 | 새 릴리스를 빠르게 알리면서 GitHub 무료 한도(시간당 60회)를 지킵니다 |
| 설치 방식 | 클릭할 때 최신 파일을 다시 확인한 뒤 **링크만 열어 줍니다** | 이전 릴리스 파일이 정리돼도 저장된 옛 주소로 404가 나지 않습니다 |
| 사용자 선택 | "나중에"(하루) / "이 버전 건너뛰기" | 선택은 디스크에 저장되어 앱을 꺼도 유지됩니다 |
| 실패 시 | 자동 확인 실패는 **조용히 무시** | 인터넷이 잠깐 끊겼다고 사용자를 놀라게 하지 않습니다 |

---

## 2. 새 버전을 배포하는 방법 (개발자가 할 일)

### ① 버전 번호 올리기 — `package.json` 한 곳만

```jsonc
// package.json
"version": "5.1.2"   // ← 여기부터 고칩니다
```

> **왜 한 곳만인가:** `src-tauri/tauri.conf.json`이 `"version": "../package.json"`으로
> package.json을 바라보도록 연결해 두었습니다. 버전을 여러 곳에 적으면 하나를 빠뜨렸을 때
> "업데이트했는데도 알림이 계속 뜨는" 문제가 생깁니다.
>
> `src-tauri/Cargo.toml`의 `version`과 도움말·업데이트 공지의 버전 표기도 같은 번호로
> 맞춥니다. 설치 파일 이름은 `package.json`을 따르지만, 모든 화면과 패키지 정보가 같은
> 버전을 보여야 배포본을 혼동하지 않습니다.

### ② 설치 파일 만들기

먼저 `src-tauri/.env`를 준비합니다. 이 파일은 빌드하는 개발자 컴퓨터에만 필요합니다.

```dotenv
NEIS_API_KEY=집에서_사용하던_나이스_인증키
POSTHOG_PROJECT_TOKEN=PostHog_설정에서_복사한_Project_token
POSTHOG_HOST=https://us.i.posthog.com
POSTHOG_DEV_ENABLED=0
```

- `NEIS_API_KEY`: 같은 키를 넣어 빌드하면 각 이용자의 앱이 포함된 키로 나이스 서버에 직접 요청합니다. 이용자가 인증키를 발급하거나 `.env`를 설치할 필요가 없습니다. 학교·캐시·메모는 이용자 PC에 저장합니다.
- 모든 설치본은 같은 키를 사용하므로 키 기준의 사용 한도도 공유합니다. 키를 변경하면 설치 파일을 다시 빌드해 배포해야 합니다.
- `POSTHOG_DEV_ENABLED=0`: 개발 앱은 전송을 끄고, release 설치본은 사용 통계를 자동으로 `environment=production`으로 전송합니다. 별도 테스트가 필요할 때만 테스트 프로젝트와 `POSTHOG_DEV_ENABLED=1`을 사용합니다.
- 시스템에 같은 이름의 환경변수가 있으면 `.env`보다 우선하므로 빌드 전 확인합니다. 키 없이 배포하는 `NEIS_ALLOW_NO_KEY=1` 우회 설정은 사용하지 않습니다.
- 배포 대상은 생성된 설치 `.exe`입니다. `.env`를 함께 올리지 않습니다.

```bash
npm run tauri build
```

결과물이 아래 경로에 생깁니다.

```
src-tauri/target/release/bundle/nsis/Tidy Task_5.1.2_x64-setup.exe
```

### ③ GitHub에 릴리스 발행하기

처음 한 번은 저장소의 **Settings → General → Releases → Enable release immutability**를
켜 둡니다. 이 설정은 앞으로 발행하는 릴리스의 태그와 설치 파일을 잠가, 실수로 이전
버전의 주소를 바꾸거나 파일을 삭제하는 일을 막아 줍니다. 설정을 켜기 전에 만든 릴리스에는
소급 적용되지 않습니다.

1. https://github.com/djqanrudgns12/Tidy-Task-Local/releases 로 이동
2. **Draft a new release** 클릭
3. **Choose a tag** → 아직 사용하지 않은 새 버전인 `v5.1.2` 입력 → *Create new tag* 선택
   - ⚠️ 태그는 반드시 `v5.1.2` 또는 `5.1.2` 형식이어야 앱이 알아봅니다
   - ⚠️ 태그 번호는 `package.json`의 버전과 **똑같이** 맞춰 주세요
4. **Release title**: `Tidy Task 5.1.2` 처럼 입력
5. **Describe this release**: 달라진 점을 한 줄에 하나씩 적습니다
   ```
   - 테마를 15종으로 늘렸습니다
   - 메모가 가끔 저장되지 않던 문제를 고쳤습니다
   ```
   → 이 내용이 앱 안내 창의 "이번에 좋아진 점"에 그대로 표시됩니다
6. ②에서 만든 **`.exe` 파일을 첨부**합니다 (Attach binaries 영역에 끌어다 놓기)
   - ⚠️ 이 파일을 빠뜨리면 앱은 릴리스 페이지 링크만 안내합니다
7. 먼저 **Save draft**를 눌러 제목·태그·첨부 파일을 다시 확인합니다
8. 이상이 없으면 **Publish release**를 누르고, **Latest** 표시가 새 버전에 붙었는지 확인합니다

> **이전 버전 보존 규칙:** 새 버전을 낼 때 기존 릴리스의 연필(Edit) 버튼으로 태그를
> 바꾸거나 기존 EXE를 삭제하지 않습니다. `Latest`는 최신 버전을 가리키는 표시일 뿐,
> 이전 릴리스를 지우는 기능이 아닙니다. 버전마다 서로 다른 릴리스와 EXE를 그대로 남겨야
> 구버전 앱에 저장된 다운로드 주소도 계속 작동합니다.

끝입니다. 실행 중인 사용자 앱은 최대 30분 안에, 앱을 다시 켜면 약 2초 뒤에 알림을 띄웁니다. 내려받기 버튼은 누르는 순간 최신 릴리스를 한 번 더 확인하고, API 확인이 실패하면 저장된 옛 파일 주소 대신 GitHub의 최신 릴리스 페이지를 엽니다.

> 이 빠른 확인 로직은 5.1.2를 설치한 뒤부터 적용됩니다. 아직 5.1.0 이하를 쓰는 사용자는 기존 확인 주기를 따르므로, 5.1.2를 발행한 직후 바로 받으려면 **설정 → 앱 업데이트 → 업데이트 확인**을 누르면 됩니다.

## 3. 사용자(선생님)가 겪게 되는 화면

1. **얇은 알림 띠** — 작업을 가리지 않고 창 위쪽에 조용히 나타납니다
   - `×`를 눌러도 "영구 무시"가 아니라 **하루 미루기**입니다. 실수로 닫아도 내일 다시 알려 줍니다
2. **안내 창** (띠를 누르면 열림)
   - 🔒 "지금까지 쓰신 할 일과 메모는 그대로 남습니다" — 가장 먼저 보이는 안심 문구
   - 이번에 좋아진 점 (릴리스 노트)
   - **설치 방법 3단계** — 누를 순서 그대로
   - 💡 "Windows의 PC 보호" 파란 경고창 대처법 (→ [추가 정보] → [실행])
   - [새 버전 내려받기] / [나중에] / [이 버전 건너뛰기]
3. **설정 → 앱 업데이트** — 언제든 직접 확인할 수 있는 고정 경로

## 4. 알아두실 점

- **저장소가 Public이어야 합니다.** Private으로 바꾸면 앱이 릴리스를 읽지 못합니다.
- **릴리스가 하나도 없으면** 앱은 조용히 넘어갑니다. 설정에서 직접 확인하면
  "아직 공개된 새 버전이 없습니다"라고 안내합니다. (오류가 아닙니다)
- **버전을 되돌리면(예: 5.1.2 → 5.1.1)** 앱은 업데이트로 인식하지 않습니다.
  버전 번호는 항상 올라가야 합니다.
- **코드 서명 인증서가 없어** 설치 시 "Windows의 PC 보호" 경고가 뜹니다.
  안내 창에서 대처법을 미리 알려 주므로 사용자가 당황하지 않습니다.
- 사용자 데이터(`tidy-task-config.json`)는 `%APPDATA%` 아래에 저장되므로
  설치 파일을 덮어써도 **삭제되지 않습니다.**

## 급식창이 포함된 빌드

- 배포 빌드 전에 `src-tauri/.env` 또는 빌드 프로세스 환경변수에 `NEIS_API_KEY`를 설정합니다. 키가 없으면 release 빌드를 중단합니다.
- `.env`와 인증키를 Git에 올리지 마세요. 프런트엔드 `VITE_` 환경변수로 전달하지 않습니다.
- 인증키 난독화의 한계, 실제 API 검사 명령, 네이티브 검수 항목은 [급식창 구현과 검수](급식창-구현-검수.md)를 참고하세요.
