## 1. 한 줄 요약

[아카이브]를 누르면 **버튼 바로 밑에서 꼭지(▲)로 버튼을 가리키는 작은 점무늬 카드**가 열립니다. 머리글의 **상자 친구**(시안 C)가 "할 일 3개를 아카이브에"라고 말하고, 아래 **딱지 두 장**(시안 A)에서 `복사해서 보관` · `옮겨서 보관`을 고릅니다.
카드는 **어떤 설정에서도 가로 224px · 세로 130px를 넘지 않습니다.**

## 2. 확정한 것 · 남은 결정

| 항목 | 결정 |
|---|---|
| 시안 | **A 딱지 두 장 + C 상자 친구(머리글 아이콘 크기)** — 사용자 확정 |
| 문구 | 1안 `복사해서 보관` / `옮겨서 보관` (v1 §3) |

## 3. 해부도와 치수

단위는 **메뉴 글자 크기 기준 em**(§5의 `menuPt`). 괄호 안은 기본 10pt(13.33px)일 때 px.

```
              ▲ 꼭지: 폭 0.9em(12) · 높이 0.45em(6) · 끝이 [아카이브] 가운데를 가리킴
┌────────────────────────────────────────────┐  ← 카드: 모서리 1.1em(15) · 테두리 1.5px · 아래 받침 0.15em(2)
│ (◕‿◕)³  할 일 3개를 아카이브에               │  ← 머리글 줄 1.8em(24): 상자 친구 1.8em + 글자 0.8em (M단계 1.5em)
│ ┌──────────────────┐ ┌──────────────────┐ │  ← 딱지 사이 0.45em(6) · 2열 같은 폭
│ │  [목록]→[상자]   │ │  [목록]→[상자]   │ │  ← 그림 4em×1.55em(53×21)
│ │  복사해서 보관   │ │   옮겨서 보관    │ │  ← 이름 0.86em 굵게, 한 줄
│ │   목록엔 그대로  │ │  목록에선 빠져요 │ │  ← 설명 0.7em, 한 줄, 흐린 글자
│ └──────────────────┘ └──────────────────┘ │  ← 딱지: 모서리 0.85em · 테두리 1.5px · 받침 0.15em
└────────────────────────────────────────────┘  ← 카드 안쪽 여백 0.55em(7)
```

세부 정렬 규칙(사소해 보여도 어긋나면 "대충 만든" 느낌이 나는 곳):
1. **머리글**: 상자 친구 왼쪽 끝 = 딱지 왼쪽 끝(카드 안쪽 여백선). 글자는 친구의 **눈높이**(위에서 52%)에 맞춥니다. 기준선이 아니라 눈에 맞춰야 친구가 "말하는" 느낌이 납니다.
2. **개수 방울**: 친구 오른쪽 위에 0.35em 겹쳐 붙입니다. 지름 1.05em, 강조색 바탕 · 흰 글자, 카드색 1.5px 테두리로 친구와 떨어져 보이게 합니다. 1~99는 숫자, 100 이상은 `99+`(가로로 늘어나되 왼쪽 끝 고정 — 친구를 가리지 않게).
3. **딱지 속 세로 리듬**: 그림 → 이름 0.25em → 설명 0.15em. 두 딱지의 그림·이름·설명 **기준선이 서로 같아야** 합니다(`grid-template-rows: auto auto auto`). 글이 짧다고 위로 뜨지 않게.
4. **그림**: 두 그림 모두 "목록 → 상자" 틀에 같은 자리. 차이는 하나뿐 — 복사는 목록이 꽉 찬 채 카드 한 장이 상자로, 옮김은 목록 한 줄이 **점선 빈칸**으로 남고 그 줄이 상자로 갑니다. (시안 A의 옮김 그림은 차이가 약해 이 규칙으로 다시 그림)
5. **점무늬 바탕**: 점 간격 1.35em. `background-position`을 카드 안쪽 여백(0.55em)에 맞춰 **모서리에서 반쪽 점이 잘리지 않게** 합니다.
6. **초점·올림 표시**: 강조색 1.5px 테두리 + 바깥 0.1em 띄움. 카드 안쪽 여백(0.55em)보다 얇아 **잘리지 않습니다**(카드 `overflow: visible`). 올리면 딱지만 1px 떠오르고 받침 그림자가 0.2em으로.
7. **딱지 글자는 줄바꿈 금지**(`white-space: nowrap`). 가장 좁은 카드(176px)에서도 `복사해서 보관`이 들어가는 것을 실측으로 확인했습니다(§4, 넘침 0).

## 4. 크기 예산 — "지나치게 커지지 않게"

### 4.1 Codex 시안 A 원본 실측 (가로×세로 px)

| 화면 글자 | 250px 창 | 380px 창 | 문제 |
|---|---|---|---|
| 6pt | 124×86 | 124×86 | 글자 8px — 읽기 어려움 |
| 10pt | 207×141 | 207×141 | 기본값인데도 할 일 4줄을 가림 |
| 12pt | 229×165 | 248×168 | |
| 15pt | 224×208 | **310×213** | 380px 창의 82%를 덮음 |

원인: 크기가 화면 글자에 **정비례**하고, 딱지에 최소 높이(6.35em)와 두 줄 설명 자리(2.7em)를 미리 잡아 둠.

### 4.2 v2 예산 (§3·§5 규칙을 시안 A에 덮어 실측 — 넘침 0, 캡처 `budget-10pt-380.png` · `budget-15pt-250.png`)

| 화면 글자 | 메뉴 글자 | L 단계 (그림+이름+설명) | M 단계 (이름+설명) | S 단계 (이름만, 한 줄) |
|---|---|---|---|---|
| 6pt · 8pt | 9pt | **176×98** | 176×75 | 176×40 |
| 10pt | 10pt | **187×109** | 187×83 | 187×44 |
| 12pt · 13pt · 15pt | 12pt | **224×130** | 224×99 | 224×52 |

- 가로: `clamp(176px, 14em, 224px)`. 최소 창 250px에서 좌우 안쪽선 12px씩을 빼면 226px이라 **언제나 들어갑니다**(가로 접힘 단계가 필요 없음).
- 세로 상한: L 130px · M 99px · S 52px. 기본 10pt의 L(109px)이 예전 시안(141px)보다 23% 작습니다.
- 상한의 근거: 메모 창 기본 크기(380×500)에서 L이 막대 아래 할 일 영역의 약 45%를 넘지 않음.

## 5. 시스템 설정 연동 (스마트 로직)

설정 창의 **글자 → 화면 글자**와 **모양**을 따르되, 메뉴가 읽기 어려워지거나 창을 덮지 않게 범위를 둡니다.
설정 창 [적용]을 누르면 열린 메뉴도 그 자리에서 바뀝니다(값은 모두 반응형, 크기가 바뀌면 다시 재고 다시 배치).

| 설정 | 메뉴에 주는 영향 | 규칙 |
|---|---|---|
| 화면 글자 크기 | 메뉴 글자 `menuPt` | `menuPt = clamp(9, uiFontSize, 12)`. 6·8pt는 9pt로 올려 읽기를 보장하고, 13·15pt는 12pt로 묶어 크기 예산을 지킵니다. 모든 치수가 em이라 함께 움직임 |
| 화면 글꼴 | 메뉴 전체 글꼴 | `var(--ui-font-family)` (이미 `resolveFontFamilyStack`으로 푼 값 — 시스템 글꼴·내 글꼴 모두 적용) |
| 테마 (15종) | 카드·딱지·꼭지·점무늬·개수 방울 | 카드 = 테마 `tidy.bg`, 딱지 = 흰색(다크 `#2b3039`), 테두리 = `tidy.border`, 강조 = `getThemeAccent(테마, 다크)`. 상자 친구 몸통은 **테마와 상관없이 골판지색**(어느 테마에서도 "상자"로 알아보게), 볼 터치만 강조색을 섞음 |
| 다크 모드 | 위 색의 다크 짝 | 명시 6자리 Hex만(`light-dark()` 금지 — 배포 빌드에서 값이 사라진 전례). 글자 대비 4.5:1 이상을 단위 테스트로 확인 |
| 움직임 줄이기(OS) | 열림·깜빡임·떠오름 | 페이드만, 친구 눈 깜빡임 끔 |
| 전체 무음 | — | 소리 없음(원래 소리를 내지 않음) |

우클릭 메뉴(1~1.25배)와 같은 생각입니다 — "따라가되 상한이 있다". `menuPt` 결정과 다크 대비는 순수 함수로 두고 테스트합니다(§12).

## 6. 높이에 맞춘 3단계 접힘

막대 아래 남은 높이는 창 크기·머리 영역(서식 줄 펼침, D-Day 배너)·화면 글자에 따라 크게 달라집니다.
예: 사용자 화면(서식 줄 펼침)에서 막대 아래 끝이 창 위에서 약 195px → **최소 창 높이 300px이면 남는 높이 약 97px**, D-Day 배너까지 켜면 약 50px.

| 단계 | 모양 | 언제 |
|---|---|---|
| **L** | 머리글(친구+문장) + 그림 딱지 두 장 | 기본 |
| **M** | 머리글 + 딱지(그림 빼고 이름·설명) | L이 아래에 안 들어갈 때 |
| **S** | 한 줄: 알약 딱지 두 개(이름만), 설명은 `title`·화면 낭독기로. 176px 폭에는 친구 자리가 없어 뺌(v2.1) | M도 안 들어갈 때 |

고르는 방법(측정 기반 — 어림값 아님):
1. 열기 직전 화면 밖(`visibility:hidden`)에서 L·M·S의 실제 높이를 잽니다(`document.fonts.ready` 뒤).
2. `아래 공간 = 창 안쪽 아래 끝 − 꼭지 끝 − 8px`. L→M→S 순서로 **처음 들어가는 단계**를 아래로 엽니다.
3. 아래에 S도 안 들어가면 `위 공간 = 버튼 위 끝 − 제목줄 아래 끝 − 8px`에서 같은 순서로 골라 **위로** 엽니다(꼭지가 아래쪽으로 바뀜).
4. 그래도 안 되면 S를 아래로 열고 창 아래 끝에 맞춰 자릅니다(창 높이 300px 이상에서는 실측상 일어나지 않을 안전망).
5. 열린 채 창 크기·화면 글자가 바뀌면 1~4를 다시 합니다(`ResizeObserver` — 메모 창 뿌리 · 막대 · 메뉴).

## 7. 배치 — [아카이브] 바로 아래 정위치

좌표는 메모 창 뿌리(`position: relative`) 기준 논리 px입니다. 별도 창이 아니라 같은 문서 안 팝오버입니다(별도 창은 초점 왕복·배율 환산이 필요한데, 이 메뉴는 창 안에 늘 들어가는 크기라 필요 없음).

1. **세로**: 꼭지 끝 = 버튼 아래 끝 + 3px, 카드 위 끝 = 꼭지 끝 + 꼭지 높이(0.45em). 버튼과 카드 사이가 비어 보이지 않으면서 버튼 테두리에 닿지 않는 거리입니다.
2. **가로 1차 — 가운데 맞춤**: `left = 버튼 가운데 − 카드 폭/2`.
3. **가로 2차 — 도크 바깥선 안으로**: `left`를 `[도크 왼쪽 끝, 도크 오른쪽 끝 − 카드 폭]`으로 묶습니다(도크 = 창 가장자리에서 10px). 카드 가장자리가 도크의 둥근 테두리와 **같은 세로선**에 섭니다. (v2 초안의 "막대 안쪽선 12px"은 막대가 도크로 바뀌어 도크 선으로 바꿈)
4. **가로 3차 — 붙임**: 묶은 뒤 한쪽 안쪽선과 10px 이내면 그 선에 붙입니다. 2~9px 어긋남이 가장 "삐뚤어 보이는" 거리라서입니다.
5. **꼭지**: `꼭지 x = 버튼 가운데 − left`를 `[1.5em, 카드 폭 − 1.5em]` 안으로 묶습니다. 카드가 옮겨져도 꼭지는 언제나 버튼을 가리키고 둥근 모서리에 걸치지 않습니다.
6. **커지는 기준점**: `transform-origin = 꼭지 x, 위(위로 열 땐 아래)` — 버튼에서 피어나는 느낌.

미리 계산한 예(v2 초안 — 옛 막대의 버튼 위치·안쪽선 12px 기준, 단위 px). 도크 기준 값은 `archiveMenuLayout.test.js`가 같은 방식으로 확인합니다:

| 창 · 화면 글자 | 버튼(왼~오) | 카드 폭 | 가운데 맞춤 left | 안쪽선 범위 | 최종 left | 꼭지 x | 비고 |
|---|---|---|---|---|---|---|---|
| 380 · 10pt | 182~242 | 187 | 118.5 | 12~181 | 118.5 | 93.5 | 정가운데 |
| 460 · 10pt | 262~322 | 187 | 198.5 | 12~261 | 198.5 | 93.5 | 정가운데 |
| 300 · 10pt | 175~196 (아이콘만) | 187 | 92 | 12~101 | **101** (9px → 붙임) | 84.5 | 오른쪽 가장자리가 지우개 끝선과 일치 |
| 250 · 10pt | 125~146 (아이콘만) | 187 | 42 | 12~51 | **51** (9px → 붙임) | 84.5 | 같음 |
| 250 · 15pt | 93~124 (아이콘만) | 224 | −3.5 | 12~14 | **12** | 96.5 | 카드가 막대 안쪽과 꼭 같은 폭 |

## 8. 상자 친구 (시안 C에서 빌린 부분)

## 9. 동작 · 접근성 · 닫힘

- 열기: [아카이브] 클릭(처리 중이면 무시). 열린 채 다시 누르면 닫힘(`pointerdown` 때의 열림 상태로 판단 — 날짜 달력과 같은 규칙). 열리면 [D-Day] 달력은 닫힘(반대도 같음).
- 초점: 열자마자 `복사해서 보관`(시안 원본은 버튼에 남아 있었음 — 고침). ←→↑↓ 모두 두 딱지 사이 이동(가로 배치라 ←→가 자연스러움), Home/End, Enter·Space 고르기, Tab 순환, Esc는 닫고 [아카이브]로 초점을 돌려줌.
- 열린 직후 150ms는 딱지 클릭 무시(위로 열린 경우 더블클릭의 둘째 클릭이 딱지에 떨어지는 사고 방지).
- 닫힘: Esc · 바깥 누름 · 고르기 · 선택 0개 · 선택 모드 끝 · 업데이트 잠금 · Ctrl+Z/Y(먼저 닫고 되돌리기) · 창이 초점을 잃음.
- `role="menu"` · `menuitem`, 긴 설명은 `aria-describedby`, 메뉴 이름 `할 일 3개 · 아카이브(보관함)`.
- 겹침 순서: 할 일 목록 위, 삭제 확인 창·안내 알림 아래(`z-index` 60 — 알림·모달은 99999).

## 10. 고른 뒤 동작과 되돌리기

| | 복사해서 보관 | 옮겨서 보관 |
|---|---|---|
| 보관함 | 카드 추가를 다시 읽어 확인(`addNotes`) | 같음 |
| 할 일 | 그대로 · 선택 유지 | 확인 뒤 목록에서 뺌(`removeTodosByIds`) |
| 안내 | `할 일 3개를 아카이브에 복사했어요` | `할 일 3개를 아카이브로 옮겼어요` |
| Ctrl+Z | 카드만 빠짐 + 안내 `아카이브에서 카드 3개를 뺐어요` | 할 일 복귀 + 카드 빠짐 (**구현 완료**) |
| Ctrl+Y | 카드 다시 들어감 | 할 일 다시 빠짐 + 카드 다시 들어감 (**구현 완료**) |

복사는 메모 창 내용이 그대로라 되돌리기 칸이 생기지 않습니다. 그래서 `appState.recordHistoryEffect(effect)`를 새로 둡니다 — 같은 스냅샷이어도 칸을 하나 강제로 남기고(`pushToHistory({ force: true })`) 거기에 딸린 일을 붙입니다.
저장소 잠김·업데이트 잠금 중에는 메뉴가 열리지 않고 안내만 띄웁니다.

## 11. 경계 상황

1. 12개·100개 이상 고름 → 머리글 숫자·방울만 바뀌고(`99+`) 크기 그대로.
2. 열린 채 다른 창 동기화로 고른 할 일이 줄어듦 → 개수 갱신, 0이 되면 닫힘.
3. 열린 채 설정 창 [적용](글자·테마·다크) → 즉시 반영, 단계·위치 다시 계산.
4. 열린 채 창 크기 변경 → 다시 배치(닫지 않음). 버튼이 사라지면(선택 모드 끝) 닫힘.
5. 위로 열린 상태에서 창을 키워 아래 공간이 생김 → **0.3초 안정된 뒤**에만 아래로 돌아감(끌기 중 방향이 깜빡이지 않게).
6. 아카이브 창이 열려 있음 → 카드가 곧바로 나타나고 Ctrl+Z 때 곧바로 사라짐.
7. 보관함 쓰기 3번 모두 확인 실패 → 아무것도 바꾸지 않고 실패 안내.
8. D-Day와 이어진 할 일을 옮김 → D-Day 설정(`syncTodosDeletedToDdays`)대로, "D-Day 남김" 안내는 결과 안내 다음에 이어서.
9. 글꼴을 아직 불러오는 중 → `document.fonts.ready` 뒤에 단계 측정(글꼴이 바뀌며 넘치는 일 방지).
