# Tidy Task 창 사라짐 진단 및 해결

- 작성일: 2026-09-16
- 대상: v5.0.2 (`main`, 커밋 `62db11c` 이후 작업 트리)
- 한 줄 요약: **배율이 다른 두 모니터에서 창 좌표를 잘못 되돌려 창이 화면 밖에 놓이던 문제**가 주원인이었습니다. 좌표 저장·복원 방식을 고치고, 어떤 경우에도 창이 화면 안에 나타나도록 세 겹의 안전장치를 넣었습니다.

---

## 1. 증상

- 컴퓨터를 껐다 켜거나 새 버전을 설치한 뒤 실행하면 **Tidy Task 메인 창이 보이지 않습니다.**
- 메인 창이 안 보이니 Tiny Note나 새 창을 띄우는 버튼도 쓸 수 없습니다.
- 시스템 트레이의 **"좌표 초기화"**를 눌러야 창이 다시 나타납니다.
- 이번 리팩토링 이전 버전에서도 있던 문제입니다.

## 3. 주원인 상세 — 배율이 다른 모니터와 논리 좌표

### 3.1 사용자 PC 실측값

| 모니터 | 물리 좌표(실제 픽셀) | 해상도 | 배율 |
|---|---|---|---|
| DISPLAY2 (주 모니터) | (0,0) ~ (3840,2160) | 4K | **200%** |
| DISPLAY1 (보조 모니터) | (3840,0) ~ (5760,1080) | FHD | **100%** |

> 용어 풀이
> - **물리 좌표**: 실제 화면 픽셀 기준의 위치. 모든 모니터가 하나의 좌표계를 공유합니다.
> - **논리 좌표**: 물리 좌표 ÷ 그 모니터의 배율. 배율이 다르면 모니터마다 기준이 달라집니다.

### 3.2 무엇이 잘못됐나

예전 코드는 창 위치를 **논리 좌표**로만 저장하고, 다시 켤 때 논리 좌표로 되돌렸습니다.

1. 보조 모니터(배율 100%)의 물리 x=4500에 창을 둡니다.
   → 저장값: 논리 x = 4500 ÷ 1 = **4500**
2. 다음 실행 때 창은 **주 모니터(배율 200%)에서 만들어진 뒤** 저장 위치로 옮겨집니다.
   → 이때 논리 4500을 **주 모니터 배율(2)** 로 계산해 물리 x = 4500 × 2 = **9000**
3. 가장 오른쪽 모니터 끝은 5760이므로 **창이 모든 모니터 밖**에 놓입니다.
4. 트레이 "좌표 초기화"는 창을 (100,100)으로 강제로 옮기므로 그때만 보였습니다.

재부팅 직후나 업데이트 뒤에 특히 잘 나타난 이유:
- 앱이 **자동 실행**되며 창이 항상 주 모니터에서 새로 만들어집니다.
- 부팅 직후에는 보조 모니터가 **늦게 인식**되거나 배치가 바뀌는 경우가 있어, 멀쩡한 좌표도 화면 밖이 될 수 있었습니다.

## 4. 해결 내용

### 4.1 좌표 저장 방식 (근본 해결)
| 변경 | 파일 |
|---|---|
| 창 위치를 **물리 좌표(`windowPhysX/Y`)와 논리 좌표를 함께** 저장하는 공용 함수 `rememberWindowPosition()` 추가 | `appState.svelte.js` |
| 새 필드를 저장 계약 표(`WINDOW_FIELDS`)에 추가 — 예전 설정 파일은 한 글자도 바뀌지 않음(테스트로 확인) | `storage/windowDataCodec.js` |
| 창 이동·닫기·전체화면 전환·Tiny Note 스냅·세로 스냅의 좌표 저장을 모두 이 함수로 통일 | `App.svelte`, `Titlebar.svelte`, `StickerWindow.svelte` |

### 4.2 좌표 복원 방식
| 변경 | 설명 |
|---|---|
| **저장 좌표 해석 규칙** `resolveSavedPosition()` | ① 물리 좌표가 있으면 그대로 사용 ② 예전 데이터(논리 좌표만 있음)는 "각 모니터의 배율로 되돌렸을 때 바로 그 모니터 안에 보이는가"로 해석 ③ 둘 다 안 되면 쓰지 않음 |
| **화면 안 판정** `isTitleStripVisible()` | 창 윗부분(제목줄)이 작업영역 안에서 끌어 옮길 수 있을 만큼(가로 80·세로 24 논리px) 보이는지 검사 |
| **화면 밖 보정** `findVisiblePlacement()` / `ensureWindowOnScreen()` | 크기까지 적용한 뒤에도 화면 밖이면 **주 모니터 작업영역 가운데**로 이동 |

파일: `src/lib/windows/windowPlacement.js`(순수 규칙, 단위 테스트), `src/lib/windows/windowRegistry.js`(Tauri 호출)

### 4.3 "창이 반드시 보이게" 하는 안전장치 (3겹)
| 겹 | 동작 | 파일 |
|---|---|---|
| 1 | 시작 과정에서 저장소를 못 읽어도 멈추지 않도록 예외가 날 수 있던 지점 보호 | `App.svelte` |
| 2 | 데이터 창은 시작 4초 뒤에도 숨어 있으면 **화면 코드가 직접 표시** | `App.svelte` |
| 3 | 시작 8초 뒤 main 창이 숨어 있거나 화면 밖이면 **Rust가 직접 꺼냄** / 트레이 **"열기"만 눌러도** 화면 밖 창을 끌어옴 / 두 번째 실행 시에도 동일 | `src-tauri/src/lib.rs` |

### 4.4 그 밖의 수정
| 변경 | 이유 |
|---|---|
| 최소화 상태로 닫힐 때 좌표·크기를 저장하지 않음 | 윈도우가 최소화 창을 (-32000,-32000)·크기 0으로 보고하기 때문 |
| 최소화 중 크기 변화 무시 | 메모 영역 높이가 기본값으로 줄고 창 크기가 0으로 저장되던 문제 |
| Tiny Note 스냅 처리에 최소화 좌표 무시 추가 | 같은 이유 |
| 우클릭 메뉴 위치를 물리 좌표로 계산 | 보조 모니터에서 메뉴가 화면 밖에 뜨던 문제 |
| "좌표 초기화"를 주 모니터 작업영역 기준 물리 좌표로 배치 | 창마다 배율이 달라 기준점이 어긋나던 문제 |
| **5분마다 설정 파일 백업**(내용이 바뀐 경우만) | 사용 중 전원이 꺼져 파일이 손상돼도 최대 5분 분량만 잃도록 (시작 시 손상 감지 → 백업 복구는 기존 기능) |

## 6. 사용자가 확인할 방법

새 버전을 실행하기 전에 지금 데이터를 백업해 주세요.

```powershell
Copy-Item "$env:APPDATA\com.tidy.task\tidy-task-config.json" "$env:USERPROFILE\Desktop\tidy-task-config.before-window-fix.json"
```

개발판 실행:

```powershell
npm run tauri dev
```

| # | 시나리오 | 기대 결과 |
|---|---|---|
| 1 | **보조 모니터(오른쪽 FHD)** 에 메인 창을 두고 트레이에서 종료 → 다시 실행 | 창이 **보조 모니터의 같은 자리**에 나타남 |
| 2 | 보조 모니터에 창을 둔 채 종료 → **보조 모니터 케이블을 뽑고** 실행 | 창이 **주 모니터 가운데**에 나타남 |
| 3 | 메인 창을 **최소화한 채** 트레이에서 종료 → 다시 실행 | 최소화 전 위치·크기, 메모 영역 높이가 그대로 |
| 4 | 보조 모니터에 있는 창에서 **우클릭** | 메뉴가 마우스 위치에 뜸 |
| 5 | Tiny Note를 보조 모니터에 두고 종료 → 다시 실행 | 같은 자리에 나타남 |
| 6 | 트레이 **"열기"** | 창이 화면 밖이었더라도 주 모니터 가운데로 나타남 |
| 7 | 트레이 **"좌표 초기화"** | 모든 창이 주 모니터 왼쪽 위부터 계단식으로 모임 |
| 8 | 앱을 켜 두고 5분 이상 메모 수정 | `%APPDATA%\com.tidy.task\tidy-task-config.backup.json`의 수정 시각이 갱신됨 |
