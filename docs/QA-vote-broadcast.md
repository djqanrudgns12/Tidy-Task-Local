# 개표 방송 리뉴얼 검수

## 화면과 집계

- 네이비 방송 무대, 현재 판세 패널, 큰 득표 숫자, 공개 용지 기준 개표율, 집계 자막을 구성했습니다.
- 후보 기호와 순위는 구분합니다. 득표 막대는 득표율과 같은 분모를 사용합니다.
- 후보·의견은 유효 득표, 찬반은 기권을 포함한 개표 인원을 분모로 사용하고 기준을 화면에 적습니다.
- 공동 선두, 선두 교체, 직전 공개 묶음의 추가 득표, 남은 용지와 기권을 공개된 표만으로 계산합니다.
- 판정은 기존 outlook 계산을 재사용하며, 복수 선출·중복 선택을 고려한 확실 판정을 유지합니다.
- 방송 자동 재생은 공개 단계 수를 기준으로 계산하고 마지막 세 단계에서 더 오래 유지합니다. 완료 화면은 4.2초, 찬반 안건 사이에는 3.6초를 확보합니다.
- 작은 높이에서는 보조 패널을 접고, 후보 9명은 두 열로 배치합니다. 긴 이름은 줄바꿈하며 보조 기술에는 기호·이름·득표율·판정·추가 득표를 제공합니다.
- 기존 캐릭터 에셋과 로컬 글꼴을 사용합니다. 움직임 줄이기에서는 전환 애니메이션을 제거합니다.

## 확인 결과

- 관련 자동 테스트 88개 통과: broadcast, vote, outlook, resultImage.
- 프로덕션 빌드 통과. 변경한 파일의 Svelte 진단 0건. 전체 검사에는 기존 자리 배치 테스트 3개 파일의 타입 오류 18건이 남습니다.
- 1440×900, 1366×768, 1024×720, 800×600 각각 후보 5명·9명·의견·찬반 화면 확인. 최종 16개 조합에서 목록 넘침과 행 내부 겹침 0건, 런타임 오류 0건.
- 공동 선두 9명, 긴 의견 이름, 전원 기권, 빈 투표, 마지막 공개 직전, 찬반 재개 상태의 추가 6개 사례 확인.
- 움직임 줄이기 환경에서 멈춤 유지, 건너뛰기 후 결과 도달 확인. 찬반 3개 안건을 실제 다음 버튼으로 끝까지 개표하고 결과 도달 확인.
- 800×600 재검사는 qa-small.json에 있으며 해당 크기의 이전 qa.json 기록을 대체합니다.
