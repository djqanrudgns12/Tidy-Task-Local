# Tidy 툴킷 집중벨 구현 계획

작성일: 2026-09-21. 음원 2차 수정: 사용자 피드백으로 종소리·사이렌 교체. 상태: 집중벨 구현 및 툴킷 연결 완료. 최종 종소리·사이렌 각 2초. 검증 결과는 QA-focus-bell.md 참고.

## 1. 사용자 요구와 참고 이미지

확정 요구: 집중벨에 종소리·폭탄·방구·사이렌을 제공한다. 교사가 버튼을 클릭할 때 소리와 애니메이션 또는 영상이 함께 재생되며 음량을 조절할 수 있어야 한다. 음원은 개발자가 적극적으로 찾아 우선 선정한다.

이미지는 큰 시각 연출과 하단 효과음 버튼 배치를 참고한다. 이미지의 자동재생 방식은 채택하지 않는다. 캐릭터나 그래픽 자체는 가져오지 않고 Tidy에 어울리는 별도 그림을 만든다. 아래 기본 음량, 창 정책, 연타 처리, 연출 상세는 구현을 위한 제안이다.

## 2. 화면과 조작

- 툴바에 `집중벨`을 추가하고 독립 창으로 연다. 같은 도구를 다시 열면 기존 창을 앞으로 가져오는 단일 창 방식을 권장한다.
- 위쪽에는 제목·전체화면·항상 위·닫기, 중앙에는 큰 애니메이션, 아래쪽에는 `종소리 / 폭탄 / 방구 / 사이렌` 재생 버튼과 `정지`, 음량 슬라이더를 둔다.
- 각 효과 버튼을 한 번 누르면 해당 소리와 연출이 즉시 시작된다. 별도의 종류 선택 후 재생 버튼을 누르는 두 단계는 필요 없다.
- 창 열기, 다시 표시, 음량 변경, 전체화면 전환만으로는 재생하지 않는다. 파일 사전 로드는 허용하되 재생 시작은 반드시 사용자 클릭 또는 버튼의 키보드 실행에 연결한다.
- 같은 버튼을 다시 누르면 처음부터 다시 재생한다. 다른 버튼은 현재 소리와 연출을 종료한 뒤 새 효과로 전환한다. 동시에 두 소리를 겹치거나 대기열을 쌓지 않는다.
- 모든 효과는 클릭당 한 번의 유한한 연출로 끝난다. 종소리 파일 내부의 연속 울림은 하나의 연출이며 자동 반복 재생과 구분한다.
- 음량은 0~100%, 권장 기본값 40%. 재생 중 즉시 반영하고 음소거를 제공한다. 음소거 시에도 연출은 진행된다. 컴퓨터 전체 음량이나 타이머 음량을 변경하지 않는다.
- 음량·음소거만 로컬 저장한다. 재생 상태는 저장하거나 재실행 시 복구하지 않는다. 창을 닫으면 소리도 즉시 정지한다.
- 최소 창에서도 4개 버튼과 정지·음량을 유지한다. 작은 폭에서는 2×2 배열을 사용한다. 기본 960×680, 최소 640×480을 초안으로 잡는다.
- Tab과 Enter/Space로 버튼 사용 가능. Escape는 재생을 정지하며 전체화면에서는 전체화면 종료도 처리한다. 빠른 점멸을 피하고 동작 줄이기 설정에서는 정적인 큰 그림과 상태 문구를 사용한다.

## 3. 효과별 연출과 확보한 파일

| 효과 | 준비한 파일 | 길이 | 우선 연출 |
| --- | --- | --- | --- |
| 종소리 | `public/audio/toolkit/focus-bell/bell.wav` | 2.00초 | 실제 핸드벨의 연속 울림에 맞춰 큰 노란 종이 흔들리고 파동이 퍼짐 |
| 폭탄 | `public/audio/toolkit/focus-bell/bomb.wav` | 1.18초 | 클릭 즉시 만화풍 폭발과 별·연기 확산. 긴 도화선 대기 없이 소리와 타격 시점을 맞춤 |

| 사이렌 | `public/audio/toolkit/focus-bell/siren.wav` | 2.00초 | 두 음이 번갈아 울리는 사이렌에 맞춰 경광등 빛이 좌우로 천천히 회전. 화면 전체의 강한 점멸은 사용하지 않음 |

1차 구현은 SVG와 CSS 애니메이션을 권장한다. 짧은 효과음과 맞추기 쉽고 오프라인에서 가벼우며 화면 크기 변화에도 선명하다. 영상은 필수 요구가 아니므로 1차에 별도 동영상 파일은 필요하지 않다.

확보한 원본 출처:

- 종소리: Joseph SARDIN / BigSoundBank, [Bell #1](https://bigsoundbank.com/bell-1-s2113.html), CC0. 실제 손으로 흔드는 종 녹음에서 0.11초부터 2초를 추출했다. 짧은 타격음만 두드러지지 않도록 피크 압축 후 -3dBFS로 정규화했다.
- 폭탄: qubodup, [Synthesized explosion](https://opengameart.org/content/synthesized-explosion), CC0. 원본 FLAC을 이름만 변경했다.
- 방구: LFA, [Gastric Distress](https://opengameart.org/content/gastric-distress), CC0. 여러 소리가 담긴 원본 중 첫 1.5초를 추출했다. 제작자는 입과 손으로 만든 효과음이라고 설명한다.
- 사이렌: Joseph SARDIN / BigSoundBank, [2 Ton Siren](https://bigsoundbank.com/ambulance-siren-2-s1464.html), CC0. 엔진 소음 없이 녹음한 두 음 사이렌에서 0.01초부터 2초를 추출했다. 페이드 적용 후 피크를 -3dBFS로 정규화했다.

라이선스는 각 원문 페이지에서 확인했다. 원본·출처 페이지 사본·다운로드 URL·SHA-256은 `artwork/toolkit/focus-bell/`에 보관했다. 배포 파일 옆에도 `LICENSE.txt`와 `manifest.json`을 둔다. Mixkit도 조사했으나 이번 집중벨은 음원 버튼 도구에 해당하므로, 도구/소스파일 재배포 제한이 명시된 후보보다 CC0 파일을 우선했다. [Mixkit 조건](https://mixkit.co/license/modal/sfxFree/)

WAV 3종은 모노 변환, 피크 기준 감쇠/증폭, 시작·끝 페이드를 적용했다. 이 과정은 체감 음량을 동일하게 맞췄다는 의미가 아니다. 폭발음은 미가공 원본이므로 최종 구현에서 디코딩한 뒤 다른 소리와 음량을 맞추고 필요하면 WAV로 변환한다. 청감 평가와 실제 교실 스피커 검수는 아직 완료하지 않았다.

## 4. 현재 코드에 연결할 지점

현재 Svelte 5 + Tauri 2 구조를 기준으로 한다. 작업 폴더에는 뽑기/토너먼트 등 다른 미커밋 변경이 있어, 구현 시 최신 상태를 다시 읽고 관련 분기만 추가한다.

| 위치 | 구현 내용 |
| --- | --- |
| `src/lib/toolkit/registry.js` | `focus-bell` / 집중벨 메타데이터 추가 |
| `src/components/toolkit/ToolkitToolbar.svelte` | 아이콘과 실행 버튼 추가, 기존 가로/세로·명단 버튼 배치 유지 |
| `src/components/toolkit/ToolkitSettings.svelte` | 집중벨 노출 관리 연결 |
| `src/components/toolkit/ToolkitApp.svelte` | `focus-bell` 역할에서 FocusBellApp 지연 로드 |
| `src/lib/toolkit/preferences.js` | 도구 ID 허용 목록, 기본값, 기존 사용자 설정 마이그레이션 확장 |

조사 당시 설정은 schemaVersion 4였으며 JS/Rust 모두 노출 목록과 허용 개수에 제한이 있다. 구현 시 최신 버전에서 다음 버전으로 함께 올리고, 기존 숨긴 도구 설정을 보존하면서 집중벨을 한 번만 기본 추가한다. 음량은 별도의 버전 있는 집중벨 설정으로 분리해 기존 타이머 preferences를 건드리지 않는다.

## 5. 오디오와 연출 제어

- 로컬 번들 파일만 사용하여 인터넷 연결 없이 동작한다. 외부 URL을 실행 중 스트리밍하지 않는다.
- 도구 전용 AudioContext 하나, 디코딩 버퍼 캐시, GainNode 하나를 둔다. 타이머 오디오 코드의 수명 관리 패턴은 참고하되 반복 타이밍용 기능을 그대로 복제하지 않는다.
- 상태는 `idle / loading / playing / error`. 첫 클릭에서 AudioContext.resume을 호출하고, 준비 완료 후 같은 실행 토큰에 대해서만 재생한다.
- 클릭·정지·닫기마다 실행 토큰을 갱신한다. 늦게 끝난 파일 로드나 이전 onended가 새 연출을 시작하거나 정지시키지 못하게 한다.
- audio 시작 시각과 실제 버퍼 길이를 기준으로 연출 진행도를 계산한다. 벨 연출은 교체된 실제 핸드벨의 연속 타격에 맞춘다. 이전 후보의 세 번 반복 간격은 사용하지 않는다. 화면 프레임의 setInterval로 소리를 스케줄하지 않는다.
- GainNode 음량 변경에는 짧은 램프를 적용해 잡음을 줄인다. 재생 실패 시 재생 중 연출을 취소하고 재시도 안내를 표시한다.
- 정지/종료 시 source.stop, 이벤트·프레임 취소, 노드 연결 해제, 필요 시 Context.close를 수행한다. 로드 중 정지도 이후 재생이 일어나지 않아야 한다.

## 6. 구현 순서와 완료 기준

1. 음원 디코딩과 청감 검수: 네 파일의 손상 여부·음량 차이 확인, 폭발음 최종 가공, 음원 카탈로그에 길이·타격 시점 확정.
2. 창과 설정: 집중벨 노출·단일 창·음량 저장·구버전 마이그레이션 구현. 이 단계부터 실제로 열리는 화면과 연결한다.
3. 버튼 재생: 네 버튼·정지·음량·음소거·오류/연타 처리를 완성한다.
4. 시각 연출: 효과별 SVG, 오디오 동기화, 전체화면, 반응형, 키보드/동작 줄이기를 완성한다.
5. 검증: 첫 실행 무음, 클릭당 한 번, 동일/다른 버튼 연타, 로드 중 정지·닫기, 0/40/100% 및 음소거, 설정 복원, 손상 파일, 오프라인, 전체화면, 모니터 배율, 도구 재사용을 확인한다.

자동 검증은 재생 제어기의 경합·수명 관리와 설정 마이그레이션처럼 오류 위험이 있는 동작에 집중한다. `npm run check`, `npm test`, `npm run build`와 관련 Rust 테스트를 수행한다. Windows WebView에서 실제 출력·창 종료 시 정지·오프라인 재생을 별도로 확인한다. 이번 단계는 계획/음원 준비이므로 앱 빌드나 집중벨 기능 검증을 완료한 것으로 보고하지 않는다.

## 7. 이번에 준비한 결과

- 계획서: 이 문서.
- 우선 적용 후보: `public/audio/toolkit/focus-bell/`의 음원 4개, 출처 표시, 가공 manifest.
- 미리듣기: `artwork/toolkit/focus-bell/preview.html`. 클릭 재생·음량·정지 가능, 앱에 연결된 화면은 아니다.
- 재현: `node --use-system-ca scripts/fetch-focus-bell-audio.mjs`로 원본 수집, `python scripts/prepare-focus-bell-audio.py`는 최초 후보 기록용이다. 2차 종소리·사이렌은 `node --use-system-ca --tls-cipher-list=DEFAULT@SECLEVEL=1 scripts/refresh-focus-bell-audio.cjs`로 재현한다. 이 명령은 Microsoft Edge와 Playwright가 필요하며 PLAYWRIGHT_PATH로 경로를 지정할 수 있다. TLS 인증서 검증은 유지한다.

### 파일 검증 기록

네 파일 모두 Headless Microsoft Edge의 AudioContext로 정상 디코딩했다. 미리듣기 초기 대기 → 종소리 클릭 재생 → 정지 상태 전환을 확인했다. 측정값은 `artwork/toolkit/focus-bell/decode-check.json`에 보관한다. 폭발음 원본의 디코딩 피크가 약 0 dBFS로 높아 미리듣기에서는 별도 0.35배 게인을 적용했다. 가공 스크립트를 재실행하면 생성 manifest의 후속 검증 메모는 갱신해야 한다. 이 검사는 실제 청취 및 Tauri WebView 실기기 검수를 대신하지 않는다.

### 사용자 피드백 반영: 종소리·사이렌 2차 교체

기존 종소리가 마음에 들지 않고 사이렌이 잘 들리지 않는다는 피드백을 반영해 두 원본을 새로 찾았다. 기존 사이렌은 가공 후 피크가 약 -14.55dBFS로 낮았고, 피크 기준 계산을 페이드 전에 했던 점도 영향을 주었다. 2차는 가공 후 -3dBFS를 맞춘다. 종소리의 잔향이 더 잘 남도록 피크 압축을 적용했다. 새 파일의 RMS는 종 -12.22dBFS, 사이렌 -10.15dBFS다. 이는 샘플 진폭 측정값이며 교실에서의 체감 음량이나 학생 반응을 검증한 값은 아니다.

기존 원본은 이력으로 보관하고, 배포 후보 bell.wav/siren.wav 및 미리듣기는 새 파일을 사용한다. 출처·정확한 추출 구간·가공·SHA-256은 sources-v2.json과 배포 manifest를 기준으로 한다. 이전 decode-check.json은 1차 결과다. 실제 청취 피드백은 새 미리듣기로 확인한다.

## 최종 구현 기록 — 2초 및 앱 연결

사용자 요청으로 종소리·사이렌을 각각 2초로 조정하고 집중벨 도구를 구현했다. 종소리 마지막 350ms, 사이렌 마지막 250ms에 코사인 제곱 감쇠를 적용해 끝 샘플은 0이 된다. 압축 뒤에 감쇠를 적용하므로 끝에서 다시 음량이 커지지 않는다.

Svelte 집중벨 창, 효과별 직접 제작 SVG 애니메이션, Web Audio 재생 제어, 0~100% 음량·음소거 로컬 저장, 정지, 전체화면, 항상 위, 창 종료 시 오디오 해제를 구현했다. 툴킷 설정을 최신 토너먼트 변경 위에서 schemaVersion 6으로 확장했다. 이전 숨김 설정을 보존하고 신규 집중벨을 한 번 추가한다. 실행 상태는 저장하지 않는다.

앞선 절의 ‘구현 전’ 또는 ‘후보’ 표기는 작업 당시 계획과 이력이다. 최종 상태와 남은 검증은 QA-focus-bell.md를 기준으로 한다.
