# 학급 툴킷 · 타이머 1차 PRD

작성: 2026-09-19 · 상태: 1차 구현 완료 · 검수 범위 별도 기록 · 현재 제품: Tidy Task 5.1.2

연결 문서: [항목별 상세 구현 계획](./PLAN-classroom-toolkit-timers.md) · [실제 검수 결과](./QA-classroom-toolkit-timers.md)

## 1. 제품 목표와 문서의 역할

교사가 다른 프로그램으로 수업하는 중에도 작은 툴킷을 잡아 옮기고, 필요한 타이머를 빠르게 꺼내 사용할 수 있게 한다. 디지털·아날로그·모래시계·스톱워치는 단순히 모습만 다른 시안이 아니라, 시간 계산·조작·다중 창·설정 저장까지 완결된 기능으로 만든다.

2026-09-19 후속 승인으로 이 PRD와 상세 실행계획에 따른 실제 구현을 진행한다. 실제 제품 구현, 에셋 생성·적용, 테스트는 실행계획에 구분하여 기록한다. 문서 작성만으로 구현이나 검증이 끝났다고 표시하지 않는다. 추가 인터뷰나 포괄적인 디자인 재승인을 작업의 선행조건으로 두지 않는다.

사용자의 최신 답변을 이전 제안보다 우선한다. 아래의 ‘구현 기본안’은 사용자가 맡긴 세부 판단을 구체화한 것으로, 실제 검증에서 조정할 수 있다. 장래에 리팩토링이 전혀 필요 없다는 보장 대신 시간 계산·창 제어·저장·표현을 분리하여 변경의 영향을 제한한다.

### 성공하는 사용 장면

1. 최초 실행 시 툴킷이 나타난다. 교사가 PPT 위에서 툴킷을 옮긴다.
2. 타이머 메뉴에서 아날로그를 선택하여 독립 창을 연다. 5분을 고르고 시작한다.
3. 같은 메뉴를 다시 선택하여 두 번째 타이머를 연다. 두 창은 서로 영향을 주지 않는다.
4. 창을 작게 줄여도 시간과 주요 버튼을 읽고 조작할 수 있다.
5. 스톱워치를 실행하고 기록을 남기면 옆 타임라인에 누적·구간 시간이 쌓인다.
6. 앱을 종료하면 측정·기록·활동 제목은 사라지고, 툴킷과 종류별 사용자 설정만 남는다.

## 2. 범위

### 이번 구현에 포함

- 독립 플로팅 툴킷, 본앱 설정 및 모던 메뉴의 ON/OFF 연동.
- 툴킷 가로/세로, 클릭 접기/펼치기, 기능 노출 관리, 자유 이동.
- 네 종류의 독립 타이머 창과 공통 시간 엔진, 다중 실행, 반응형 UI.
- 종류별 설정 영속화와 창별 측정 상태의 비영속화.
- 툴킷 전용 투명 배경 아이콘 생성·검수·적용, 기존 테마와 어울리는 시각 표현.
- 바늘·모래·숫자·종료 연출, 접근성 및 동작 감소 설정 대응.
- 시계음·종료 경고음·종료음의 파일 검색, 배포 가능한 라이선스 확인, 길이·음량 편집, 앱 번들 적용 및 실제 재생 검증.

### 이후 고도화

- 알림장, 개인/모둠 점수판, 학급 온도계, 판서, 간단 뽑기, 롤린 썬더.
- 학급 명단 등록과 모둠 지정. 향후 툴킷 끝의 ‘학급 명단 등록’에서 입력하고 각 기능이 공유한다.
- 스톱워치 기록별 짧은 메모·타이틀.

미구현 기능을 실행 가능한 것처럼 노출하지 않는다. 이번 기능 관리 목록에는 타이머 그룹만 존재하며, 이후 등록된 기능을 같은 관리 UI에 추가할 수 있게 한다. BGM은 이후 목록에도 포함하지 않는다.

## 4. 툴킷 요구사항

### TK-01 — 표시와 설정 진입

- 처음 설치해 툴킷 설정이 없으면 ON으로 취급한다. 저장된 OFF를 기본값으로 덮어쓰지 않는다.
- 본앱 설정창에 ‘학급 툴킷’ 토글을 둔다. 모던 UI 메뉴에도 같은 값을 조작하는 토글을 둔다.
- 두 진입점과 툴킷 자체 설정은 하나의 전역 설정을 읽고, 변경 직후 서로 일치한다.
- OFF는 툴킷·선택 메뉴·툴킷 설정창을 닫는다. 이미 열린 타이머는 계속 동작한다.
- 같은 ON 요청이 겹쳐도 툴킷은 하나만 생성한다. 타이머의 다중 생성과 구분한다.

### TK-02 — 독립 창과 앱 수명

- 툴킷은 독립 Tauri 창이다. 본창 최소화 또는 닫기와 무관하게 남아 다른 프로그램 위에서 작동한다.
- 툴킷 또는 타이머가 남아 있으면 본창을 닫아도 프로세스가 종료되지 않는다.
- 앱 트레이의 명시적 종료는 모든 창과 측정을 끝낸다. 측정 데이터를 저장하는 종료 루틴을 추가하지 않는다.
- 설정창·일시적인 선택 메뉴만 남아 앱이 계속 살아 있는 상태는 방지한다.
- 타이머·툴킷은 메모 저장 창 및 메모 매니저 후보에 포함하지 않는다.

### TK-03 — 어디든 잡아 이동

- 툴킷 본체의 배경·아이콘·기능 이름·버튼 위에서 누른 채 이동하면 창을 끌 수 있다.
- 클릭은 클릭으로, 드래그는 이동으로 처리한다. 드래그 종료 시 기능 실행이나 펼침/접힘이 발생하지 않는다.
- 클릭/드래그를 가르는 이동 기준, 입력 취소, 창 포커스 상실, 더블클릭을 명시적으로 처리한다.
- 툴킷에 드래그로 인한 최대화·전체화면 전환을 부여하지 않는다.
- 설정 입력란이나 열린 메뉴의 항목 선택은 별도 조작 영역이다. 타이머 시계판 드래그는 바늘 조작이며 툴킷 이동과 섞지 않는다.
- 화면 배율·모니터 배치가 바뀌어도 툴킷을 다시 잡을 수 있어야 한다.

### TK-04 — 접기와 방향

- ‘툴킷’ 버튼은 아이콘과 글자를 함께 표시한다. hover로 펼쳐지지 않는다.
- 클릭하면 접힘/펼침이 바뀐다. 접힌 상태에서도 같은 버튼을 잡아 이동한다.
- 펼치고 접을 때 ‘툴킷’ 버튼의 화면상 기준점을 유지한다. 화면 밖으로 나가는 경우에만 최소한으로 보정한다.
- 가로/세로는 자체 설정창에서 선택하며, 화면 가장자리에 닿았다는 이유로 자동 변경하지 않는다.
- 기능 실행 후 툴킷 상태는 유지한다. 사용자가 직접 접는다.
- 위치·방향·접힘 상태는 로컬에 저장한다.

### TK-05 — 메뉴와 노출 관리

- 타이머 버튼 클릭 → ‘전광판 타이머 / 아날로그 타이머 / 모래시계 / 스톱워치’ 목록 → 선택한 종류의 새 창.
- 목록은 짧은 이름과 일관된 아이콘으로 구성한다. 툴바에는 설명문을 넣지 않는다.
- 화면 위·아래·좌·우 끝에서도 목록이 잘리지 않는다. 메뉴 때문에 보이지 않는 큰 영역이 다른 앱의 클릭을 가로채지 않는다.
- 자체 설정에서 기능마다 ‘추가/숨기기’ 또는 명확한 토글로 노출을 관리한다. 노출 0개도 허용하며 툴킷 버튼과 설정 진입은 남는다.
- 기능은 안정적인 ID로 등록한다. 학급 명단과 미래 기능은 별도 모듈로 추가할 수 있어야 한다.
- 펼친 툴킷 끝에 설정 진입을 둔다. 접힌 상태는 펼친 뒤 접근한다.

## 5. 타이머 공통 요구사항

### TM-01 — 창과 독립성

- 종류 선택 한 번당 고유 ID의 창 하나를 생성한다. 같은 종류를 다시 선택해도 이전 창에 합치지 않는다.
- 창별 활동 제목, 항상 위, 창 크기, 현재 시간, 기록, 실행 상태는 독립이다.
- 새 창은 동일 종류의 최신 사용자 설정을 읽는다. 이미 열린 창에 다른 창의 설정을 강제 반영하지 않는다.
- 창 안의 항상 위 버튼은 상태가 눈에 보이며, 실제 OS 상태와 일치한다. 항상 위 값은 저장하지 않는다.
- 제목 기본값은 종류 이름이다. 사용자는 활동 제목을 입력할 수 있으며 제목은 해당 창 수명 동안만 유지한다.
- 기본 960×680 논리 px를 목표로 하되 작업영역을 초과하지 않는다. 최소 360×420에서 주요 기능을 조작할 수 있게 검증한다.
- 기본 창 위치는 툴킷이 있는 모니터에서 찾고 연속 생성 시 조금씩 엇갈리게 배치한다. 영구 창 복원은 하지 않는다.
- 실행 중 닫기는 일시적 확인창을 제공한다. 취소하면 측정은 그대로 진행한다. 스톱워치 기록이 남아 있는 경우에도 삭제됨을 확인한다.

### TM-02 — 시간 설정과 상태

- 분·초 직접 입력과 빠른 시간 버튼을 제공한다. 유효 실행 시간은 1초~60분이며 0초는 시작할 수 없다.
- 잘못된 입력은 값 근처에서 바로 알린다. 60:00을 넘는 직접 입력을 몰래 변환하지 않는다.
- 기본 상태는 `준비 → 실행 ↔ 일시정지 → 종료`이다.
- 시작하면 큰 표시가 중심이 되도록 설정 영역을 작게 정리한다. 사용자는 다시 설정 패널을 펼칠 수 있다.
- 실행·일시정지 중 시간 증감은 가능하다. 0 미만/60분 초과는 경계값으로 제한하고 버튼 상태로 알린다.
- 실행 중 감산 결과가 0이면 정상 종료를 한 번 처리한다. 일시정지 중 0으로 만들면 0초의 정지 상태가 되며 종료음을 발생시키지 않는다.
- ‘다시 설정’은 이번 실행을 시작할 때 정한 시간으로 돌아가 정지한다. 실행 중 증감은 이 기준을 바꾸지 않는다.
- 종료 후 ‘다시 시작’은 그 기준 시간으로 새 실행을 시작한다. 실행 전 직접 입력/빠른 선택/바늘 조작은 새 기준을 설정한다.
- 일시정지 중 바늘·증감 조작은 남은 시간을 바꾼다. 최초 설정을 바꾸려면 ‘다시 설정’ 후 수정한다.
- 종료 상태에서 시간을 추가하면 새 준비 상태가 된다. 무의식적으로 재실행하지 않는다.
- 최소화하거나 다른 창을 사용하는 동안에도 계산은 계속된다. 앱 종료 후에는 어떤 측정도 이어지지 않는다.

### TM-03 — 전광판 타이머

- 멀리서 읽히는 큰 고정폭 숫자와 분·초 구분. 60분은 `60:00`으로 표시한다.
- 네온·발광·거대한 검은 패널 대신 기존 테마의 배경과 명확한 숫자 대비를 사용한다.
- 숫자 폭이 바뀌어 전체 배치가 흔들리지 않는다. 보조 진행선은 시간을 정확히 반영한다.
- 종료가 가까워지는 시각 상태와 종료 상태는 색 외에 숫자·문구로도 구분한다.

### TM-04 — 아날로그 타이머

- 실제 시계 같은 원형 눈금·바늘과 남은 시간 부채꼴을 함께 표시한다. 현재 시각을 나타내는 시/분침 시계와는 구분한다.
- 60분 기준: 위 0, 오른쪽 15, 아래 30, 왼쪽 45. 30분 기준은 5분 단위 주요 숫자와 1분 눈금으로 구성한다.
- 남은 시간 비율은 `remaining / dialRange`이며, 위쪽 0에서 시계 방향으로 부채꼴을 채운다. 종료를 향해 바늘은 0으로 돌아오고 면적은 줄어든다.
- 30분 기준에서 남은 시간이 30분을 넘으면 60분 기준으로 자동 전환한다. 자동 축소는 하지 않는다.
- 30분을 초과한 상태에서 30분 기준 선택은 비활성화하고 이유를 접근 가능한 설명으로 제공한다. 시간을 잘라내지 않는다.
- 시작 전·일시정지에서 바늘을 잡아 시간 설정. 바늘은 1분 단위로 맞추고, 초 단위 정밀 입력은 숫자 입력으로 제공한다.
- 한 바퀴 경계에서 0↔최대가 튀지 않는다. 0과 가득 찬 원은 바늘 위치가 같아도 상태가 구분된다.
- 화면 크기가 달라도 손잡이를 쉽게 잡는다. 키보드·숫자 입력으로 동일 기능에 접근한다.

### TM-05 — 모래시계

- 실제 남은 시간에 비례해 위쪽 모래가 감소하고 아래쪽에 쌓인다. 낙하 줄기·소수 입자는 진행 상태를 보조한다.
- 단순 수면 높이가 아닌 모래 면적의 비율이 시간과 맞도록 모양을 계산한다.
- 일시정지 시 모래의 이동도 멈추며, 0초에 위쪽 모래와 낙하 줄기가 남아 있지 않는다.
- 시작 전은 모래가 위에 있고 종료 후는 아래에 있다. 실행 중 시간 추가는 현재 분포에서 자연스럽게 변경되며 0~100% 범위를 벗어나지 않는다.
- 남은 시간 숫자는 기본 표시. ‘남은 시간 표시’ 토글은 종류별로 저장한다.
- 프레임·모래는 평면적인 형태, 일관된 선 두께, 차분한 포인트 색으로 표현한다.

### TM-06 — 스톱워치와 타임라인

- 0에서 시작하고 시작·일시정지·재개·기록·초기화 제공. 카운트다운의 60분 상한을 적용하지 않는다.
- 1/100초까지 표시하되 측정 정밀도와 화면 갱신 빈도를 구분한다. 한 시간 이상이면 시 단위를 추가한다.
- 실행 중 기록 버튼을 누르면 누적 시간과 직전 기록 이후 구간 시간을 동일한 시점에서 계산한다.
- 기록은 최신 항목이 위에 오는 세로 타임라인. 기록 번호, 누적 시간, 구간 시간을 구분한다.
- 기록 버튼은 처음부터 보인다. 기록이 없을 때 타임라인은 작게 정리하되 기능을 숨기지 않는다.
- 넓은 창에서는 오른쪽, 좁은 창에서는 아래. 사용자가 과거 기록을 보고 있으면 새 기록 때문에 스크롤을 빼앗지 않는다.
- 초기화는 경과 시간과 기록을 함께 지우고 설정은 유지한다. 기록이 있으면 확인한다.
- 기록 구조에 안정적인 ID를 부여해 향후 메모·짧은 제목 추가가 가능하게 한다. 현재는 입력 UI도 로컬 기록 저장도 없다.

### TM-07 — 실제 효과음과 설정

- BGM 없음. 카운트다운에 시계음·종료 경고음·종료음 토글을 각각 제공하며 최초 ON.
- 경고 시작/지속 선택은 3절의 목록을 정확히 사용하고 종류별 저장한다.
- ‘계속 울림’은 경고 시작부터 0초까지. 유한 지속도 0초를 넘지 않는다.
- 일시정지·초기화·닫기·OFF 시 해당 소리를 중지한다. 종료 시 경고음을 먼저 중지하고 종료음을 한 번만 발생시킨다.
- 경고 구간에서 시간을 추가해 경고 시작점보다 커지면 경고를 멈추고, 다시 구간에 진입할 때 새 경고를 허용한다.
- 스톱워치는 시계음만 적용한다. 끝나는 시점이 없으므로 종료 경고·종료음 제어는 표시하지 않는다.
- 실제 음원 3종을 앱에 포함해 오프라인에서도 재생한다. CC0 등 재배포 가능한 음원의 원본 URL·저작자·라이선스·수정 내역·파일 해시를 보관한다. 부드러운 시계음, 짧은 경고, 구분되는 종료음을 선정하고 각 항목에서 미리 듣기를 제공한다.
- 파일 디코딩·오디오 활성화 실패를 숨기지 않는다. 실행 시점의 사용자 입력에서 오디오를 활성화하고 종료/정지/초기화/닫기 시 예약된 재생도 취소한다. BGM이나 종료음 반복 옵션은 추가하지 않는다.

## 6. 저장·디자인·품질 요구사항

### ST-01 — 설정만 저장

- 전용 파일 `tidy-task-toolkit.json`에 버전과 허용된 설정만 저장한다. 기존 메모·급식 데이터 파일과 분리한다.
- 툴킷의 ON/OFF·방향·접힘·노출 기능·위치와 종류별 소리·표시 설정만 허용한다.
- 활동 제목, 현재 시간, 시작 시각, 실행 여부, 최초 설정 시간, lap 기록, 타이머 창 좌표·핀은 저장하지 않는다.
- 같은 종류에서는 마지막으로 성공적으로 변경한 **필드**가 최신값이다. 다른 창의 오래된 전체 설정으로 덮어쓰지 않는다.
- 다른 종류에는 영향을 주지 않는다. 열려 있는 창의 측정이나 설정 스냅샷은 외부 변경으로 바뀌지 않는다.
- 읽기 실패 시 기존 파일을 기본값으로 덮어쓰지 않는다. 쓰기 실패 시 저장 완료로 표시하지 않는다.
- 손상값·알 수 없는 종류·잘못된 enum을 정규화하고, 미래 버전 파일은 조용히 다운그레이드하지 않는다.

### UX-01 — Tidy Task와 일관된 외형·밀도

- 2026-09-19 디자인 수정 요청을 우선한다. 툴킷/타이머는 밝은 크림색·흰 작업 면·세이지/노란 강조색을 사용하며 본앱의 다크 모드를 자동 상속하지 않는다. 본앱 자체의 테마는 변경하지 않는다.
- 바탕·섹션·경계·강조색의 역할을 분명히 하고 숫자·제목·조작의 위계를 유지한다.
- 공간을 억지로 채우거나 과도한 카드·태그·설명문으로 꾸미지 않는다. 작은 글씨로 압축해서도 안 된다.
- 기준: 일반 라벨 13~14px, 주요 버튼 43~46px 높이, 툴킷은 32px 이상 조작 영역. 실제 앱 글꼴/배율에 따라 재검증한다.
- 숫자와 시계는 남는 영역에 맞춰 커지되 조작 영역을 밀어내지 않는다. 낮은 높이에서도 스크롤 또는 설정 접기로 필수 조작에 도달한다.
- 일반 라벨은 기존 UI 글꼴을 따르되 시간·눈금·기록은 가독성 높은 Segoe UI 계열과 tabular numerals를 사용한다. 숫자 안의 장식 문양은 사용하지 않는다.
- 타이머별 별도 색 선택 UI는 1차 범위에 추가하지 않는다.

### UX-02 — 생성 에셋과 아이콘

- Tidy Task 로고를 재사용하지 않는 **학급 도구함 모티프의 툴킷 전용 아이콘**을 생성한다.
- 평면·둥근 모서리·정돈된 진한 외곽선, 작은 도구함과 최소한의 문구 요소. 어설픈 3D, 광택, 네온, 흰 스티커 테두리, 과도한 장식 금지.
- 실제 알파 채널을 갖는 투명 PNG 원본을 프로젝트에 보관한다. 체크무늬를 배경에 그린 가짜 투명 이미지는 불합격.
- 오브젝트 전체가 들어오며 사방 여백을 확보한다. 흰 덩어리·잘린 손잡이·축소 시 뭉개지는 세부를 검수한다.
- 툴킷 버튼과 설정 헤더에 적용한다. 앱 전체 아이콘은 교체하지 않는다.
- 일반 조작 아이콘은 이미 설치된 Lucide를 일관되게 사용한다. 모든 버튼마다 별도 래스터 아이콘을 생성하지 않는다.
- 시계판·모래·움직이는 숫자는 SVG/CSS로 구현한다. 생성된 정지 이미지에 시간을 눈속임으로 겹치지 않는다.
- 샘플 사진은 기능 참고 전용이며 색·레이아웃·그래픽을 복제하지 않는다.

### UX-03 — 움직임과 접근성

- 툴킷 펼침/접힘, 버튼 반응, 기록 추가, 종료 연출에 통일된 짧은 움직임을 적용한다.
- 시간의 진행은 실제 측정값에 선형으로 대응한다. 바늘·모래에 탄성을 줘 시간을 부정확하게 보이게 하지 않는다.
- 종료 시 도구가 작게 반응하고 ‘시간이 끝났어요’가 나타난다. 한 번의 생동감 있는 연출 후 안정된 종료 화면을 유지한다.
- 지속적인 튀기·화면 전체 흔들기·번쩍임·축하 입자 남발은 제외한다.
- `prefers-reduced-motion`에서는 장식 움직임을 제거하되 시간·상태 변화는 계속 표현한다.
- 버튼 이름, 키보드 포커스, Escape 닫기, 메뉴 탐색, 대화상자 포커스 복귀를 제공한다. 매초 스크린리더로 낭독하지 않는다.
- 숫자 대비와 조작 대비는 실제 테마 조합에서 검증한다. 색만으로 진행/정지/종료를 구분하지 않는다.

### QA-01 — 정확성·성능·운영 품질

- 시간은 경과 시각으로 계산한다. `setInterval` 호출 횟수만큼 1초씩 빼는 누적 오차 방식은 사용하지 않는다.
- UI 프레임과 시간 엔진을 분리한다. 프레임이 끊겨도 다음 샘플에서 실제 시간으로 돌아온다.
- 앱이 실행 중인 OS 절전 구간도 경과 시간에 포함하는 것을 구현 기본안으로 둔다. 복귀 시 지난 경고음을 몰아서 재생하지 않는다. Windows WebView2에서 반드시 실측한다.
- 종료 이벤트는 실행 1회당 최대 1회, 기록 시점은 하나의 시각 샘플로 계산한다.
- 다중 창의 listener·RAF·interval·오디오 예약은 닫을 때 정리한다.
- 기존 메모·Tiny Note·급식·리마인더 저장과 창 수명 회귀를 검사한다.
- 브라우저 QA와 실제 Tauri의 항상 위·드래그·DPI·모니터 이동·최소화/절전 검증은 별도로 기록한다.

### EX-01 — 확장 경계

- 도구 레지스트리, 창 생성, 종류별 설정, 공통 타이머 엔진, 시각 표현, 소리 출력의 책임을 분리한다.
- 새 도구 추가가 기존 타이머의 조건문 확장이나 본앱 저장 스키마 변경을 요구하지 않게 한다.
- 현재 필요 없는 플러그인 로더·범용 이벤트 버스·학급 DB·클라우드 동기화는 만들지 않는다.

## 7. 완료 판정

1. 위 요구사항별 구현 위치와 검증 증거가 상세계획의 추적표에 연결되어 있다.
2. 클릭/드래그, 작은 창 메뉴, 메인 창 없는 실행, 설정 충돌 시험을 실제 Tauri에서 통과한다.
3. 네 타이머가 시작→정지→재개→증감/기록→초기화/종료→닫기 전 경로에서 정상 동작한다.
4. 실제 3종 음원이 로컬에서 재생되고 ON/OFF·경고 시점/지속·종료 단발성·여러 창의 독립 재생을 검증한다.
5. 생성 아이콘의 알파·사방 여백·작은 크기·밝은/어두운 배경 검수를 통과한다.
6. 앱 종료 후 측정·기록·활동 제목이 디스크에 남지 않고, 사용자 설정만 복원된다.
7. 자동 검사와 네이티브 수동 검증의 통과/실패/미실행을 구분한다. 기존 실패를 신규 성공으로 덮지 않는다.

## 8. 조사 근거와 적용 범위

2026-09-19 확인. 인기나 최신이라는 이유만으로 품질을 보증하지 않고, 실제 앱에서 필요한 기능을 검증해 채택한다.

- [Bits UI 공식 소개](https://www.bits-ui.com/docs/introduction): Svelte용 headless UI. Switch·Select·Dialog·Menu의 접근 가능한 상호작용을 맡기고 외형은 직접 작성한다.
- [Bits UI Dropdown Menu](https://www.bits-ui.com/docs/components/dropdown-menu): 일반 메뉴와 정적 콘텐츠 API 확인. 네이티브 창 경계 문제는 별도 창 설계로 처리한다.
- [Floating UI](https://floating-ui.com/docs/computeposition): 기준 요소와 부유 요소의 배치 원리 참고. 이것만으로 OS 창 바깥에 메뉴를 그릴 수 있다고 가정하지 않는다.
- [Tauri Window API](https://v2.tauri.app/reference/javascript/api/namespacewindow/): 창 생성 이후의 위치·크기·항상 위·드래그 제어를 구현할 기준.
- [Tauri Store](https://v2.tauri.app/plugin/store/): 로컬 설정 저장에 현재 설치된 플러그인 사용. 저장 요청 순서는 별도 계약으로 보완한다.
- [MDN performance.now](https://developer.mozilla.org/en-US/docs/Web/API/Performance/now): 단조 시계와 OS 절전 중 동작 차이 확인. 일반 브라우저 설명을 WebView2 실측 결과로 오인하지 않는다.
- [MDN Pointer Capture](https://developer.mozilla.org/en-US/docs/Web/API/Element/setPointerCapture): 드래그 중 입력 추적과 해제의 기준.
- [InkCanvasForClass](https://github.com/InkCanvasForClass/community): 교실용 독립 도구와 숨김 방식의 제품 참고. C#/WPF 구현을 Svelte에 직접 이식하지 않는다. GPLv3 저장소의 코드를 복사하지 않는다.
- [교실 타이머 사용 논의](https://www.reddit.com/r/teaching/comments/1konzyr/should_i_make_a_classroom_timer_that_can_be_used/): 수업 화면과 타이머를 함께 쓰는 사용 맥락만 참고. 기술 신뢰성의 근거로 사용하지 않는다.


## 디자인 개정 — 2026-09-19 후속 피드백

기존 어두운 화면, 낮은 대비, 작은 시계 눈금과 장식 숫자체를 폐기했다. 밝은 도구함과 큰 시간 표시 중심으로 프런트엔드를 다시 구성했다. 아날로그는 밝은 시계판/큼직한 숫자/분명한 남은 시간 면적, 모래시계는 곡선 유리/세이지색 프레임/황금색 모래로 변경한다. 곡선 내부 면적에 맞게 모래 수위 계산도 변경한다. 기본 960×680에서 모든 소리 설정을 스크롤 없이 볼 수 있도록 하고, native 최소 크기는 380×520으로 높여 시계와 주요 조작의 가독성을 확보한다.
