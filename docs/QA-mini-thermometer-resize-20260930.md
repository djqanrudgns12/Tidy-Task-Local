# 미니 온도계 크기별 글자 배치·위쪽 테두리 검수 · 2026-09-30

## 수정

사용자 첨부 화면의 넓어진 미니 창에서 조작 안내가 목표 패널에 겹치고, 숫자가 이름 영역을 침범하는 문제를 재현했다. 880×480 미리보기에서 숫자·최대·조작 안내는 약 164px를 차지했으나, 배정된 숫자 영역 높이는 약 111px였다. 부모의 `scrollHeight`만 확인하면 이런 형제 영역 간 겹침은 놓친다.

- 숫자 영역 자체를 크기 컨테이너로 두고 **목표·기록을 배치한 뒤 실제 남은 높이**와 숫자 길이에 맞춰 숫자를 키운다. 이름·목표 글자와 카드 여백도 너비와 높이를 함께 따른다.
- 버튼·온도계 관이 차지하는 최소 높이를 실제 합계와 맞췄다. 좁은 카드에서 관이 2px 옆으로 튀어나오는 것도 고쳤다.
- 낮은 카드에서는 조작 안내·다음 목표·도장 줄, 더 낮으면 오늘의 변화·최대 표시를 순서대로 줄인다. 아주 좁은 카드에서 긴 누적 기록이 여러 줄이 될 때 도장 줄이 카드 밖으로 밀리는 문제도 보완했다.
- 긴 온도계 이름은 말줄임, 긴 목표 이름은 여유에 따라 한두 줄 표시를 유지한다. 창 제목이 길어져도 핀·설정·닫기 버튼의 폭은 줄어들지 않는다.
- 위쪽 가운데에 `North` 크기 조절 손잡이를 추가했다. `td-board`의 크기 컨테이너 안에서는 `fixed`도 카드 기준이 되므로, 손잡이를 카드 밖에 두어 **실제 창의 맨 위 12px(투명 여백 포함)**을 받는다. 모서리 손잡이와 제목 줄 창 이동은 유지한다.

온도 변경·이름 저장·학급 자료·설정 저장 경로는 바꾸지 않았다. 버전 변경·배포·커밋은 하지 않았다. 기존 작업 파일과 과거 검수 기록은 보존했다.

- `cargo test --lib thermometer`: 온도계 창 크기·온도계 수·미니 설정 독립 보존 관련 3개 통과.
- 프런트 빌드: `npm run build -- --outDir output/qa/mini-thermometer-resize/dist` 성공. 설치 프로그램을 만드는 배포 빌드가 아니다.
- `scripts/qa-mini-thermometer.cjs`: **4,484개 배치 검사 통과**, 오류 0. 14개 너비(280~4000) × 20개 높이(220~3000), 온도계 1개/2개, 메이플스토리 L/맑은 고딕, 첨부 화면·긴 단계·−1000·목표 완료 조합. 배치 전환 경계 전후 1px 크기도 포함한다.
- 카드의 각 줄, 숫자·단위·안내, 조작 버튼·관, 목표·기록의 실제 경계를 비교했다. 부모 밖 넘침과 형제 간 겹침을 각각 확인했다. 작은 설정 패널은 세로 스크롤을 허용하고 가로 넘침은 없음을 확인했다.
- 증감·이름 편집·재열기 후 값 유지·두 미니 화면의 저장 동기화, 어두운 화면과 200% 렌더 배율 통과.
- `scripts/qa-mini-thermometer.cjs --resize-only`: 실제 네이티브 화면 분기에 **브라우저 내부 IPC 대체**를 넣은 별도 검사. 위쪽 1·4·6·11px에서 손잡이가 잡히고 `start_resize_dragging`에 `North`를 전달하며, 제목 줄 빈 곳은 기존 `start_dragging`을 전달함을 확인했다. 실제 앱 자료나 Windows 창을 조작하지 않는다.

로그·스크린샷·자동 검사 결과: `output/qa/mini-thermometer-resize/`. 전체 배치 결과는 `report.json`, 위쪽 손잡이 별도 결과는 `resize-report.json`이다.

## 네이티브 확인 범위

실행 중인 개발 앱의 미니 온도계(캡처 521×426)에서 수정된 글자 배치를 확인했다. 위쪽 테두리의 실제 Windows 드래그 검증은 사용자 물리 Escape 입력으로 Computer Use가 중단되어 **최종 통과로 기록하지 않는다**. 카드 밖으로 옮긴 최종 손잡이에 대한 OS 크기 변경·다중 모니터 배율 검증은 미완료다. 브라우저에서 명령 전달이 확인되었다는 결과와 실제 Windows 창 크기가 바뀌었다는 결과는 구분한다. 사용자 온도 값·이름은 네이티브 검수로 변경하지 않았다.
