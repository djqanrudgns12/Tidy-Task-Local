# PRD — Tiny Note 헤더 반응형 개선

## 1. 배경 (Problem)

Tiny Note 헤더는 **좌측 고정 영역 + 우측 버튼 7개**가 한 줄에 모두 들어가야 하는 구조입니다.

| 영역 | 실측 폭 |
|---|---|
| 아카이브 버튼 + 제목 입력창(`w-[80px]` 고정) | 약 110px |
| 우측 버튼 7개 (핀·테마·롤업·비우기·최소화·전체화면·닫기) | 약 154px |
| **합계** | **약 264px** |

그런데 Tiny Note의 기본 너비는 **250px**, 최소 너비는 **160px**였습니다.
즉 **기본 크기에서 이미 14px 부족**했고, 버튼이 추가될 때마다 22px씩 더 밀려
"웬만한 크기에서는 버튼이 잘리는" 것이 사실상 정상 동작이 되어 있었습니다.

근본 원인은 **버튼 개수는 계속 늘어나는데 헤더 폭은 고정**이라는 점입니다.
따라서 폭을 줄이는 미봉책이 아니라, 개수가 늘어도 깨지지 않는 구조가 필요합니다.

## 2. 목표 (Goals)

1. 어떤 창 크기에서도 버튼이 **잘리지 않는다**.
2. 버튼이 앞으로 더 추가되어도 **구조가 깨지지 않는다**.
3. 스티커 메모다운 **아담한 크기(200px)** 를 유지한다.
4. 버튼의 **발견성**을 높이되 평소에는 조용하다.

### Non-goals
- 아카이브 버튼의 위치 변경 (좌측 유지 — 사용자 결정)
- 헤더 높이(35px) 변경
- 롤업/전체화면 등 기존 동작 변경

## 3. 결정 사항 (Decisions)

| # | 결정 | 근거 |
|---|---|---|
| D1 | 최소 너비 **160px → 200px** | 160px는 어차피 버튼이 잘려 쓸 수 없던 크기. 200px는 스티커 메모 감성의 하한 |
| D2 | **우선순위 기반 자동 접기**(Priority+ 패턴) | 폭이 모자라면 우선순위가 낮은 도구부터 `⋯` 메뉴로 이동 |
| D3 | 버튼 **항상 은은하게 노출** (호버 시 또렷) | 호버 전용은 발견성이 너무 낮음 |
| D4 | 아카이브 버튼 좌측 유지 | 사용자 결정 |
| D5 | 제목 입력창 **고정 → 가변** | 남는 공간을 버튼에 양보 |

### D1 보충 — 200px에서의 물리적 한계

사용자는 "아카이브·핀·테마·롤업·비우기를 항상 노출"을 희망했으나,
200px에서는 물리적으로 불가능합니다.

```
200px − 좌측 최소(72px) − 창 제어 3개(66px) = 62px
62px − ⋯ 버튼(22px) = 40px  →  도구 버튼 1개만 수용
```

따라서 **200px에서는 접기가 실제로 동작하는 것이 정상**이며,
자동 접기를 채택한 이유가 바로 이것입니다. 창을 넓히면 자동으로 다시 펼쳐집니다.

| 창 너비 | 헤더에 펼쳐지는 도구 수 |
|---|---|
| 200px | 1개 (+ `⋯`) |
| 230px | 2개 (+ `⋯`) |
| 250px 이상 | 4개 전부 (`⋯` 숨김) |

## 4. 우선순위 (Priority)

**남는 순서** (뒤로 갈수록 먼저 접힘):

```
닫기 > 최소화 > 전체화면 > 롤업 > 핀 > 테마 > 비우기
└──────── 절대 안 접힘 ────────┘ └──── 접기 대상 ────┘
```

- **창 제어 3종(최소화·전체화면·닫기)은 절대 접히지 않습니다.** OS 창 관습을 따릅니다.
- **아카이브는 좌측 고정**이라 접기 대상이 아닙니다.
- **롤업**은 Tiny Note 고유 기능이므로 접기 대상 중 가장 오래 남습니다.

**표시 순서는 우선순위와 분리**합니다. 접혀도 남은 버튼의 좌우 순서는
기존과 동일(핀 → 테마 → 롤업 → 비우기)하게 유지해 위치 기억을 해치지 않습니다.

## 5. 상세 사양 (Spec)

### 5.1 자동 접기

- 헤더 폭은 `ResizeObserver`로 관찰합니다. (창 크기·DPI 변화 모두 대응)
- 버튼 폭은 CSS로 **22×22px 고정**하여 계산이 항상 정확하도록 합니다.
- 몇 개를 펼칠지는 **순수 함수**로 계산해 단위 테스트로 검증합니다.
- 초기 렌더 시에는 저장된 창 너비로 폭을 추정해 **깜빡임(FOUC)을 방지**합니다.

### 5.2 롤업 상태

롤업하면 35px 띠만 남고 본문이 보이지 않으므로,
**롤업 버튼 + 창 제어 3종만** 표시합니다. 테마·비우기·핀은 숨깁니다.

### 5.3 은은한 노출 (D3)

| 상태 | 불투명도 |
|---|---|
| 평소 (창 활성) | 0.45 |
| 헤더 호버 | 1.0 |
| 창 비활성 | 0.25 |
| 핀이 켜진 경우 | 항상 1.0 (상태 표시) |

- 전환 150ms. 개별 버튼 호버 시 `translateY(-1px)` + 원형 하이라이트.
- 창 비활성 시 흐려지므로, 여러 개 띄웠을 때 **지금 쓰는 창이 자연히 도드라집니다.**

### 5.4 제목 입력창 유연화

- `w-[80px]` 고정 → `flex: 1 1 auto` + `min-width: 36px`
- 창이 넓으면 제목을 길게 쓰고, 좁으면 알아서 양보합니다.
- 넘치는 제목은 말줄임(`text-overflow: ellipsis`) 처리합니다.

### 5.5 `⋯` 메뉴 감성

- 스티커가 떨어지듯 `scale(0.94) → 1` + 살짝 오버슈트하는 등장 애니메이션 (180ms)
- 배경은 **현재 노트의 테마 색**을 따라가 통일감을 줍니다.
- 아이콘 + 한글 라벨을 함께 보여 기능을 명확히 합니다.
- 바깥 클릭 / `Esc` / 창 비활성화 시 닫힙니다.
- 헤더 드래그·더블클릭 영역과 충돌하지 않도록 이벤트를 격리합니다.

## 6. 검증 (Acceptance)

- [ ] 200px에서 버튼이 잘리지 않는다.
- [ ] 창을 넓히면 접혔던 버튼이 자동으로 다시 펼쳐진다.
- [ ] 200px 미만으로는 창을 줄일 수 없다.
- [ ] 기존에 160~199px로 저장된 창은 다음 실행 시 정상 크기로 복구된다.
- [ ] 롤업 상태에서 롤업 해제 버튼에 접근할 수 있다.
- [ ] `⋯` 메뉴의 모든 기능이 헤더 버튼과 동일하게 동작한다.
- [ ] 드래그 이동·더블클릭 전체화면이 그대로 동작한다.
- [ ] 폭 계산 순수 함수의 단위 테스트가 통과한다.
